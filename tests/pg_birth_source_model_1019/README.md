## Measured gap and source authority

Actual paired engines have identical 255 cells, geometry and timing. Default 308/510 PG terms bind; strict 318/510 bind. The strict branch adds exactly five real clock BUFx8 instances / ten PG terms. Its remaining 192 are 49 `buffer_ports` BUFx2 (98), 45 hold-repair BUFx2 (90), and two real open-output CTS load inverters (4). No clock-name or open-output exemption is valid. These manual CTS jobs did not exercise accepted CL.RUNNER admission or its final ODB/SPEF publication checks.

The retained actual CTS log identifies `OpenROAD 26Q3-1510-g6cb3f2b704`. `upstream/` contains read-only official sources downloaded at that exact revision, with SHA inventory in SOURCE_MANIFEST.json. This pins the advertised source revision; rebuilding the binary from those sources has not been established. No unpinned current-master behavior is used.

- [dbInst::create](https://github.com/The-OpenROAD-Project/OpenROAD/blob/6cb3f2b704/src/odb/src/db/dbInst.cpp#L1334) allocates all master ITerms, installs the supplied region, then invokes `inDbInstCreate` before returning (1417), followed by ITerm-create callbacks. It does **not** apply global-connect rules. A birth callback therefore sees PG MTerms and ITerms, including open-output cells, but not later caller-assigned location/region or signal connectivity.
- [dbGlobalConnect](https://github.com/The-OpenROAD-Project/OpenROAD/blob/6cb3f2b704/src/odb/src/db/dbGlobalConnect.cpp#L161) explicitly connects when called; registered rules are not a future-birth subscription. Native single-instance `connect` skips protected instances. Native rules use their real regex and exact dbRegion membership. Native `addGlobalConnect(...do_connect=true)` may bind immediately; it is a mutation, not just rule registration.
- [C++ callback base](https://github.com/The-OpenROAD-Project/OpenROAD/blob/6cb3f2b704/src/odb/include/odb/dbBlockCallBackObj.h#L42) has birth and master-swap callbacks. SWIG common `odb.i` includes this base, but the retained revision has no director/virtual override bridge in these interfaces or Tcl/Python SWIG CMake settings. Exposure of a base method is not evidence that a Tcl proc/Python subclass receives native callbacks. Current image has no demonstrated usable script birth callback.
- `dbInst::setDoNotTouch` (755) directly changes a flag, without an observer. A Tcl wrapper around `set_dont_touch` does not cover `$inst setDoNotTouch` or native C++ setters.
- [CTS run](https://github.com/The-OpenROAD-Project/OpenROAD/blob/6cb3f2b704/src/cts/src/TritonCTS.cpp#L89) writes actual cells, calls `setAllClocksPropagated`, and internally estimates placement parasitics (2685) **before** Tcl `clock_tree_synthesis` returns. Its `placeDummyCell` (2630) creates real open-output load cells. Native clock repair also runs before return.
- [Resizer](https://github.com/The-OpenROAD-Project/OpenROAD/blob/6cb3f2b704/src/rsz/src/Resizer.cc#L5912) creates cells through both dbNetwork and OpenDB insert-buffer operations. Internal native parasitic estimates/updates exist; wrapping only Tcl `repair_timing` or `repair_timing_helper` cannot intercept them.
- [EstimateParasitics](https://github.com/The-OpenROAD-Project/OpenROAD/blob/6cb3f2b704/src/est/src/EstimateParasitics.cpp#L443) has full and incremental C++ entry points. A Tcl estimate wrapper does not see those calls or establish their RC provenance.

## Minimum source changes, divided by achievable claim

Reuse `ot_pg_master_census`, actual `ot_pg_prepare` rule/domain mapping and exact region semantics. Assert every POWER/GROUND MTerm has the correct ITerm and one unambiguous native-domain net. Existing protected-unbound/wrong-domain/missing-term cases refuse; never clear protection. No `global_connect` in assertions.
2. In that same existing conditional helper, install strict wrappers around actual birth-capable command entry points (`buffer_ports`, `repair_clock_inverters`, `clock_tree_synthesis`, `repair_timing`, `repair_design`, timing-driven `global_placement` and any nested supported source helper). 3. `physical/common_flow/native_pg_bootstrap.tcl`: compose the installer/entry audit at actual process entry; preserve the separately reviewed final-only preflight semantics. No duplication or undo of `da986`.
4. `tools/ref_tile/ref_route.sh` and `tools/ref_tile/ref_tile.py`: generate strict composed wrappers for actual PRE_FLOORPLAN / PRE_GLOBAL_PLACE_SKIP_IO / PRE_GLOBAL_PLACE / PRE_CTS and every later requested mutation stage. 6. `tools/closure_loop/helper_overlay.py` / `closure_loop.py`: no new helper file is needed if additions remain in existing PG conditional files. Preserve typed boolean spec policy, shipped exact bytes/modes and frozen-plan policy validation. Require a supported native-capability receipt before issuing a birth-safe result. Guard every acceptance/publication path against an absent capability, not just route exit0.

This is a useful tightening: existing-image strict jobs with unsupported birth paths stop honestly. It does not fix the 192 missed terminals and cannot justify a rerun-to-PASS.

### B. Smallest genuine native birth capability (separate tool source/image grant)

A real solution requires a native C++ guard, not another Tcl spelling of `global_connect`. Proposed native capability `ot_pg_native_birth.v1` is off by default and activated only by typed strict source policy. Its concrete implementation surface is:

- New small guard owner under OpenROAD `src/ord` with a registered Tcl activation/capability API; build entries in `src/ord/CMakeLists.txt` and its Tcl/SWIG interface. Derive from `odb::dbBlockCallBackObj`; attach after actual DB import, reattach on replacement and reject use before attachment. Reuse/port the audited role/domain rules rather than evaluating arbitrary Tcl from a reentrant OpenDB callback.
- `inDbInstCreate`: once all MTerms/ITerms exist, derive exact native applicable rules and require one domain for every PG term. Preflight the whole instance, then bind all pending terms before callback return; read back all terms; append an ordered native receipt. Include real open-output load cells and physical-only masters. Callback ordering/reentrancy is an explicit proof obligation: inDbInstCreate precedes inDbITermCreate notifications, and connecting PG inside it may notify existing network consumers early. The minimum implementation must prove all registered consumers tolerate this order, or use a new end-of-create native guard point after ITerm notifications and before dbInst::create returns. No unsupported callback-order assumption. No name filters. If the instance's region is assigned only later and a domain cannot yet be determined, refuse; do not choose a default domain. Native post-master-swap callback rechecks new MTerms and refuses any changed protected/incorrect domain. Cached master role data requires invalidation on master mutation.
- `src/odb/src/db/dbInst.cpp`: add a callback before transitioning do-not-touch false→true, with corresponding virtual callback declaration in `dbBlockCallBackObj.h`. It performs a read-only native PG assertion; it never repairs a protected cell. This covers C++ and direct object setters.
- `src/est/src/EstimateParasitics.cpp`: capability guard at both full and incremental entry points, before estimation, plus success notification only after the actual requested native model finishes. Birth/rule/connection changes remain dirty until that witnessed estimate. A native CTS placement estimate may clear dirty only with witnessed native canonical CTS provenance; it must not manufacture a Tcl-frame claim. Routed/global-route/SPEF states remain fail-closed to binding changes. Full path audit must also identify any analysis consumers bypassing these EST entry points; those remain unsupported until an explicit native pre-analysis guard is installed.
- Observe native PG ITerm connect/disconnect, master changes and rule/domain/region changes. Existing callback coverage is insufficient for every rule/region mutation: exact native rule/region mutators need guard notifications or immutable-during-transaction refusal plus a full mapping fingerprint/census at each native pre-analysis boundary. No old mapping survives a mutation. Protect against recursive callbacks while applying a preflighted binding transaction, without suppressing unrelated mutations or exception propagation.

The optional capability uses generic OpenDB native rule matching, not coupon80fF, specific IO names, clock-name waivers or generated-net guesses. Initial source rule installation must precede admitted floorplan births; absent rules are explicit HOLD. No full-flow claim follows from supporting only this coupon's later operations.

## Costs, shipping and immutable history

Hardware area/state/latency: zero; PG metadata only. Existing pair's geometry/timing identity does not predict geometry after new source/native guards or prove conductor connectivity. Targeted native birth work should scale with new PG MTerms and applicable native rules, with full O(instances × PG terms + actual rule expansion) audits at stage boundaries. Rebuilding a whole-instance mapping once per inserted cell is rejected: the already observed ~98k-instance audit costs seconds, so such a design would be quadratic. No native timing/runtime measurement is claimed for this model. Native image build inventory/resources require a later measured admission.

Keeping functionality in the four existing conditional PG files preserves helper **counts** 49 default / 53 strict; shared ref_route/ref_tile changes may alter hashes in newly captured default plans despite default behavior remaining off. Do not promise old and new default digests match. Existing immutable 48/49/53 payloads and plans remain exact and recoverable; no retrofitting capability fields or helpers into historical strict jobs. An old strict job without native capability must refuse a new birth-safe claim, not silently acquire a new image/helper. A native image must be pinned by digest and source/capability receipt through source generation, submission, installed bytes, process start and fresh collector; that is an additional frozen dependency, not a mutable executable outside the 53-file count. Gate-Rule is tightening, scoped to strict PG behavior; default source behavior remains unchanged.
