TOP defaults to `qkd_host_control_packet_capture_token_service`; other supported tops are `qkd_host_token_service`, `qkd_host_native_token_endpoint` and `qkd_host_service_guard`. Set VERILATOR to the installed5.050 binary and HOST_BUILD_JOBS to the admitted worker count. Generated `OUTPUT/obj/VTOP.h` and `VTOP__ALL.a` are the public callable API; OUTPUT/callable.json hashes both. Callers link the archive with Verilator runtime objects, use a separate VerilatedContext per simulation or shared context for related objects, update all inputs before eval, and deliver each credited pulse once. No HOST callable archive or live HOST build existed at publication; native dispatch owns the next build/composition.

The central allocator is external and unique. Connect token_request_valid/ready and token18/position18/generation2 to its request face; connect its held grant and allocated-valid/delivered witness tuple back to the corresponding token_grant/allocated fields. HC22v2 transports token epoch bits230:245, validity246 and distinct service epoch247:262 unchanged to all ranks. The endpoint outputs request_v and full59bit stage0/segment0 TAG plus generation/token/position and pr143. request_v is a credited one-cycle event; the registered cohort must receive eight genuine endpoint events, return actual credits and hold execution until all eight match. Seven packet copies or a timer do not satisfy the barrier.

Native normal result input is a credited one-cycle event: result_v with full matching head37/segment0 TAG59, generation2, done/fault/cause4, next_token18, next_value32 and cycles32. result_cr returns storage at retirement. All actual KV/VM/collective/HOST drains must be true before TK93 completion; done0/fault1 is supported without fabricated done. Results must originate from actual native head/abort execution; test callbacks do not certify numerical execution.

Cancellation is a separately held record cancel_valid/tag59/generation2/done0/fault1/drained4. abort_drained bit ordering follows the transport RTL: inspect the explicit collector wiring and connect genuine drain flags, never readiness constants. token_cancel_accepted must be the selected collector acknowledgment qualified against that exact held identity; an unqualified acknowledgment for another terminal must not clear this record. A central collector arbitrates normal and cancellation terminal records and retains a selected record until the allocator/cohort acknowledgment. The allocator terminal-consumed rearm requires terminal_valid to drop between accepted records.

por_n alone clears the epoch allocator and rank replay witnesses. HOST warm reset flushes the endpoint/credits while allocator identity and cancellation witnesses remain retained. The actual native execution reset/queue flush must share the same host_rst_n contract; no independently reset token counter is permitted. FFFF reuse and identity-fault recovery require real four drains plus link reset seen and retraining done, using token_wrap_* pins. The warm service epoch is a separate prerequisite, and ready from an old service epoch cannot authorize a new token.
