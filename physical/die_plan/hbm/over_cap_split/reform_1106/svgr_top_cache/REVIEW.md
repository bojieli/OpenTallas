# SVGR TOP cache SRAM successor

SOURCE/GEOMETRY PROPOSAL READY, physical qualification NOT RUN. Whole TOP swap is the first option; native helper cut is secondary and unadopted.

The canonical packed136 and split RTL remain byte-identical. packed136 stores **136 bytes = 1088 bits** per row, across four full 256-bit payloads and 64 useful bits in the fifth. Both banks retain 64 rows. The catalog contains no matching single-clock 128x64 master; the two-clock master changes the contract and is not selected. The approved 128x256 r0c0_g256 master already exists in the repository. All native writes set every original w_mask bit; original repair pins are tied zero. A scalar mask of one preserves these writes. Both macros register read data on the same clk edge, hold when read CE is zero, and receive identical addresses/enables.

`ot_svgr_cache136_native` adds RW_SRAM=0 by default. `ot_svgr_top_cachecut` adds CACHE_RW_SRAM=0 by default and changes no other source logic. The optional whole TOP recipe selects CACHE_RW_SRAM=1. The whole TOP external ABI, stream_clk, native reset, face shell, and original descriptor/programme macros are retained. No new internal timing boundary is introduced by the SRAM swap. `svgr_top_rw_kit.py` passes through the canonical backend recipe unless --cache-rw is explicitly supplied. No main recipe or plan is edited.

Exact full-shape native bench: 190 reference rows, 270 cache reads, 80 cross-bank overlap cycles, 242 source edges, 828 sectors, seven invalid-protocol fault cases. Both original/default macro and optional RW macro modes pass against a concurrent canonical helper. Payload-flip, read-address alias and removed-read-edge mutants are caught. Full released TOP parameters elaborate in both modes. The pre-existing producer out_bank width padding warning is retained; neither composition adds it.

Actual render `macro_pin_review.png` was opened and reviewed. It draws the retained TOP B external pin locations and every SRAM signal pin from the actual LEFs. Five cache macros become 91.8x27.576 um (was 94.824x41.064), while signal pins fall 819->530 per macro and maximum face pins 410->265. Cache area falls about 35%. MY orientation puts read pins toward the inner logic. All five proposed RW macro origins are on the approved 48-nm grid; descriptor/programme locations and external pin locations are retained. The cache2/desc_hi pair remains in measured hot band y160..200: smaller SRAMs remove pin burden and obstruction, but do not prove the whole hot band closes. The render shows no macro/halo collision. Verdict PASS-COND for whole TOP source/geometry proposal; requires HBM exact source/geometry/PG adoption and physical measurement before closure.

The secondary helper proposal is a compact two-column, three-row bank at 224.64x250.56 um. All five original macros fit with 4.32-um halos and 10.8-um nominal channels. `graph.json` maps every helper group to actual parent sources and first captures. block_ready, bank_owned, busy, fault remain combinational; this is an INTERNAL_CORE/R2_INTERNAL_TIMED_IN_PARTITION proposal, never blanket all-pass. Helper/remaining-parent native mapping counts, exact die rectangle allocation, seam PG continuity, parent clock/reset delivery and terminal fault ownership remain NOT ADOPTED / NOT RUN. The helper is not ready for P&R.

`resource_assessment.json` records retained measured TOP synth/placed functional counts, excludes TAP cells, and projects utilization using the retained placed standard-cell area and reduced macro area. These reference numbers are below 150k/.45; they are not a new mapping or physical pass. No P&R/STA was launched. Original failed TOP A/B evidence remains untouched.

Only the reachable TOP/feed/stream-producer closure is included in the unique composition; the stream-producer module also has a unique name. The unrelated OWN/RF1 modules are not copied into this proposal. The helper source hash exactly matches retained TOP B (f06fc1118b435ef275bf52bcd152c33fa8dab4bf56bf8659afab372c8dd20fc5). Retained TOP B applies the normal __fcore rename; newer canonical split source also contains unrelated default-off OWN RF1 definitions, which are outside this selected closure.

Kit hierarchy: because the unique source top is ot_svgr_top_cachecut, the shared backend emits its established wire-only port adapter as u_core before applying the ordinary face shell. Recipe macro paths therefore start u_core.feed / u_core.issuer; generated shelled paths start u_fcore.u_core. No register or edge is added by that adapter. The reviewed whole-TOP origin table names these exact proposed paths.
