This additive delivery uses one `ot_hbm_native_register_slice` implementation and the existing `ot_fwd_link_stage`. The owner inventory is 23 kinds / 348 copies; 208 waypoint copies (168 forwarding, 16 gather, 16 multicast, 8 distribution) do not imply 208 native implementations. `variants.json` specifies eleven width classes, H/V pin sides, and 55%/60% placement targets. Every prepared route is explicitly unlaunched and unhardened.

The native wrapper carries four captures, matching the existing die station state sizing, with a real kept inverter at every boundary. Its reset vector supplies one synchronous reset per forwarded domain. It is default-off. It has no ready pin: producers must reserve downstream capacity. Data is unspecified while valid is low; there is no backpressure holding promise. Payload protection is preserved transparently, but protection of valid/control and actual parent reservation/reset implementations remain open. A four-capture cluster cannot claim four remote spans without the actual placement, clock wire and receiver context. It is not an adopted optimization or a closed parent.

`tb_native_slice.sv` exercises W2160 at full width with one deterministic seed and reset recovery. The passing gate reports 1,200 checks. The real negative changes the source inverter to a wire in a temporary copy and fails check15 after initialization. Original source bytes are unchanged. Initial negative evidence was retained; the monitor then excludes reset initialization so rejection proves the mechanism rather than unknown initial state.

The 974-bit link and 512-bit host ledgers include opposite TX/RX directions. Their parent needs independently clocked directional slices and the corrected bit packing. Multicast requires actual tap and branch ports; gather requires aligned t0/t1/a/a2 joins and validity; control distribution requires actual demultiplexing and reverse busy/arrive semantics. Generic forwarding does not implement those functions. Their parent views remain OPEN pending direct source-owner contracts. No leaf clock is borrowed for a parent and no missing protection is priced at zero.

`export_routed.py` reads the already-closed W512/D4 meso FIFO final ODB/SDC/SPEF and verifies its committed hashes and exact RTL bytes. It exports real LEF, separate SS/FF extracted timing models, input load maps and expanded clock-to-output paths. It does not synthesize, place, route, or repeat the passing exact/signoff campaign. The selected FIFO has SS+10.13ps/FF+9.44ps, zero DRC/slew/cap, and 4842.31um2 standard-cell area. Its original core utilization was 30%; extraction does not silently claim a new 55–60% route, H/V layout or parent closure. At least48 crossings require two real equal-frequency clock domains, resets, live/fault/credit ports and their measured latency (2.0135 average periods/crossing, typical4/edge5 periods/roundtrip). No unclocked-station credit.

`prepare_variant.py` prepares pinned route argv without submission. `station.sdc` requires all four actual mapped forwarding roots, unchanged 1.2GHz SS60/FF25 and real generated waveforms; missing roots fail rather than introducing clock cuts. The existing PRE_CTS hook preserves forwarding inverter trees. `cpu_fit.py` checks fresh CPU/load and caller-inventoried disk before and after the unchanged host admission guard. It exits on hold and does not queue a RAM-only worker. Heavy execution is EPYC2 / NVMe2 only, 16threads. No heavy job was launched with the observed fleet overload.

The two SerDes and one host reservation slabs are placement blockages, not LEF logic. `reservations_r14b` records their original selected DEF rectangles and empty pin sets. The parent r14b is invalidated; geometry is reference-only until the die owner supplies its corrected allocation. Existing PHY/SerDes/UCIe views are reused by their owners and are not rewritten here. No die generator or Claude structural source is changed.
