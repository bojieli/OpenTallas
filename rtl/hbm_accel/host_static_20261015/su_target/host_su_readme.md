# SU native host target component

`host_su_target` instantiates the unchanged actual `ot_hbm_su_programme` and its target SRAMs. Connect the host transport's SU transaction to `cfg_v`, `cfg_bank[15:0]`, `cfg_row[6:0]`, `cfg_data[255:0]`. The bank and row are configuration metadata, independent of the 256-bit payload. `cfg_accept` is the actual native macro write enable. `cfg_ready` indicates idle installation capacity; invalid bank, row or dictionary reference is rejected and sets sticky `fault`.

Elaborate with the compiler manifest's `EDGES`, `LINE_BITS`, `DICT_BANKS`, `DICT_ENTRIES` (manifest `dictionary_entries`) and `MACROS`. Hardware records successful writes in a finite control bitmap and checks every index lane against its dictionary's true entry count. It rejects padding rows, unknown banks, writes while busy/scanning, and config/validate/launch collisions. Reset clears installation tracking and sticky faults, so a reset requires reinstallation even though physical SRAM contents may survive.

After the last accepted write, leave two full quiet edges, then pulse `validate_v`. A deterministic scan checks all required index and dictionary rows. `block_ready` appears after exactly `config_transactions` scan edges. It never comes from host input or SRAM power-up contents. Any subsequent write invalidates the scan. Missing rows latch a fault; reset and reinstall before retry. Programme `length` is in 1..EDGES and always starts at native PC zero; an enclosing descriptor must enforce base zero. An accepted `launch_v` is the same edge as native `start`. The first valid command is presented after launch+3 and consumed by a sequential downstream engine at launch+4; following commands have interval one without runtime stalls. Readiness drops while native busy, then supports replay without reinstallation.

Prepare a real image with `python3 tools/hbm_static/host_su_target/host_su_prepare.py PROG_MEM OUT`. Pass `--extra-mem CAL_MEM --extra-bits 64` for the native-VM composed 9752-bit command/calendar image. Build/run the generated component bench through `ot-run --mem 16 --threads 4 --dir STAGED_ROOT -- bash STAGED_ROOT/tools/hbm_static/host_su_target/host_su_run.sh OUT`. It compares every command bit and exact presentation edge twice, checks omitted index/dictionary rows, invalid bank/reference, stale validation, busy writes, and requires data/address/phase/readiness mutants to fail. SRAM power-up initialization is disabled.

The checked-in model records the actual 7111-edge, 9688-bit compiler inventory. The 301 macro outline sum is 1.171364665 mm2 before placement whitespace, controller, bitmap, muxes and clocks. The 38,528-bit bitmap exceeds the 15,000-sink controller root rule by itself: a physical implementation needs partitioned roots or measured compliant CTS. This is component logic/storage evidence; whole-SU numerical qualification, parent host wiring, compiler descriptor integration, mapped controller area, clocks, TT/FF timing and DRC remain separate work.
