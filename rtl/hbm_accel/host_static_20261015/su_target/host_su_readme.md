# SU native host target component

`host_su_target` instantiates the unchanged actual `ot_hbm_su_programme` and its target SRAMs. Connect the host transport's SU transaction to `cfg_v`, `cfg_bank[15:0]`, `cfg_row[6:0]`, `cfg_data[255:0]`. The bank and row are configuration metadata, independent of the 256-bit payload. `cfg_accept` is the actual native macro write enable. `cfg_ready` indicates idle installation capacity; invalid bank, row or dictionary reference is rejected and sets sticky `fault`.

Elaborate with the compiler manifest's `EDGES`, `LINE_BITS`, `DICT_BANKS`, `DICT_ENTRIES` (manifest `dictionary_entries`) and `MACROS`. Hardware records successful writes in a finite control bitmap and checks every index lane against its dictionary's true entry count. It rejects padding rows, unknown banks, writes while busy/scanning, and config/validate/launch collisions. Reset clears installation tracking and sticky faults, so a reset requires reinstallation even though physical SRAM contents may survive.

After the last accepted write, leave two full quiet edges, then pulse `validate_v`. A deterministic scan checks all required index and dictionary rows. `block_ready` appears after exactly `config_transactions` scan edges. It never comes from host input or SRAM power-up contents. Any subsequent write invalidates the scan. Missing rows latch a fault; reset and reinstall before retry. Programme `length` is in 1..EDGES and always starts at native PC zero; an enclosing descriptor must enforce base zero. An accepted `launch_v` is the same edge as native `start`. The first valid command is presented after launch+3 and consumed by a sequential downstream engine at launch+4; following commands have interval one without runtime stalls. Readiness drops while native busy, then supports replay without reinstallation.

Prepare a real image with `python3 tools/hbm_static/host_su_target/host_su_prepare.py PROG_MEM OUT`. Pass `--extra-mem CAL_MEM --extra-bits 64` for the native-VM composed 9752-bit command/calendar image. Build/run the generated component bench through `ot-run --mem 16 --threads 4 --dir STAGED_ROOT -- bash STAGED_ROOT/tools/hbm_static/host_su_target/host_su_run.sh OUT`. It compares every command bit and exact presentation edge twice, checks omitted index/dictionary rows, invalid bank/reference, stale validation, busy writes, and requires data/address/phase/readiness mutants to fail. SRAM power-up initialization is disabled.

The checked-in model records the actual 7111-edge, 9688-bit compiler inventory. The 301 macro outline sum is 1.171364665 mm2 before placement whitespace, controller, bitmap, muxes and clocks. The 38,528-bit bitmap exceeds the 15,000-sink controller root rule by itself: a physical implementation needs partitioned roots or measured compliant CTS. This is component logic/storage evidence; whole-SU numerical qualification, parent host wiring, compiler descriptor integration, mapped controller area, clocks, TT/FF timing and DRC remain separate work.

## Dedicated AXI-Lite32 installer

`host_su_axi_install` wraps the target directly. It holds AW and W independently and retains B/R responses under host backpressure. The host transport clock must be the addressed target's installation/control clock; independent serial and stream instances each receive their own AXI boundary. A parent address demultiplexer and any asynchronous host transport belong outside this module.

| Address | Write | Read |
| --- | --- | --- |
| F34 | `{reserved[8:0]=0, row[6:0], bank[15:0]}` starts one macro word | Most recent selector |
| F38 | Eight 32-bit chunks, least significant first; only chunk eight reaches the actual macro write port | SLVERR |
| F3C | `1` requests hardware required-row validation | bit0 ready, bit1 busy, bit2 target fault, bit3 installation capacity, bit4 partial word, bits7:5 next chunk |
| F40 | Length in 1..EDGES | Length |
| F44 | `1` launches the validated programme from PC zero | Zero |

All writes require all four strobes. Unknown addresses, reserved bits, incomplete words, invalid control values, unavailable targets and premature launches return SLVERR. A rejected register operation does not silently extend native execution. An out-of-range native bank/row/index on the eighth payload chunk returns SLVERR and latches the target fault. Reset clears a partial word. Installation readiness is withheld while a selector/payload transaction is incomplete. Nine AXI writes install one 256-bit word; the boundary supports a minimum write initiation interval of three local edges with immediate responses. Payload assembly and AXI state add 387 FF bits, excluding the native target.

The current RF36 two-plane image is source `e74a2e646`: serial SHA `ef51677866608d14c080d0aef73939220f5e18230a566a015d511c0f07daff2a`, 7116 edges x9688 bits, 302 SRAMs/34452 writes; stream SHA `fcba67807bbf4d3be28ae2f3fcd063b547f09248ef095d22c06fd3bac098363d`, 9489 edges x64 bits, 76 SRAMs/9493 writes. These are independently installed native producers at 900/1200MHz. Their macro outline sums are 1.175256242/0.295759849 mm²; loaded bitmaps are 38656/9728 FF bits. The two-plane epoch bench uses the same integer event lattice as the native composition, launching each producer four local edges before the shared downstream sample epoch. It verifies every sampled command and rejects a one-stream-edge epoch shift. This is fixed-phase RTL simulation; physical phase/skew, metastability/CDC, parent demultiplexing and whole-SU numerical qualification are not established.

For a stream image, use `--line-bits 64 --lowerer PATH_TO_CURRENT_COMPILER`; a frozen compiler outside its checkout can use `--lowerer-root CHECKOUT` for dependency pins. Generated benches pass named typed dictionary arrays, avoiding Verilator 5.050's assignment-pattern resolution against the unspecialized 38-column default. `host_su_axi_run.sh OUT` exercises the full AXI installation path, independent AW/W order, retained B/R responses, response errors, missing-row rejection, exact native output timing and replay. `host_su_pair_prepare.py IMAGES` and `host_su_pair_run.sh IMAGES` handle the shared sample epoch independently of AXI installation.

Current installation/readiness layout supports `INDEX_PACK=1` only. Opt-in `INDEX_PACK=16` is unsupported until required-row accounting and all packed index-lane checks are adapted. The preparer refuses such manifests; attempting the six-macro packed stream capacity with the current native target fails its capacity elaboration check. Parent integration must bind the explicit supported-layout metadata before sending any configuration. No packed-image adoption is implied by the unchanged bank/row transport ABI.
