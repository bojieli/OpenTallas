# Native HC STRIPE4 prefetch component

`ot_hgi_hc_prefetch_static` is an opt-in actual RTL producer at the HC weight-aperture boundary. The row descriptor is the source-owned 20 GiB STRIPE4 layout, not the historical 30 GiB simulator hook. Eight HC-bank segments occupy 320 contiguous sectors each at row base + bank × 10,240 bytes on stack bank modulo four. It instantiates the production address mapper and corrected sector-address/XOR-PC native prefetch CDC. PHY requests and responses are the only modeled boundary in the paired gate.

Four native engines retain two segments each. Each engine contains 32 actual mapped 128×256 SRAMs, for 128 macros/512 KiB of prefetch staging. Their configurable fixed delivery interval is eight cycles; each emitted eight-sector burst is serialized from four 2048-bit registers into four HC bank writes per cycle. These writes transpose into an additional 32 real landing SRAMs (128 KiB). Two fixed 256-cycle, eight-bank delivery blocks carry all 2,560 source sectors plus 1,536 explicitly zeroed padding sectors. The actual HC bridge drives the 64-macro, 256 KiB aperture. The standalone default therefore has 224 real SRAM macros/896 KiB. `INTERNAL_APERTURE=0` omits the standalone aperture and exposes `ap[2223:0]` for the actual HC engine's store, avoiding duplication in the full arithmetic join. The extra staging is a measured functional mechanism with explicit resource cost; physical slot and throughput qualification remain open.

The compiler or actual upstream sequencer provides these pulses on the stream clock:

1. `row_v`, row-local byte base, HC slot and epoch; allow six edges for the two landing-bank opens.
2. `reserve_v` with half zero then half one. Check all `reserve_ready` bits before each reservation. Wait for whole prefetched blocks (`fetched_ready=8'hff`), solely at the permitted PHY boundary.
3. `drain_v` half zero and half one, separated by 330 stream edges. Each drain is forty eight-sector bursts at fixed II eight; each burst feeds eight consecutive serialization writes. No per-lane readiness is consulted.
4. `pad_v`, then 196 edges to write positions 320 through 511 as zeros into the second landing block. Both `delivery_ready` bits must now be set.
5. `deliver_v` half zero and half one, separated by 264 edges to cover 256 reads plus bridge/aperture pipeline. The bridge's source-sector bases zero and 2048 are logical addresses within this staging allocation, not physical HBM addresses.

Production reserves must prefetch ahead of the compiled consumer timeline. A delayed off-chip read can postpone entering a block; it cannot stall or stretch these on-chip sequences. A complete static compiler/sequencer join and overlapped refill schedule are still required. This component's setup/control pulses in the bench are external component stimuli, not a full-chip native controller claim.

`tools/export_hbm_hc_stripe_row.py` reads an explicitly named safetensors FP32 `[24,20480]` tensor by exact file offsets. It writes bank-major source bytes, 256-bit sector hex, descriptor provenance, source and checkpoint-row hashes. `--all-rows` emits all 24 rows, `rows.json`, and a 24×20480 original-order FP32 matrix for the arithmetic reference. Synthetic input is explicitly opt-in and labeled; reduced shapes are refused. The real released layer-zero attention shard was available for the source-bound gate.

The paired gate freezes all eleven actual source/model files, exercises distinct stream/HBM clocks at 833.332/1024 ps with arbitrary PHY response delays, checks the exact XOR PC and 20 GiB source segment on every request, and reads both HC slots through actual SRAM ports. The mutant corrupts bank five's final source sector before landing and must fail at actual SRAM readback. No on-chip numerical or memory substitution is used. This does not prove loader installation/ACK, the full 43-layer image, all 24-row arithmetic consumption, physical closure, immutable price, or complete native chip behavior.
