# Actual INDEX512 to native TKM boundary

`ot_hgi_coll_idx_tkm_join` is a new typed component parent. It instantiates the actual fixed-pass INDEX selector, actual global512 staging producer, explicit VM/IDX ingress station, a real four-source/four-sink qslots transport and the real KMAX2048 TKM engine. It hardwires native `cfg_n=512` and `cfg_pf=64`; selected512 records become64 native flits. The existing V1/V2/V3 parents and their proofs are unchanged. This parent has64 explicit synchronous physical clock entries:17 selector,9 staging,1 reservation check,1 ingress,2 transport and34 TKM. All clock phases and physical relays must be accounted for by the compiler.

The real selector scans **171 source lines**, not128 historical TO slots. Its actual selected record stream is4×16 entries of37 bits `{id20,BF16score16,valid1}`. The native staging producer compacts exactly512 chosen records into eight real64x512 SRAM macros. BF16 scores are expanded to FP32 by appending16 zero bits; IDs are zero-extended from20 to32 bits. The four545-bit output flits carry eight FP32 scores in their low256 bits and eight U32 IDs in their next256 bits, with header `{valid1,destinationFF,rank8,global_flit16}`. Global flit index is `(rank-gbase)*64+local_flit`; this matches the actual TKM provenance calculation for nonzero rank/base. Native staging source is pinned to39e0af759 and the exact selector/macro inputs are hashed in `idx_tkm_native_sources.json`.

`staging_ingest` is the explicit compiler reservation. The actual selector `selected_v[3:0]` is checked against four copies of that bit on the sampled edge, while the actual `selected_line` drives staging data. A missing or unexpected producer faults; it cannot delay staging. The declared `score_line` input is the selector's external score boundary, not a preselected answer. Binding the upstream actual INDEX arithmetic/query/VM service remains H-IDX's separate production requirement.

The typed ingress station physically captures **both** native VM and native INDEX input faces. Its compiler mode and complete expected bitmap are captured with them. One edge later it registers the selected payload and validity. Any activity on the inactive typed port, or a selected-valid mismatch, faults without moving an output edge. It introduces no demand arbitration, queue, credits or backpressure. The explicit VM port is not relabeled INDEX; the station is named and versioned as a shared boundary. The original SW mux root remains14,824 bits; expanding it with four extra sources would exceed its current budget. This separate local transport remains a component composition, not a claim that a new full-parent ISA/source calendar is already adopted.

For a staging emit reservation at E, the actual producer launches its four flits after E+1; ingress captures E+2, publishes E+3, qslots captures E+4 and launches E+6; native TKM samples E+7. TKM's first sample is its start+9, so **TKM start must be E−2**, with subsequent emits exactly8 edges apart. There is no SU INJLAT12 assumption. The producer's source-pinned first launch is frame833; this composition's first transport output is838 and consumer sample839. For local G1, native TKM starts830, consumes16 beats through959, and its declared KMAX2048/nout512 schedule finishes at1583 (753 edges from TKM start). These last TKM numbers are inspected source contracts, pending composed real-engine execution; they are not claimed as measured qualification.

Each local producer holds one rank's512 candidates. The new parent exposes `cfg_g`/gbase for native TKM typing, but only the local G1 case can be supplied by this one staging inventory without an actual multi-rank transport composition. A G>1 target needs all other ranks' real native producers/fabric; this parent does not supply their values or silently reduce the requested group. Full group96 and actual token-rate closure remain open.

The ingress station analytic budget is6,558 register bits on one root,4,375 input pin bits and2,185 output pin bits. The dedicated4×4 transport capture/output roots are2,185/4,382 declared bits. All are below15,000 by register count; mapped area, slot, reach, clock insertion/spread and routed timing remain unmeasured. Full extra latency and any end-to-end throughput effect require the integrated production compiler/price proof.

`run_vm_idx_ingress_bench.sh` checks73 full-width cycles, mode transitions, inactive-producer conflict, selected-bitmap mismatch and exact timing after sticky faults; incorrect data mode and disabled checker mutants fail. `run_idx_transport_bench.sh` runs the **actual selector and actual staging SRAMs** through the new station/qslots, checking three source-pinned score frames against expected sets only. It proves1,536 chosen records,192 flits and48 beats at the real TKM input boundary. The test explicitly does not instantiate or replace TKM and does not claim TKM execution. Wrong mode, wrong selected source and incorrect ingress reservation mutants must fail. The typed parent instantiates the actual engine, but its full-shape execution is deferred to the publisher's existing native engine build; no duplicate heavy TKM compile is launched by this stream.
