# Native SW ARGMAX selected-mechanism join

`tb_hgi_coll_sw_arg_join` instantiates the actual1536-bit SRAM program issuer, V2 SW control leaf, NS11/ND16 qslots, native ARGMAX fold, fixed VM writer and eight final SW VM banks. The gate includes three actual64x512 program SRAM macros and24 actual1024x256 VM SRAM macros. All ARGMAX operands are read from the actual VM SRAMs; their output records pass through the actual control assembly and qslots. The ARGMAX result passes through its distinct qslots source to the actual RGX writer, actual bank commits and actual native SRAM readback.

This is a selected-mechanism component gate, not a full q3 elaboration. The nonselected TKM, reduction, ring and link subtrees are outside its declared boundary. They are not replaced by computed results or latency-only substitutes. Production V2 RTL is unchanged. The bench observes the exact production mode expressions that suppress TKM valid/slot in ARG mode; it does not claim to execute the omitted TKM engine. `tools/hbm_coll_static/check_sw_arg_join.py` checks30 actual child-port connections against the production parent, as well as independent ARG source wiring, mode exclusion and ISA bitfields. Changed wiring fails before simulation.

External DMA preload writes96 declared operand lines into the real SRAMs before each run. The bench uses five cases from the native ARGMAX component specification: maximum ties choosing lower unsigned ID, all NaNs choosing lower ID, signed zeros comparing equal, infinity with a NaN present, and negative values. Expected answer functions only check actual outputs; they never drive internal operands, SRAM responses, arithmetic results or completion acknowledgments.

The real issuer receives all64 rows through its37-bit configuration interface. It executes24 consecutive four-line read requests. Native responses and every resulting545-bit operand record are checked at exact cycles. The program starts ARGMAX with group96, base0 and publisher rank3. Separate compiled mode/slot instructions route four VM sources to the four ARG sinks. Source membership is checked by the actual ARG controller, which receives all96 unique ranks. No arrival-driven completion is used.

Relative to the program start edge, the four input sink records are visible after edges17 through40; ARG samples them at18 through41. Flush occurs at42, and registered publication at48, exactly six edges later. The result source is captured by qslots at49 and arrives at its writer sink after51; the actual writer captures at52. Low/high sectors commit to SRAM at57/58, verified from actual `kq_done`. A programmed readback request reaches the real bank at61 and its registered result returns at67. The issuer's fixed halt pulse occurs at66, while the declared read-response pipeline finishes at67. This gate explicitly observes the remaining prescribed response and does not claim halt alone drained it. Full production programs must place their halt after all externally required responses.

Five runs check480 exact native operands, five exact winner records, ten actual result-sector commit pulses, and five native SRAM token readbacks. Every native response-valid bit is checked, including absent cycles. Mode misuse, wrong ARG result-source selection and early publication mutants each fail. The negative mode case verifies that the excluded TKM valid/slot expressions would become active; it is correctly rejected rather than silently interpreted as another operation.

The source manifest and logs record the exact tested inputs. The native bank is pinned to0334452c through `native_vm_sources.json`; changed bank or macro source fails before building. This gate does not prove full G96 network traffic, group reduction/multicast, full SW parent physical hierarchy, license PHY behavior, distributed mirror replication, die timing or end-to-end token rate. It complements the frozen V1 and V2 component proofs without broadening them.
