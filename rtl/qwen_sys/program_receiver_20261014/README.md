# Actual program write commitment

`qkd_program_pw_observer` decodes the exact two-bank, 64-row, 512-bit program SRAM interfaces. Bind its inputs to the same `w_ce_in`, `w_addr_in`, `wd_in` and `w_mask_in` nets consumed by both real SRAM macros. The combinational observation is sampled by `qkd_program_commit` on that same write edge. It requires exactly one enabled bank and one full 64-bit slice mask; address reconstruction is `{row,bank,slice}`. Disabled-bank masks do not cause writes.

Bind DW events to the actual synchronous descriptor-store write enable, address and data, with `dw_full_word=1` only for a store which always consumes all 64 bits. If observations are registered, register PW and DW consistently. Host launch pulses and program replay timers cannot replace these observations. Every physical program copy needs its own observed ledger, including TT and SU copies. Each ledger emits an attestation only for its own observed bytes.

BEGIN clears old ready/capability and requires the production dense profile of PW 0–1023 followed by DW 0–7. Independently transported AUTH must have the same program image epoch and an external authorized digest. Only those actual writes update the seed `51484f5354505247` using ROL7 XOR data64 XOR `{53'd0,is_desc,addr10}`. The final actual DW write verifies the digest. The ledger then waits for actual ME/SU/XPF store-seal validity before emitting a single commit and stable ready, epoch and digest. Missing final writes never commit; other missing writes, duplicates, wrong order/address, corrupted data, wrong epoch and partial masks reject the image. Faults remain sticky until reset. No write-ready handshake is added.

The installed fused capability is captured from bit 12 of actual consumed PW 1023 only when its XPF1 footer magic, opcode, reserved bits and count format are valid. It becomes visible only with the verified image and real store validity. A valid non-fused image can become ready with capability zero. The compiler must derive the authenticated footer bit from the actual supported native program. Runtime token epoch is separate from installed program image epoch.

`qkd_program_commit_join` combines independently verified physical copies. Every sink must first revoke its old ready after BEGIN. All subsequently ready sinks must match the separately authorized image epoch and digest; one missing or mismatched copy prevents commitment. Faults from any sink revoke the aggregate. Cross-clock synchronization and actual metadata transport belong to the physical route; these ports require synchronous signals.

`run_gate.sh /absolute/output` builds a small focused bench with the actual SRAM functional model, reads back all 1,024 PW words, checks the eight descriptor writes, exercises eight bad-write cases, delays actual store-valid permission, checks capability zero and tests missing/stale/mismatched physical copies. Its descriptor array is a bench vehicle; this receipt does not establish whole-controller integration, production clocking, routed timing or throughput. Actual TT/SU observer exports and the typed metadata transport must be connected and tested by their owning integration streams.
