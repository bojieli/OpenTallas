# Opt-in static rstd release mechanism

The xrt1/xrt3 masters accept QDELAYS, one shared128-bit LUT of sixteen8-bit cycle delays selected by the existing sid strap. A compiler/kit may provide `OT_S81SL_QREL_DELAYS`; the macro defaults to128d0. Zero elaborates to wires and preserves the current design. Nonzero delays hold the32-bit rstd word and release its valid on the exact static edge; no ready/backpressure. An overlapping rstd or sid change while holding raises a sticky fault through the existing collector fault group.

Smallest actualRTL bench: all16SID values,48payload words/3280cycles PASS; reset cancels pending valid and data has no reset; overlap and sid-change fault controls PASS. Wrong-release mutant (SID2 delay+1) caught6mismatches. Actualxrt1/xrt3 locksteps against pre-change78efb0f49: default0 and nonzero hold,20,000cycles each, every meaningful output bit agrees. The nonzero reference delays rstd through an independent pipeline reset by its own matching region reset relay. Invalid rb_d is unobserved; valid/data and all other outputs remain strict. Initial comparison failures were test-fixture issues: old full-pin reference adapter against the current narrowed reference, then an early-reset pulse buffered before the reference's delivered reset. Original failure run dirs remain; corrected focused fixture is committed.

This qualifies the generic mechanism only. The arbitrary test table contains delays0..148; it is NOT a production release calendar. The earlier C1 zero-collision schedule used an incorrect direct V-partner assumption at column4; its claimed schedule validity is withdrawn pending the full seqhost/bk_sel V route. TOK-DS owns that correction and will regenerate the LUT from the actual C8 schedule. Do not enable this prototype in a production profile before the corrected occupancy model and actual token cut pass. Four-slice q_norm and head XB-only schedules are not automatically qualified by the16-slice attention norm calendar.

Hardware sizing: optional47state bits (32data+4heldsid reset-free;8counter+busy+valid+stickyfault reset as control), per xrt master, plus a16x8 constant selector and decrement/comparison logic. Existing ports, widths, outlines and neighbours unchanged; zero extra boot fields/cycles. The existing sid strap and reset/start ordering remain required. No extra reset synchronizer is added. No P&R/STA launched, and no timing closure claimed. Re-sign xrt1/xrt3 and refresh their C1/C3 partition timing views when a nonzero table is adopted; plan latency and compiler schedules must carry each selected delay and its downstream quant/allgather completion. No algebra, rounding or reduction-order change.
