# Shared core infrastructure implementation coupon

`tools/die_plan/core_infra.py` is the common slice-driven core implementation for QC, S81, HEAD, KV and HBM. `master_slice.kit_apply` invokes it only for an explicitly supplied core slice with `pushdown`; kits without a slice remain unchanged.

The hook creates fixed core-owned noninverting clock/reset feedthrough BUFs and dedicated M5 ports; the core clock/reset remain separate inputs. It binds native PG terminals before setting dont_touch, protects the feedthrough nets, and refuses port/core-clock shape overlap, island fit/overlap failures, unidentified PG domains, missing sink identities and unassigned clock sinks. It removes the obsolete island holes/OBS from core slice application. Explicit `core_tree` nodes and named sink sets replace nearest-leaf heuristics. Equal stage counts and equal sink counts are checked before a build. Named bay-cell and M7 pin assignments are consumed; unbound metadata does not masquerade as an implemented bay/pin.

The source API `emit_wrapper(slice, logic_module, original_interface)` emits the synthesis/LEC top wrapper with the same isolated feedthrough cells. Passing `logic_module` and `logic_ports` in the slice writes `master_core_wrapper.v`; the adapter must add this source to its synthesis source list and use the separate original logic master. No text-based RTL rewrites are performed. The core physical helper can also install the cells directly into a trial core ODB; its exported netlist is then the exactness vehicle.

Production adapters must supply the real clock port as `core_clock_port` or `core_tree.clock_port`, a complete type-specific tree/sink list, actual bay cell/pin bindings, and the frozen slice. The helper does not invent any missing contract, adjust a clock from measurement, choose a nearest leaf, or alter the master-plan freeze policy. This coupon is implementation evidence, not timing closure or die freeze evidence. Production views still require the normal LEC, geometry, route and sign-off gates.

The 86.4 x 86.4 um coupon has four pre-existing DFFs, a symmetric two-stage core tree with two equal-load leaves, two isolated FT buffers and four FT ports. Geometry in `review.png` was rendered and viewed: sparse macro-free core, short symmetric tree legs, no unstationed long reach, ample island area, core clock and FT pins separated on M5. The shared hook ran twice on the same ODB without duplicating cells/ports. Native PG census reports 18 terminals/0 failures (UNCHECKED by NUMBER-CHECK, from `coupon/coupon.log`). It added zero data cycles and zero reset cycles.

The final netlist was checked against the original four-flop core with a five-cycle lockstep SAT miter over arbitrary data and independent FT inputs. Positive proof PASS; a seeded reset feedthrough inversion FAILS the proof. Both ran via ot-run on fleet localhost, unit `oth-ubuntu-1844364-1793026449`, directory `/srv/opentallas-scratch2/claude/shared-core-0733/coupon_r2`. `miter.sh`, `models.v`, final netlist and logs are retained here. Failed initial fixture attempts (ASAP7 default make_tracks negative offset; nonexistent BUFx16 instead of BUFx16f; Yosys check cells requiring chformal -lower) remain as small logs in the earlier fleet `coupon/` directory and were diagnosed, not labelled physical design failures.

Focused tests: `test_core_infra.py` + `test_master_slice.py`: 36 PASS, 7 existing optional per-die-generator integrations SKIP in the narrow sparse checkout. No broad test wave was run.

## Actual RP1 core pilot

The shared helper was also applied to an own copy of the real RP1 R3 `3_place.odb` (259.2 x 276.48 um, two SRAMs), using the planned core clock entry (129.6,169.0) and separate FT pins. The existing RP1 macro/data-flow image was viewed first: the centre SRAM-row channel is clear for the two buffers/ports, macro interface logic stays at the existing edges, no new long path is introduced. The trial removed only legacy unconnected clock instrumentation and the two legacy FT buffers/ports from the copied ODB; the source ODB was unchanged.

`rp1_actual/apply.log` records PASS after two applications: exactly two new BUFs/four FT ports; every original functional instance/pin-to-net tuple is byte-identical before and after; data/reset cycles +0. The two new buffers pass the helper's native PG bind-before-protection checks. Existing core clock/reset ports are retained independently. Run: fleet localhost unit `oth-ubuntu-2067103-1793026917`, `/srv/opentallas-scratch2/claude/shared-core-0733/rp1_actual`. This was a structural/geometry implementation trial, with no CTS, route, STA or SIGNED claim.

The QC generator now passes its existing clock/reset port manifest to the shared `kit_apply` API. Exactly one explicitly named core clock is accepted; disagreement with the slice refuses. The original slice file and digest remain unchanged; the compiled infrastructure plan records the manifest binding. The wrapper API also preserves original ascending/nonzero packed-bus ranges from `offset`/`upto` metadata. Two focused adapter/range tests pass. The actual pilot's first private cleanup attempt stopped on a protected legacy FT net; correcting the cleanup order in the private-copy script resolved it. The failed small log remains on the fleet; no shared production helper clears protection.
