# In-hand checkpoint: normative refresh roots, not production qualified

The source adds opt-in `STATIC_REFRESH=1` to the real JEDEC controller. It selects bank 0..31 in round-robin order at the original 118-HBM-edge REFpb cadence, with the original 196-edge bank busy time and 48-edge precharge lead; pull-in is refused. The legacy dynamic key selection remains the default. Dynamic refresh choices depend on open/done/refreshed history, so merely choosing a larger literal startup constant cannot prove universal context safety.

New `qkd_kv_refresh_roots.sv` derives deterministic K/V quiet windows. K uses banks 0..7, V banks 16..23. Its warmup is a source-derived fixed point: old-row RAS28 + RP16 + eight PRE parity slots16 + eight ACTs32 + RCD19 + pin/row stages8 =119; periodic refresh/forced PRE costs at most19 edges per118; W=119+19*(ceil(W/118)+1)=176. This bound still needs independent review. The window excludes refresh precharge lead, busy time, warmup and eight I/O guard edges. Actual boundary counters and physical reset/strap epoch MUST bind the configured due phase; no guessed normal profile is permitted.

`qkd_controller_context_calendar` adds `REFRESH_ROOTS=1`. Image bits `[91:89]` choose role 1 K descriptor,2 K go,3 K RD,4 V descriptor,5 V go,6 V RD; original literal role0 remains. Descriptor15 is profile metadata: due phase `[107:96]`, profile-present flag108, V descriptor earliest-ready offset `[127:112]`. All reservations remain fixed functions of sealed image, global phase, T and group. No actual-ready input or production wait is used.

Independent Python compiler `refresh_roots.py` enumerates forbidden per-bank intervals instead of copying RTL modulo arithmetic. It derives full-rate K reservations with only necessary partial bank-group padding; V uses eight reads then five deterministic gap edges. `run_refresh_context_controller.py` checks the real calendar and strict PROFILE0 core.

The one in-hand PC13 run finished successfully during hand-back: 36 persistent changing-T frames, 6,626 exact reads and exact reservation timeline, with source/binary/image/expectation hashes in `pc13_receipt.json`. This is NOT all32-PC qualification: additional straps, negative controls, physical epoch/phase profile, mapped timing and cost remain unfinished. No new jobs may launch while Claude owns the lock.

Actual partial-block successors and their completed evidence are in `partial_front/`: 2,176 real calendar/front passes, 106,002 words, zero hold/stalls and peak25/32 storage; 288 landing numerical/timing/idle cases; updated core all32-strap regression. Original closed front and landing-calendar sources remain unchanged. New front requires `blk_nminus1[2:0]`; new group front calendar exports that field plus registered idle; new landing calendar exports actual pipeline idle. Exact final front mutations must be rerun after adding idle (earlier versions' read-address/full-tail/floor-block negatives failed).

Remaining production joins: a real bounded PHY service profile (tested jitter16 is NOT authority), measured phase-launch aperture/reset epoch and metadata hold, actual front/ring release margins, K/V write visibility and upstream quiet, actual native attention calendar and real die pins/views. Ring depth8 cannot absorb the native core/HBM full-context rate difference; a 64-row ring appears necessary and must be modeled/proved/mapped. The normative roots still need integration with the actual front/landing calendars and all stage/bandwidth/token cost pricing. Do not adopt the old arbitrary 300/900/1000/1300 witness roots as production.
