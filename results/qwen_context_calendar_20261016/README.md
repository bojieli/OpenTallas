# Variable-context K/V component candidate

The opt-in context descriptor uses actual token count T, stack and group, with K and V row counts computed in hardware from the same closed forms as the real front/landing calendars. It changes count per accepted `go`; it does not reset the persistent controller between layers or tokens. The original closed `qkd_controller_hbm_calendar.sv` remains byte-identical.

The new command ABI keeps the existing 43-bit boundary: `{first[9:0], command[31:0], valid}`. Command type `command[31:30]=3` is enabled only by `CONTEXT_DESC=1`. Its fields are row `[18:0]`, count `[27:19]` (0..256), V flag `[28]`, K order-B flag `[29]`; `first[7:0]` is the K first-segment count (0..128). The core tracks an ordinal and remaining count independently of the mapped physical sector. Empty descriptors issue no reads. V sectors alternate eight-sector chunks between physical bank sets 4 and 5, and both sets remain protected/preopened throughout the pass. K has both the native small-context permutation and large-context segmented order.

New `qkd_controller_context_calendar.sv` image bits `[87:86]` select literal/K/V count. Bit `[88]` substitutes a context descriptor into a single command event. Reservation runs use actual K/V counts. For partial order-B K, a non-multiple-of-four first segment can repeat a bank group sooner than tCCDL=3; hardware and independent compiler insert only the missing 0..2 HBM edges at that known segment boundary. There is no readiness input or dynamic wait.

Physical/accounting limits: new calendar adds 19 captured context input bits (`ctx_t[13:0]`, `cfg_stack[1:0]`, `cfg_group[2:0]`) and 27 active descriptor bits, approximately 46 additional FFs before synthesis. Each controller adds 29 state bits (ordinal/count, flags, first-segment count) before optimization. Image capacity remains 16x128 bits. Boundary and command pin latency remain unchanged. No new pin grant, mapped area, clock tree, route or physical master is claimed; `CONTEXT_DESC=1` cannot reuse the legacy closed view. Replica count and complete die area must come from the adopted real parent, not an assumed multiplier.

`shape/receipt.json` binds 400,207 actual hardware vectors over 64 contexts, every stack/group, both passes, empty streams, the 4096/4097 order transition and full T=8192. Expected addresses come independently from the native QK compiler and PV16 stream enumeration. Two deliberately broken count/mapping versions fail.

The old literal fixture roots fail for partial contexts: `fixture_roots_partial_failure.json` preserves a real missing-open bank at K ordinal 10 (T=1024, stack=3, group=1). A conservative component witness moves K first RD from 120 to 300 and V descriptor/go/first RD from 600/700/1000 to 900/1000/1300. These roots are diagnostic. They do not establish a production calendar or preserve the old performance price. Production must derive a refresh-safe schedule from actual reset/phase/history, check front/ring timing and price all roots. There is no per-token reset fallback.

The actual controller test uses PROFILE0 throughout 36 persistent layers with changing T and independently generated sector/address and reservation expectations. All-PC receipts cover each physical refresh strap. This proves a controller component; it excludes real PHY returns, SRAM/attention composition, full token/native die completeness and physical timing. The native attention 176-bit calendar producer remains a separate required dependency.
