## Actual receipt, rather than emitted count

For each calendar, each bit `seen[i]` represents an actual accepted correct 32-bit entry at address i. The acceptance predicate is exactly `cfg_we && !running && !cfg_addr[5] && cfg_addr[4:0]==i`. Compare the data HALF actually consumed: entries0..15 use cfg_data_c[31:0], entries16..31 cfg_data_c[63:32]. It is incorrect to compare only upstream b_data or a merged/emitted word. Base receipt uses `cfg_we && !running && cfg_addr[5]`, the actual cfg_base_c[4:0], and its two old/new sel1 copies. Canonical base address32 is additionally required by the private boot protocol; address33..63 must not certify the fixed image. Both one-hot copies must reflect the accepted decode before first start.

Target11 is 66 words: alternating TX/RX table entries0..31, then TX and RX bases32. Dispatcher target/address/epoch/padding checks and emitted linkcfg_done remain useful upstream checks, but do not set local receipt bits. A rejected/running/colliding/wrong-data/wrong-base write never certifies an entry. Wrong identity or any write after authorization, outside the exact sequencer runtime-base contract, poisons the generation. Detect simultaneous TX/RX boot enables explicitly; current BC ternary STALE can otherwise inspect only TX. No compressed hash stands in for actual equality.

The fixed-image component compares all2048 actual table data bits with the pinned K_TX_IMG/K_RX_IMG constants, and both actual 5-bit bases with K_TX_SEG2=9 and K_RX_SEG2=10. The immutable source/image SHA is evidence identity, not a hardware equality test. Epoch16 travels with the real target11 word through the SAME captures as that word, with a real producer-valid bit. Each calendar latches epoch on its first accepted word, compares every later word and first epoch request, and never counts an absent/misaligned metadata word. A new epoch cannot reuse old receipt bits. The current die does NOT carry this metadata to the calendar; adding that actual transport is a prerequisite, not an assumed existing port.

Production variable images are NOT covered by comparing to these compile-time constants. They require a separately selected exact expected-image authority and binding, or an exact source-to-acceptance correspondence proof. A collision-free digest may not be assumed. A full on-chip expected-image mirror would add2048 runtime indexed bits (plus identity/control), crossing the ~2kb storage threshold when combined; it requires a real SRAM/port/lifetime model. No such mirror or dynamic credit is proposed here.

## Settling and first epoch behavior

Let W be the LAST actual accepted entry/base write. On W, seen completes but the unreset first0/first1 prefetches still sample old state. At W+1 they capture the final image and cfg_recent clears if cfg_we=0. Maintain ONE local settled bit, set at W+1 from old all-seen && no current cfg_we && correct live identity; clear it on any write/reset/reload/identity loss. At W+2 its old value is1. Therefore an actual first start can be authorized at W+2, never W or W+1. A two-stage ready shift starting from old all-seen would accidentally add a third edge; do not implement that off-by-one.

The actual calendar start boundary checks old all-seen, old settled, correct epoch/provenance, both TX/RX readiness, !cfg_we, !cfg_recent, !running, coherent start/segment copies, and no same-edge reset/reload/halt/fault veto. All original start-dependent branches receive the SAME legal start decision; gating only ev_v later is forbidden. This blocks unauthorized state mutation at its cause, rather than masking downstream outputs. Runtime base writes after successful first epoch remain the original priced SEG2/SEG1 sequence and W+1/W+2 relationship; they do not demand a fresh 64-entry boot upload each token.

BC validates the real first calendar-epoch trigger BEFORE u_seq consumes epoch_go_q. If installation/identity/frontier is incomplete or a reset/reload coincides, assert sticky EARLY_FIRST and fail-stop that generation. Do not latch a pending request, wait for later writes, synthesize a replacement epoch, or shift an ordinary token start. Correctly installed startup passes the epoch at the original sampled edge and all subsequent ordinary anchors remain bit/cycle equal. Source joins/return transport can require additional fixed edges: those must be priced and scheduled before any physical adoption, not hidden inside ready waiting.

Preserve power/HBM boot_go and its training/reset sequence independently. Host initial setup protocol must explicitly arrange installation and the later first calendar epoch; no on-chip credit/backpressure waiter is introduced. Missing setup followed by an epoch is an observable failure, not a deferred successful boot. This is a ROOT-selected source contract change, not a claim the current interface already offers a separate first-calendar-epoch command.

## Fault priority and reset lifetime

Priority at each actual consumption edge: local reset assertion; generation invalidation/reload; current malformed identity/configuration or EARLY_FIRST; then healthy acceptance/start; otherwise original evolution. A same-edge new fault vetoes the operation even while old sticky fault is0. OR the existing source faults into sticky poison without replacing their causes. Fail-stop suppresses future owned calendar starts and keeps the actual fault visible until a real local reset and complete fresh installation. Reload invalidates receipt; it cannot silently clear poison or replay an early request. Upstream recovery/RAW POR/epoch-counter semantics are preserved and remain separate.

All106 logical receipt/identity/control bits reset on their actual calendar reset family; they are NOT POR-retained completion state. Either calendar reset invalidates the pair before any later epoch; asynchronous differing regional reset arrival requires a real invalidation/frontier protocol, not a numerical reset-generation counter assumed never to wrap. No native reset ID exists today. The private common-clock model defines generation identity as an interval after BOTH actual local reset assertions and before ANY intervening reset/reload. Numeric epoch16 alone is insufficient across reset.

Initial receipt Q may be arbitrary before actual local assertion; no self-initialized guard may certify startup. Bench must run actual reset landing from arbitrary Q and preserve all pre-assertion side effects. Full accepted-image overwrite plus W+1 prefetch can erase calendar data history only after the real common frontier. Recovery epoch/written-map/SRAM histories are separate. A first event before that frontier is a failure to expose, not a reason to arm the checker late. Missing native producer-valid and reset identity leave whole startup safety HOLD.
