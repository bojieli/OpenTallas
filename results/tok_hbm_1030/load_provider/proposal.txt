HBM STATIC LOAD provider integration proposal — SOURCE ANALYSIS ONLY
No RTL, plan, interface, target allocation or physical view is adopted here.
Root selected the narrow static-provider estimate/component direction B; binder
owns the new converter component. This note supplies the existing interfaces
and remaining structural choices, before implementation of a full provider.

Observed current source (intel1 codex-hbm-bind-0300/top_native.sv):
- hb_dbk_NE/NW are ot_hgi_dma_back_static_vp4_banks_cp, RR_RT80, both stk2,
  targets107/106. They consume matching NE/NW VM rr1 and implement STORE only.
- NE/NW vmb use sid3/2. Their DMA DQ input comes from raw NPC2 vmdel lanes.
- vmdel_NE bank0 consumes vmks_NW4/6 PC0: PCs16/24. Across8banks, NE receives
  stack2 PCs16..31; NW receives stack2 PCs0..15. Current SE/SW DQ are top inputs.
- vmfc_NE/NW are existing hfd_hgi_vm_calendar_f20_role W89, targets59/58.
  payload[51:0] holds begin/start/bank/epoch/base; [52] opens VM fill window,
  [53] buffer bank,[69:54]epoch,[84:70]row,[88:85]column.
- Current ot_hbm_svc_vmdel_lane_n has no scheduled arbitrary-format LOAD port.

Existing static-compatible source that supplies the missing mechanism:
1. ot_static_cmd_target MODE1: CW62, RELF0 is a direct fixed-dated command
   issuer for the existing62-bit LOAD command. No ready, credit, deferred issue
   or runtime rescheduling. It uses a128-entry command table, so full MTP VERIFY programme
   operation needs descriptor/loop compression or programme tiling, not a
   fictitious unbounded table. Target ID is NOT allocated by this proposal.
2. ot_hbm_svc_vm_kshare_splitstrap: existing PHY-boundary ownership windows,
   drained before VM fills,64 captured sectors per PC. Ready/CDC are confined
   to the existing HBM boundary. K addresses are stack-local SECTOR indices,
   not byte addresses. PC(s)=s[6:2]^s[11:7]^s[16:12]. Its fixed window request
   formula is {row15,j[2:0],{col4,j[3]},P^col^{row[1:0],j[2:0]},2'b00},
   len4, j0..15. This is a fixed swizzled block; the inverse below selects any linear sector.
3. ot_hbm_svc_vmdel_lane_load_static NPC2: an existing alternative leaf type
   preserves begin/fill ownership/epochs/raw mode and accepts load_v+load_cmd62.
   It faults for unowned/unfilled/stale/illegal requests and never waits.
   It emits load_dest_bank3/load_dest_q2 + native load_dq281. Existing formats
   include FP32/BF16/E4M3/INT8/U32/UE8M0; generic mover's unsupported fmt6 is
   NOT a reason to delete static LOAD's UE8M0 behavior. Binder converter now
   retains all six. Replacing the current raw type changes its interface and
   is a new type/plan event, not reuse of a SIGNED raw view.

Exact existing62-bit LOAD command:
  bit0 landing buffer;16:1 epoch;18:17 source PC group;24:19 PC slot;
  29:25 source byte offset;32:30 format;48:33 VM sector16;
  51:49 first VM word lane;55:52 element count(1..8;0 only release);
  bit56 release landing buffer;59:57 destination bank;61:60 destination quad.
  A noncoalesced/strided source may need multiple commands/response sectors.

VM namespace / static ownership contract:
  HGI VM word w -> sector16={0,w[17:3]}; quad=w[17:16], bank=w[5:3],
  row=w[15:6], word lane=w[2:0]. Mirror uses sector bit15 and requires quad0;
  do not silently use mirror as an aperture or destination quadrant selector.
  Native DQ281={valid,sector16,data256,wordmask8}. Binder's ap0+sector15
  output is compatible with NONMIRROR DQ namespace only. The destination quad
  and bank must receive the packet on their own physical DQ wires.
  In current q0faces WG2, DMA is write slot WG+4=6: matching wslot_v/wslot6
  must arrive with the DQ beat; other write sources at that bank must be idle.
  An unselected active source faults; there is no arbiter or retry.
  Actual face-wrapper and bank pipeline add fixed transport/commit cycles;
  their DQ-done return is not replaced by the converter's3-cycle latency.

Proposal for the minimum closed path:
  Existing F20 install/launch -> fixed calendar -> owned PHY PC window ->
  existing bank/epoch/slot landing -> scheduled decode -> statically selected
  (quad,bank) DQ -> existing VM slot6 -> real DQ-done/status.
  Prefer reuse of proven landing ownership/epoch checking. A new converter
  supplied a bare sector_valid without matching epoch/tag/slot cannot prove
  it decoded the requested response; provider integration must include those
  identities. No runtime on-chip merge between raw and converted DQ modes:
  compiler reserves one producer/mode per bank cycle and illegal overlap faults.

Open physical/compiler choices the die owner must resolve:
- Current selected PHY path reaches stack2 only. Stack3 scratch has no selected
  LOAD/STORE provider. Choosing stack2 instead needs actual VM-read namespace,
  request routing, manifest reservation and target binding; no implicit fix.
- Existing vmks fills a fixed PC-swizzled64-slot block. The exact inverse
  below reaches any linear source sector without data pre-swizzle, at the
  full-window fill cost. A narrow arbitrary-sector mode is an optional cost
  reduction requiring its own contract. Generic FRONT/mover rotating-priority
  picks/credits are not a drop-in static source.
- Existing raw vmdel has no read-data export. Reusing it with the new3-stage
  converter requires a new leaf/interface or the existing load_static leaf;
  estimate lots/pins/clocks and accept one coherent plan event first.
- Backend macro namespaces, F20 target/capacity, full request/capture/decode/
  VM-commit/drain dates, reset release and invalid-command/fault contract.
- Source HGI indexed LOADs: actual a122 has96 dynamic DMA LOAD operands.
  Runtime I-list/stride semantics require a fixed-capacity indexed sequencer;
  known contiguous U32 boundary LOADs alone do not cover the native ISA.

Additional cost caution: NPC2 block_ready requires both64-slot PC payloads in
all8 lanes:1024sectors=32768HBMbytes per quadrant window. It cannot be priced as
one32-byte scalar source read when a command selects one item. Reusing that
fixed-window mode for an arbitrary canonical source address may overfetch and
uses the exact inverse PC/block selector below; charge the real fill bytes. A narrow
new arbitrary-sector PHY window with matching response identity would avoid that
block cost but changes provider/source contracts and needs the die owner's
explicit coherent plan/port/clock estimate before build.

Exact inverse removes the supposed pre-swizzle blocker (qualified analysis):
  Let s be stack-local SECTOR, not byte address.
  row=s>>15; col=(s>>8)&15; PC=hash(s);
  j=(((s>>7)&1)<<3)|((s>>12)&7); slot=4*j+(s&3).
  Landing owner: NW forPC<16, NE otherwise; bank=PC&7; group=(PC>>3)&1.
  Request that native(row,col) window, then read its(group,slot) at the
  selected landing bank, with sourcebyte=original_byte_address&31.
  window_map.py proves131100 inverse cases including every low17-bit PC/
  slot/column/row-low2 combination; high row bits pass through. One complete
  window is2048 unique sectors/64KiB; each landing quadrant is32KiB.
  This is a planner proposal, not selected source coverage or a physical gate.

Routing/target cost to carry into the plan estimate:
  A single command issuer needs load_cmd62+sourcebank3+sourcequad1+valid
  (~67bits), gating exactly one landing leaf per scheduled cycle. The leaf's
  output destinationquad2/bank3 must match its sector16 namespace and reach
  that VM's physical DQ. Existing raw DQ wires are fixed bank/quad, so this
  cannot be adopted by simply adding a converter and leaving routing intact.
  Static source selection/routing may be compiler fixed per crossing; no
  runtime merge/credit/arbitration. Price281-bit neighbour hops and CA landing
  latency, all VM slot6 reservations, PHY completion, macro read and decoder
  latency, and real DQ-done. W89 fill target uses all existing fields; an
  appended LOAD command or new issuer type requires explicit target/interface
  ownership and one coherent plan event. No target ID is guessed here.

Resolved-address command construction (proposal artifact, not installed):
  load_command_plan.py emits exact existing62-bit load commands for an explicitly
  resolved linear LOAD, grouping at most8 consecutive source elements from one
  captured HBM sector into consecutive lanes of one VM sector. Non-unit element
  strides split into count1 commands rather than silently changing addresses.
  Format0/1/2/4/5/6 address reconstruction passes936 elements over12 cases;
  a wrong source-PC landing lane control is caught. Example deliberately retains
  stack3 and reports current_stack2_reachable=false, never relabels its address.
  Actual buffer/epoch are mandatory caller inputs; no dates or target selected.

  Ownership warning: load_static release56 affects only leaves with load_v.
  A fixed window begins/fills all8 landing leaves. Releasing only the final
  read's leaf leaves the others owned and the next broadcast begin faults.
  After all reads, use existing legal release-only(count0,bit56) broadcast to
  all8 leaves for the matching buffer/epoch, or eight scheduled per-leaf
  releases. This control must be included in the full provider calendar.

Actual compact counter / programme capacity follow-up (CODEX):
- Existing MODE1 loops replay literal payloads; only dates advance. RELF adds
  absolute clock bases to low32 payload fields and is not an address counter.
  ROLE1024 similarly repeats literal payloads. Explicit effective227 consumer
  counters are needed; target_capacity.json prices unrolled literals only as
  an upper budget, not a lower bound after legal recurrence compression.
- effective227_contract.json gives adapter-authoritative fields, a real inserted
  LOAD example, ordinary native VM mapping, dynamic-resolution boundary and
  per-step owned-window handoff. No target/date or new ISA is introduced.
- Binder confirms per-step buffer/epoch/owned-row/column ports; the caller
  window controller is still open. Code0 uses full physical row arithmetic;
  code1 explicitly selects row-striped stack with local arithmetic. Every
  request must preserve physical capacity and no-cross-stack-run guards.
- counter_budget.json covers actual3916-record full40-layer N6 MTP VERIFY+head
  source candidate, inserted LOADs only. A single global one-word-per-cycle
