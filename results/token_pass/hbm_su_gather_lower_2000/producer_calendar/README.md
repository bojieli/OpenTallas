# Source receipt calendar composition

The composer loads a hashed JSON authority for every native producer, allocation and control transport. Each receipt must carry status PASS, producer_kind, source_sha256, die_sha256 and clock_epoch_identity. Producer receipts additionally carry first_word, word_count, ready_edge and release_edge. Output allocations carry free_edge and release_edge. Control receipts carry configuration_start, calendar_epoch, launch_to_calendar_zero, ownership_release_tail and the actual endpoint parameters. All dates refer to the same selected stream epoch.

Requests contain the actual descriptor and earliest model issue only after physical producer placements are bound. The checked partial requests here contain logical descriptors because no current source placement/launch receipt is admitted. The builder returns before using them, retains null job dates, and lists the exact missing source authorities. It never uses fixture outputs, injected far ends or a component check edge as a producer date.

IDXSU owns the selected IDX native output and gather endpoint source proof; COLL owns the real GSC producer and four native run commits; chain owns final physical route ages. Their active work has no admitted absolute ready/retention dates yet. The diagnostic graph and source identities are recorded separately from an admitted die binding.

The programme provenance map is TP96: W.even(384,96) assigns four scores to each rank, with 24 rank shards per logical 96-word interval. The selected diagnostic r18d transport/index source uses TP192; no physical rank, Col8 column or group identity is inferred from that logical partition. The composer requires producer_tp from the source control authority and checks every aggregate receipt against its full native shard set (24 four-word shards for TP96 or 48 two-word shards for TP192). A current caller must prove the actual source binding before any dates become usable.

The referenced functional native endpoint profile is kept under functional_endpoint_component in the partial binding. Its local launch offset and ownership tail do not populate the unresolved whole-host binding fields. The main compiler accepts this calendar manifest directly and preserves the candidate status while source authorities remain missing.

Source identities are explicit: binding.source_sha256 identifies the selected banked engine. The hashed control transport receipt carries its own source_sha256 and separately names engine_source_sha256, which must match that binding. This keeps the wrapper/transport source distinct from its engine dependency.

The gather replay also installs finite resident owner-zero calendars on all four native controllers, targets 96/97/98/99, using their actual 187-bit F20 ABI. Only rslot_v/wslot_v are enabled; the directly multiplexed native gather pins bypass the preserved LG-local selectors. One shared launch starts the calendars and six-row gather programme. Each quarter requires eight actual host-launch-to-bank-owner pin ages. Those route-dependent ages remain null. Calendar publication cannot preempt a previous owner or follow the first gather request, and the reported reservation includes the complete finite calendar interval.
