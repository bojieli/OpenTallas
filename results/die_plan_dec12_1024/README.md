## What changed

### S81 (`physical/die_plan/s81/gen_plan_v4.py`, generator-only; outputs regenerated by `run_v4.sh`)
- **Hop and station reach:**
  - `REACH` 1500 -> 405 um, and `die.reach_um` 405.
  - `FT_STATION_MAX` 750 -> 405 um. Station counts keep the 0.98 placement factor, so planned spacing is at most 397 um.
  - `budgets.reach_margin` 1.0 and `ft_station_max_um` 405: the limit is exactly 405, with no 0.9 margin.
  - Lanes are not re-routed: the routes are unchanged and every crossed slot gets more stations.
- **Layer budget:**
  - `die_use` = `[clock_spine, pg]`: `ft_reserved` and the M8/M9 `cut_avail` are gone.
  - The M9 svc fold grant is withdrawn (`FOLD_GRANT` = [] by default). No signal pin or face layer is on M8/M9.
  - M3 was tried as the third vertical layer and rejected: the M3 tracks (offset 9 nm, pitch 36 nm) are not mirror-symmetric on a 1442.88-um type, which gave 54 abutment errors.
- **svc fold rung (S81 parent ruling, option A refined):** without M9 the fold faces were at 6.24-6.47 pins/um.
  - The score-gather sub-bus `{go_d, go_v}` (2133 b each way) leaves the full-width `attn` lane. It moves to a 2-beat lane `attnh__svc_a__svc_b` (bus `attnh_o0` / `attnh_i0`, 1068 b).
  - Fold load is now 4.77 pins/um on pairs 1-3 and 5.00 on pair 7 (budget 6, target <= 5.5).
  - The dn stream (high duty) and scatter / P.V / up stay full width.
  - Selection: `S81_FOLD_2BEAT=gi` (default). Scatter alone (`si`) was tried and leaves pair 7 at 5.73.
  - **Pending:** TOK-DS confirmation that gather duty is <= 50%.
- **Reset:** `reset.release` = `wavefront` (decision 13). `reset_tree.py offsets`: root `s_4S_L3`, max release 100 clocks, max die hop 378 um, 0 unreachable, 0 long hops.
- **Type names:**
  - The generator now also keeps a type's reference name when its instances are exactly one reference type's instances (`instance_map.json` `type_of`).
  - Result: 0 renamed, 180/180 names kept.

### Beat format (contract for S81/H23, every fold pair, both directions)

Lane `attnh__svc_A__svc_B`, port width 1068 = `{beat, payload[1066:0]}`.

| item | value |
|---|---|
| word (2133 b) | `{go_d[2131:0], go_v}`, so `go_v` = `word[0]` |
| beat 0 (beat = 0) | `payload = word[1066:0]` |
| beat 1 (beat = 1, next cycle) | `payload[1065:0] = word[2132:1067]`; `payload[1066]` = 0 in beat 1 only |
| word cycles | lane `cycles` (2) + 1 = 3 (`LAT_ATTNH_..._WORD` in `lat/s81_lat_pkg.sv`) |
| rate | at most 1 gather word per 2 cycles per fold direction (compiler spaces back-to-back gather words) |

## Open item: hard-core rst pins (RESET API)

`core_rst_reach.json`: 3276 hard-core rst pins. 128 of them are more than 405 um (worst 640 um) from the nearest clock tap, which is where the wavefront tree ends. All 128 are the `ot_s81c_attn_hcore` cores in the svc types (8 per svc).

`reset_tree.py` targets clock taps and `rst_o` only. Neither `reset.tap_um` nor `reset.depth` (hard partitions) can name a core's rst pin inside a soft type. This needs a RESET tool change: relay targets at hard-core rst pins from the pin tables.
