## Exact address adapter contract

For the retained r17 global byte address `B`:

```
stack2 = (B // 128) % 4
local_byte = (B // 512) * 128 + B % 128
local_sector34 = local_byte // 32
byte_in_sector5 = local_byte % 32
system_sector34 = B // 32
local_PC5 = ((local_sector34 >> 2) ^
             (local_sector34 >> 7) ^ (local_sector34 >> 12)) & 31
physical_PC7 = 32 * stack2 + local_PC5
B = (local_byte // 128) * 512 + stack2 * 128 + local_byte % 128
```

This is executed from the archived source function, not a new address policy. The source's local-sector aperture is31bits, carried losslessly in R14's34-bit field. Source rank/die is1bit in this provider binding; it does not establish TP4 or DS addressing.

At `B=32`: system sector1, legacy low7 PC1; actual local sector1/hashPC0. Replacing low address bits by the desired PC changes sector/payload ownership. The proposed adapter preserves B/system sector/byte mask, emits explicit physical_PC7 and stack/local-sector, and validates those against the hash. W2's additive wrapper must validate the explicit translated PC, replacing the low7 guard only in the connected opt-in route. Existing address semantics are not silently reinterpreted.

An aligned128B stripe has four local sectors with one hashed PC. Split a larger transfer at stack-stripe and hash-run boundaries before presenting PC-scoped W2 transactions. A full aligned512B RF frame has16sectors, four stripes, and four actual stack destinations. This is a deterministic source-address subdivision, not a claim of parallel physical service. Child logical tags must be preserved/allocated uniquely with a pre-bound parent reference; a single tag cannot be overwritten with a beat or PC to manufacture uniqueness. Repeated opaque tags in the same producer generation require proven previous-copy drain before reuse, or a separately bound distinct child tag. The actual caller allocator/schedule is still missing.

## Proposed endpoint ABI for integration

These widths freeze a **lossless model-stage ABI**, not an installed port claim. Valid/ready fields and direction/credit controls must be included in control costs, even where counted separately from payloads.

- Parent descriptor reference32 is a live directory handle, not a hash/truncation of software owner64 or generation64. Its row retains native identity, actual versions/home/reader leases, bound physical rank/SM, parent capture55, expected sector/mask/format and release state. Directory capacity, full row size, ownership and read/update ports require Popper/Dewey integration; no free private store is asserted.
- Source-meta92 = child full owner46 + requester_SM5 + RF_slot9 + parent_reference32. Child owner contains the **actual child PC** and original child tag32/gen4/client3. Parent55 is fetched from the pre-bound parent row; its anchor PC and original tag are stable across children. Child→parent field agreement is checked; RF owner is never the last returning child. Metadata echoes unchanged. Direction/LEN/beat remain explicit in the enclosing source packet.
- W2 scoped physical request/return tag39 contains client3/original32/sourcegen4. Across a shared boundary append actual PC7. Existing wrapper PTAG35 is unchanged history; no module already has39 merely because this ABI proposes it.
- R14 acceptance must expose an explicit atomic receipt `(accepted_valid, allocated_tag12, backend_gen4)` on the actual request acceptance edge. The stage testbench currently observes `.provider.on.next_tag` hierarchically; that is not an endpoint. Reserve both old context and metadata capacity before `req_r` can accept.
- Provider request455 + meta92 =547raw. Returned owned465 + meta92 + backendgen4 =561raw. Command339 with full16 rather than12 tag =343raw. Queued and returned structures already have tag16, but their consumers and commands must stop discarding high4 bits. Existing fixture hardcodes upper4zero and is not proof of this new token.
- Store meta92 + backendgen4 as96 private bits alongside the **same existing PC/context index**. A source-macro realization is one additional128x256 1R1W RAM per existing PC context bank:32 per stack/128 per four-stack die, with the original CAM controlling both parallel reads. This is a sizing input, not selection/placement or a second CAM. The allocation/capture path, RAM SS timing/protection, write fanout, full-bank read mux and retention through reverse must be priced. If Popper binds equivalent reserved directory storage, subtract only demonstrably replaced resources; never double-count or assume it is free.
- Source read completion means captured data from the actual accepted backend request. Write completion means the actual backing-visible commit, not merely accepted command or the legacy write-done pulse. Nash's reserved entry captures a backend pulse and holds client completion until ready; no backend write-ready is necessary if acceptance already reserves that exact slot. The fixture's write+8 commit is fixture causality, not actual PHY visibility qualification.
- RF4096 assembly uses exactly the bound16sector frame mask or a source-valid preserved read/modify/write frame. No zero-filling of a64B C0 fragment or32B KV sector as a complete512B RF write. KV bytes may require the source codec/exact arithmetic before FP32 RF deposition; transport is not permission to reinterpret FP8 as FP32. Shared64B destinations use actual shared endpoint/home semantics, not RFslot9. This RF-only cost input does not silently cover shared10 addressing.

## Canonical table decision and lifetime

**Current W2 is not on the R14 finite-stage route.** The proposed connected baseline puts W2 exact logical ownership on that route; Popper must include its receiver match/hold latency, not price it as an unconnected side table. R14's existing owner is the physical allocation/address restoration authority. It cannot replace the full logical completion table as-is: it has no full client32/sourcegen, retires before RF/consumer/reverse, discards backend high4 and serializes via one saved return state. Use the same R14 CAM index for extra metadata; do not replicate its4096-tag CAM just to echo logical identity.

A future physically shared canonical table is not admitted by this inventory. Proving shared capacity, both logical and backend keys, exact lookup/update ports and the complete lifetime would permit a composed replacement debit; today's model may not take that saving. W5 parent/version leases are separate semantics, not duplicate physical-tag matching. Preserve source12CORE read latency, source7CORE return arbitration and actual one command bus/stack; no free128-PC throughput comes from the number of context RAM banks. Nash's user-relayed read2/write3 client-edge floors (not measured by this inventory) remain analytical minimums until clock/physical proof; do not add them twice if already in Popper's path ledger.

Backend physical tags and associated context/sidecar rows must remain quarantined through W2 held completion, complete RF commonACK, visibility, actual consumer/reader ACK, child reverse, parent release and both-direction CDC drain. Source tagowner's early `ore` retirement must be replaced/held for this connected route; keeping a sidecar alone does not prevent old physical-tag reuse. Allocation+retirement on one edge needs joint atomic live accounting. Duplicate/wrong-direction/wrong-generation/stale responses or reverse messages latch fault and cannot grant or return credit.

Neither source gen4 nor backend gen4 is a universal ABA proof. Reuse/wrap/reset requires a source-owned all-copies predicate covering provider pending reads/writes, ingress/PC/return queues, owner held/inflight, W2 accepted/reserved/held entries, RF copies/commonACK, consumers/reader debt, child/parent reverse and both endpoints of every forward/return/reverse CDC. Stop new admission before collecting the predicate; a local FIFO-empty snapshot or reset-to-zero does not establish it. Before wrap, prove no old response can subsequently arrive; otherwise refuse reuse. Price any resulting wait in the continuous1737/2213 program stream. No1bit generation, no finite fixture-size cap presented as a full design, and no fresh external identity silently selected.
