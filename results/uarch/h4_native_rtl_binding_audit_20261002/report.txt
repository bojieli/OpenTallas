Scope: Qwen 1,737 PCs/21 families and DeepSeek 2,213 PCs/30 families.
This audit consumes immutable Git objects, not loose main-checkout sources.
It adds evidence and software extraction only. No engine RTL, P&R, experiment,

Finding
All 3,950 PCs have executable native software bindings. None of the 51 families
has a complete corresponding H1 hardware command/control path demonstrated by
these sources. This is a composition gap, not a claim that every arithmetic
unit is absent. H1 is a finite one-SM matrix -> captured RF -> dependent ADD ->
consumer visibility test. It does not decode or execute either full native
program, implement32SM/rank, or join2Qwen/96DeepSeek ranks into a token.

H1 has real ot_gpu_sm_q/ot_gpu_sm_v matrix bodies, mirrored RF macros, a128-lane
ADD/MUL service,64KiB scratch and an RF visibility fence. The bench binds
simd_mul=0: ADD is exercised, MUL is available in RTL but unexercised here.
Qwen's row-scale multiplier exists but op_scale/sw_en=0. DeepSeek contains
BF16/FP4/FP8 datapaths but H1 op_fmt=0 and op_gs=0. These ties matter; existence
of a module cannot stand in for the required family/shape/configuration gate.
H1's matrix issue controller is a row/group sequencer, not native-PC dispatch.
The matrix capture adapter is test/audit register storage, not a hardened macro.
The source itself labels the top an executable finite source-join audit.

CPU versus RTL boundary
Qwen TiledMachine.execute invokes NativePrimitiveVM.primitive with NumPy typed
arrays and source-specific leaf recipes. DeepSeek execute_bound_ds_operation
binds templates/provider views and executes bounded native software primitives.
A complete primitive program without golden macro callbacks remains CPU
execution. LOAD/TAKE/SCATTER, PACKET_COMMIT, ASSERT and view operations must
receive real hardware addressing, completion and visibility bindings. They do
not become a controller, network or persistent KV fence by being software ops.
QKV_SPLIT has no arithmetic command: hardware view/version binding remains.
KV_FENCE has no arithmetic command: hardware publication/retirement remains.

Concrete binding discrepancies
1. RF is512 vectors *128 lanes *32bits =256KiB logical, two physical mirrors
   =512KiB. Its service holds the whole transaction through mirrored write ACK.
   Native32-vector workspace is a software allocation, not a new RF port.
2. Native Qwen calendar advertises128B shared beats; actual scratch port is
   512bits/64B. Reprice shared transactions. Matrix weight ingest128B is a
   separate port and must not be conflated with scratch bandwidth.
3. Unified DS model stack_levels=3/group_slot=True; actual H1 LEV=4/op_gs=0.
   Reconcile one exact admitted config before attaching model latency claims.
4. Matrices expose row results of16FP32 lanes(Qwen) or8(DS), not complete native
   typed/versioned operands. H1 packs fragments in host tasks; full shapes,
   rounding, compressed format and row-scale adapters remain to be connected.
5. H1 fixture uses host-generated weight responses and a functional10ns clock.
   It does not establish actual checkpoint/protocol/PHY or SS/FF timing credit.

Remaining implementation work, before a connected token
C0: Native-PC/micro-op sequencer, finite operand/home allocator, version and
    dependency scoreboard, predicates and selected-EID control. All51 families
    need this common bridge. Preserve acceptance vs completion dependencies.
V1: Integer/logic/shift, comparisons/select, signed/I64 paired-word semantics,
    conversion and FP8/ldexp opcode endpoints. Matrix-specific unpack hardware
    is not a general RF vector primitive endpoint.
R1: General golden-ordered reductions, scalar broadcast, argmax tie-breaking
    and top-k. Matrix accumulator trees cannot be assumed interchangeable with
    norm/softmax/chunk8 trees or padding. Price streaming reduction and broadcast.
S1: Source-exact exp, reciprocal, rsqrt, DIV/SQRT chains. Qwen reciprocal seed
    0x7ef311c7 and separately rounded Newton steps are source contracts. DS
    approximate DIV is not interchangeable with an IEEE divider. RSTD mean is
    multiplied by source1/4096; changing it to DIV changes the contract.
M1: Typed RF/shared/provider addressing, gather/scatter and layout/view commands,
    finite spill, matrix fragments and exact64B scratch transactions. Reuse the
    current provider owners; this audit creates no alternative provider stream.
T1: Matrix descriptors for every full shape, long-K/row loop and compressed
    format; enabled row scales; RF-visible outputs with proper version/address
    and consumer rounding. Model-price storage replacing audit capture.
N1:32SM/rank and distributed collectives, persistent KV/state fences, finite
    common-fabric credits, exact-once retirement and validated reverse grants.
G1: Compose actual checkpoint and complete programs through these RTL paths;
    then representative layers, full-rank token/state, contention/reset and
    same-source SS setup/FF hold in actual context. Directed H1 does not pass G1.

Per-family work assignment is in family_summary.tsv. family_bindings.json.gz
contains every PC, native primitive set, operand shapes, template/rank/buffer
configuration, original exact home references and actual H1 module/entry/config
bindings. DeepSeek template code shapes are logical source shapes, not a claim
that RTL materializes full tensors; the bounded forward-dispatch reference and
existing forward primitive scalar counts retain that distinction. Empty ranks
are explicit empty extents, never fabricated opcode callbacks.

Dewey coordination and useful software parallelism
Dewey_handoff.json joins the existing DS/Qwen calendars by model, family, PC,
program hash and template/ordered primitive sequence. No replacement calendar
was generated. Missing costs remain positive provisional inputs, never zero
or measured hardware credit. C0 owns the single command/version interface.
V1/R1/S1/M1/T1 ABI, shape and contract checks can proceed independently in
local software against that interface; Dewey composes the one finite resource
calendar and joins current provider owners for N1. This is a prepared handoff;
no acknowledgement or downstream integration by Dewey is claimed.

Validation
All PCs occur exactly once; counts match21/30 families; all shapes and native
rank/buffer templates resolve. All 90 H1 RTL digest checks match the committed prepared
manifests for Qwen r10/r11 and the DS r8 path. Module capability and exercised
configuration are recorded separately. Source/hash and replay receipts are
additive. CPU timing and native calendar counts do not qualify hardware.

Compilation closure distinction: hardware_inventory.json retains every prepared RTL
file and simulation SRAM model. Uninstantiated SFU modules in a compiled file
are not H1 opcode paths; behavioral memory models do not provide SS/FF evidence.
