# HHP four-SRAM dataflow placement PREP

This closes the missing concrete SRAM-site proposal. It is not a generated macro kit, a head hardview, a source/date adoption or a CAD release.

The selected actual HHP source has four real128x256 SRAMs,94.824x41.064um. The selected native R2C wrapper preserves payload[255:0]. The inner group reverses source lane names and then concatenates them in reverse, so SRAM bankq really receives PCq. The bound parent already has D1/D3/D1/D5 305-bit data delays. Landing_pc already has ad_q and out_data FFs, and its branch already has hop295 before rowctl rsp and the parent BOUTs. No extra FF or data edge is proposed.

Actual r27c BASE o_grp[255:0] pins are on S. Genuine HEAD uses its separate planned r25 N-face pins; no BASE LEF is used for it. Proposed SRAM R0 origins: bank0(138.240,600.012), bank1(544.320,600.012), bank2(544.320,873.612), bank3(397.440,873.612). All four clear every PC lot,126 actual clock-driver reservations and eight unchanged fixed relays, including conservative4.32um halos. Signal pin centres sit on the actual parent M4 .024+.048k grid. The old soft-lot SRAM Y origins would miss it by12nm; they also cannot remain inside hardened PC footprints.

The drawn paths are candidate soft guides for EXISTING state, not placed FFs or routed wires. The largest screened stage path is390.636um versus405, and candidate BOUT pin distances are123.212/97.084um versus150. SRAM clock pins are at most196.508um from a real existing entry tap versus220. These are geometry screens, not RC timing, routed congestion, pin-access, clock-tree or PDN qualification. Native placement may need to revise guides. Initial D3 point(518.4,380.16) intersected a driver reservation; the preserved failure led to a corrected(524.88,380.16) guide centre. No fixed source relay moved.
