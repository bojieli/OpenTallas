## Programme allocation is a required source proof

F16's standalone loader interprets PW0 as restart and PW400..438 as39 padded transfer words for13×134=1742 actual bits (hard2048-bit cap). It then waits for genuine all-copy authorization and matching profile/digest/epoch. These addresses are a synthetic ABI, not a demonstrated reservation in the production programme.

Frozen `0d4c` CTLM instantiates the legacy `qfd_dv_cmd_cal_mu`; it has **no CALENDAR_ROM parameter**. Its descriptor is CALD, commands use two PW words each below976, and `params.json` selects NU4/OPSEG1/STAGE_ME1/XPF21 only. A *hypothetical*406-command CALD image necessarily occupies PW400..438: base+812<=976 implies base<=164 and the last word>=811. This arithmetic is a compatibility counterexample, **not a claim that current CALR ROM commands occupy these PW addresses**. Historical CALD base480 capacity248 remains unchanged.

`7e5150af5` CALR capacity249/390/1023 and archived390-command real ROM transport are separate source proofs. Current406 decode commands/1009 total capsule entries are also separate from the frozen GEN; their two-ROM command body does not automatically consume two PW words per command. Neither receipt supplies an exact source-pinned current CALR descriptor, template word allocation, and actual CTLM/SYSFACE binding together. A production compiler map must prove PW400..438 unused or assign a real dedicated39-word boot stream and bind its exact1742 payload to the installed programme identity.
