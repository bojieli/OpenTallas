## Compact-carry transition to prove before implementation

Let `f=total mod8`, `b0=floor(total/8) mod8`, incoming count `n in[0,64]`, completed flits `nf=floor((f+n)/8)`, and `fnew=(f+n) mod8`. Existing rotated data maps incoming record j to slot `(total+j) mod64`. The old-ring data is used ONLY when physical bank equals b0 and slot q<f; all other write-word records come from the current rotated beat. Thus the proposed invariant is that seven compact entries equal existing ring slots `(8*b0+q)` for q<f. Unused entries remain arbitrary and must never be observed.

For each completed bank b, preserve existing write enable/address and choose compact[q] iff b==b0 and q<f, otherwise current rotated slot b*8+q. At the SAME S5 state edge compute next bank `bnew=(b0+nf) mod8`. For each q<fnew, select prior compact[q] only if nf==0 and q<f; otherwise select current rotated slot bnew*8+q. With nf==8, bnew==b0 but the new partial contents must come from the NEW rotated tail, never prior compact. With n==0, nf==0 and valid compact entries retain their values. With fnew==0, all retained contents are semantically dead.

This derivation is a candidate state invariant, NOT an executed proof. It must be checked against exact production RTL under64-record/71-pack wrap, zero-count and full-flush beats, clear/reset with in-flight data, all legal command interleavings, every SRAM write address/data/enable, and exact emit/fault/count ages. The <=7-record storage only removes the cyclic2304-bit retained bank; fixed computational pipeline registers remain and their fanout/depth are separate problems. Bank/slot mux controls still need bounded source provenance and actual mapped census.
