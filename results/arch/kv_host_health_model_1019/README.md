## Exact selected interfaces and ownership

An ordinary two-FF synchronizer cannot qualify a one-cycle event from another clock.

Existing consumer interface: service `raw_faults[24:0]` enters `fm`, `fs`, sticky/bad after three logical core edges; protocol input is captured then retained. Physical and transport each have eight summary bits, sampled as `pf_q`/`tf_q` and routed diagnostically. They are absent from bad/abort/guarded-TK/ready. These are 42 existing input lanes, not 42 distinct primitive faults. They overlap the source inventory and must not be added to the minimum357 KV/DCAL count as unique sources. DCAL source `a1c24018d`, evidence `103049e43`, preserves its own exact predicate and qualification obligations; neither readiness nor certificates become error bits here.

Proposed ownership is per producer: retain every event in a monotone source-domain sticky bit before crossing. Reuse an existing proved sticky register when available; add a source register for pulse-only predicates. Preserve each bit through a priced landed/clock-crossing path until reset recovery clears it. With independent sticky bits, arrival order can differ without losing an event; a coherent multi-bit cause transaction requires a separately proved bridge. Guard/core continuously ORs retained health. Neither START, STATUS, a functional cutoff, CSR acknowledgement nor a service BEGIN clears health. Every source needs a pinned clock/reset/clear table before this proposal can instantiate that path. Unknown producers are refused.

## Proposed fixed machine contract

Keep all active data movement and scheduled operation/drain edges unchanged after a fault. Register health into both (a) engine fixed STATUS formation and (b) host terminal retirement. Actual selected-source ports for the new engine path and transport reservations do not exist in this packet; their source-to-pin binding is required before RTL. Gating admission or tainting an occasional DONE alone does not repair the terminal path.

Retain the exact existing client/slot/generation/position identity in each terminal record. Propose four cause bits (service, physical, transport, protocol), bad bit and three-bit code, registered together with identity. Zero code means healthy; priority is missing/identity=5, protocol=4, physical=2, transport=3, service=1. Cause bitmap retains concurrent causes even when the code selects one. This is a proposed new contract, not an interpretation of an existing STATUS encoding. The real STATUS/codec owner must bind code and reserved bits explicitly.

For every operation, source-owned nominal/late/missing deadline must precede fixed STATUS by the complete source capture + bridge + join + AFR + TX/LAND + consumer latency, including worst permitted phase. Missing reports become retained faults on their fixed deadlines. Faults observed at or before either terminal decision edge veto healthy completion on that edge, including same-edge next-health evaluation; dataflow continues its static schedule. Health arriving between a healthy engine STATUS and host retirement vetoes healthy host retirement. After an already published terminal, no retroactive rewrite is possible; later observed health blocks future admission and all subsequent healthy completions, conservatively including overlapping users. This is continuous observation, with no per-request health snapshot or cutoff mask.

A healthy terminal can certify only the priced fault-observation envelope. Faults after a work-complete cutoff remain continuously observed and can conservatively invalidate later work. The cutoff itself must cover every operation's failure/late/missing/drain path; this packet supplies none of those actual deadlines. A fault with DONE low must still taint the fixed terminal; waiting for matching DONE or cancellation does not provide this bound. Recovery is a fixed, separately priced admission interval after genuine producer clears and real pending-path drain, with source/reset/identity lifetime proof. No conditional wait, invented skew64, depth273 adoption, or increase of HOLD128/IGNORE255 is proposed.

## Separate MU interface/lifetime gap

Actual `qkd_host_control_packet_admission` has no MU parameter and its prompt instantiation does not override MU. Prompt defaults MU0 and passes it to fullcontrol. Fullcontrol selects NSLOT1/PLB13; the host uses ENG_CTX=NSLOT, MU_OUT=MU, MODE0, while ctl_service passes MU0 into qkd_host_ctl and package controller. Its actual watchdog and current-generation DONE behavior must retain that attribution. The alternate MU path selects NSLOT4/PLB11, host outstanding accounting, address/slot mapping and different package generation/drain semantics. Enabling it is a separate end-to-end interface and lifetime change: carry MU through every caller/profile, verify genuine four-context prompt/KV/request identity/storage lifetimes and held-generation wrap, and prove four outstanding fixed retirement/drain/admission paths. A parameter flip cannot establish these properties. This packet leaves MU0 unchanged.
