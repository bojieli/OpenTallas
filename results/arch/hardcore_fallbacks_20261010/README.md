# Hard-element fallbacks and structural redesigns, 2026-10-10 (hardcore-1010)

This file answers the owner's 2026-10-10 request. It covers the 19 genuinely hard open elements in OPEN_ELEMENTS_20261010.md, each confirmed against the element registry at 8765/api/elements. For each element it gives:
- the root cause of the failure;
- a guaranteed-closure **fallback**, in the style of BF's HALF_PHL: slower or larger, but structurally safe;
- the cost of that fallback, in tok/s and area;
- a **structural redesign** built on established accelerator practice.

Each fallback runs as a dual-track `-cl` line (job names contain `fb`), alongside the owning stream's main line. Whichever line closes first, with an exact bench and a mutant, wins.

The owner's rules apply to every line:
- cycles and area are not strict;
- no masking;
- die count is not scarce;
- exactness is at the transaction level.

- **tu_retry_phy_port.** FB is a bench-exact protocol change on the error path only:
  - in a rewind cycle the fresh flit is now sent, and the replay resends it; the receiver drops the duplicate under go-back-N.
  - OT_TU_FB_COVER showed the new case happens once in the positive bench (seq 17). Default-off RTL is merged to main.
  - The DFREE mutant of the iqs6 spec does not apply under FB (the tx is replaced by ot_hbm_tu_link_tx_k), so it is not in the fb jobs.
  - If the routes still miss, the next step is a 2-stage ack classification with base forwarding (the structural redesign).
- **ha2 rx_s.** The flop queue costs power and area against the SRAM queue, but it is closed and on main (4a12f4d5d is an ancestor of main). hbm-phys keeps the cplh line as the main line. The registry should fold rx_s into the rx_phys closure if cplh fails.

- **hcoll_port.** OWNER/COORDINATOR DECISION NEEDED: the fallback drops the port's payload SECDED. That is allowed under the 10-10 academic SRAM ECC policy only if this ECC is SRAM ECC, but drive-1010 classed it as link ECC at 08:07.
  - Open check: the existing ECC run_port.sh bench exited rc=127 on EPYC1 and was not rerun. It needs a clean run before 7ea0839ae is merged (the FB change also touched the ECC head wiring).
