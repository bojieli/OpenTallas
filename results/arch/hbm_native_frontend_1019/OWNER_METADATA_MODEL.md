# Owner retained-metadata component

This next source component implements the real owner immutable47-bit record: generation12, epoch16, block bank2, permutation1, row-low2, ordinal11, length3. It is32x47=1504bits. Existing mutable valid32/seen128 remain separate owner state, not hidden in the table. The helper alone does not replace or qualify an owner.

Four <=12-bit field regions each split into two16-row halves. Each half retains native address/data capture FFs, registered16-way onehot read/write decodes, read-half Q, local reset landing and local write-valid copies. Runtime words are unreset and protected by reset-cleared write qualifiers; owner valid/generation protect read legality. Maximum modeled dataQ load16, local onehot load12, write-valid16, decode-address16; synthesis must measure all actual roots. Addresses and enables are not shared across eight halves.

Writes: H0 capture address/data/valid, H1 decode, H2 real data-array write. Reads: H0 address/valid capture, H1 local decode, H2 half-data Q, H3 combined output Q. A same-slot read/write at H2 is read-first; owner must forbid allocation/return collision. Read output-valid follows an indexed four-slot phase ring and reset cancels occupied operations. All local reset branches release in two edges from a raw fanout-two first stage; actual clear/D sinks remain a mapped obligation.

This conservative safe decomposition adds another two return edges relative to the earlier fused lookup proposal: native return capture, retained local decode/read/merge, validation Q, two link edges reach H6 pair (six additional HBM edges relative to old direct capture).
