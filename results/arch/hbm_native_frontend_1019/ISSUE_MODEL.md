# Native request issue bridge

Four-slot51-bit ring holds real K addr30/len4/tag17 requests. Source admission is the existing owner ready/valid interface, not a new die credit protocol. Input data/valid and historical source-ready capture unconditionally on first Q; the following edge stores the exact accepted request. Ready deasserts when registered next occupancy reaches3, reserving one of4slots for the already admitted capture stage. This avoids duplicated acceptance or over-admission caused by registering ready without finite pending capacity.

External K-valid is a single-edge registered pulse. It is followed by one confirmation edge; first-Q K-ready and historical K-valid identify exactly whether the receiver accepted that pulse. An unaccepted request remains resident and retries only after confirmation. All request fields come from output Q and remain coherent; private per6-bit-slice ready/pulse/inputvalid state and pointer copies keep terminal loads<=32. Nine slices own independent four-slot data arrays, not payload shifts. Actual mapped retained FFs/reset loads remain required.

Source accept H0 -> ring write H1 -> K pulse Q H2 -> PHY acceptance H3 (minimum +3HBM). Steady issue II2 when ready; up to4pending requests and variable PHY wait remain explicit. Full4beat requests require at most1command/4HBMedges for a32B/HBM-edge return port, so II2 does not cap that sustained burst rate. Tail/small blocks and whole block queued-drain (up to8HBMedges plus PHY waits) require real production shape repricing; no free overlap or prefetchtotal is adopted. The actual source receiver must accept events precisely on Kvalid&&Kready; no AXI-style persistent-valid assumption is made. A different receiver contract blocks adoption.

Storage:204 persistent pending bits,51 native input FF and51 outputFF,9local pointer/control groups (at least72FF),9second reset+2first resetFF and controller occupancy/history/readiness/stop/fault FFs. No array>2kb. Model only; clocks, <=405um reach, measured area and native sink matching remain OPEN. This bridge does not fix canonical issuer/cohort, descriptor capacity or TOPK collector controls; those remain owned work.
