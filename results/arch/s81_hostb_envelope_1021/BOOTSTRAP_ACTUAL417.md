Authority/source and clock route

The actual off-chip HOST producer supplies the separate HBC1 configuration header/raw-body pair through the exact8916 HSF0 HFWD producer. Configuration must arrive at compiled local-reset-clock bootstrap slots, with independently bound stage/rank straps. Those slots are build inputs tied to actual clock/reset/source identities, not values learned from the first data header. Shadow fields load from the configuration body; a separately booked explicit COMMIT enables the context and the affine data schedule only after exact sequence/CRC/range/idle checks. A local epoch seed is supplied as an actual timestamp at configuration-body capture, following the existing KS6 CSR0x19 semantics. Its production value is still unmeasured; no zero epoch or runtime vector is emitted here. Full512 CSR0x19/0x17 must remain intact through HOST_WORD; inline ARM still does not replace them.

Source route is actual HEAD HFWD -> selected s0N endpoint receive in ck_K -> HBE interception before the current K->S landing/slice stop -> either explicit NEXT forwarding or local host-region transport -> actual seqhost clock root5. Return uses explicit PREV. The current endpoint lacks a host PREV selector: its pairB is solely the MU XB/XQ window and user0 is copyA. A separately named opt-in per-beat PREV selector, carried with the current IN_PIPE edge and all actual TX cohort predicates, is required; raw body magic must never infer direction. Current G9 and current LEP views remain unchanged/unaliased.

The multi-millimetre s0N-to-seqhost route needs a concrete existing typed on-die path or a priced relay corridor. The earlier one-edge fixture landing is not adopted for that distance. Exact topological packing, clock-domain landing ages, physical reach and compiler dates remain blockers. No source implementation, runtime, native storage gate or physical candidate is launched by this proposal.
