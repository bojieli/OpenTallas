# Private retained scheduler component

The clone preserves the pinned original file and keeps ENABLE_RETAINED_COMMIT=0 by default. Opt-in mode accepts only the selected scalar SU and contract type COMPONENT=1; all production calendar fields remain NULL. The attached H12/deadline8 fixture is an explicit conditional environment, not a production-complete Boolean. Each launch owns one pending snapshot and reservation until fixed H; no subsequent launch can consume speculative rawdone state before H. Original rawdone inflight and source sl_* updates remain unconditional. A missing deadline response poisons while its real engine response remains owned and must later drain.

All original sequential scheduler/observer processes use raw POR in retained mode. Startup warm/lock observations poison only after ever-armed or real retained ownership. Observed health/restart/role/DMA errors fail-stop; no warm clear or software recovery exists. The committed CSR mirror changes at prompt certification or generated CQ word0 offer. The CQ event, lineage, address and phase are snapshotted before word1; a fault uses bad_next at the actual word0 offer. Independent AW and W VALID/data retention and real B/MSI cleanup continue while bad. The observer reports the actual offered status at original B/pop, never grants authorization.

Per-owner failure bitmap/report-once state permits one fault report. A first mutable queued event may carry that report; otherwise finite queue space receives a real fault entry. Once the report is offered, later immutable queued entries remain owned and retained until raw POR. They are neither overwritten nor emitted as success. Healthy context release requires explicit modeled owner_drained and empty real pending, event, DMA and report obligations after MSI; poisoned contexts never release. This conservative retention policy does not promise recovery throughput.

The declared additional state at NW18/H12/EVQ4 is 1563 bits, including 992 lineage bits in the event table. The full indexed table is 2864 bits and remains functional-component storage only: physical SRAM mapping/read/collision/clock/PG closure is HOLD. The complete original state and its real clock/reset/copy costs remain additional obligations. Absolute H/R, production SU/MU performance, cache poison transport and PHY/bridge whole-root retention remain unqualified.

Selected retained SU additionally fixes its round-robin candidate to slot0. The original SB1 round-robin increment may otherwise index slot1 after terminal own_v clears; default-off equations remain untouched. Healthy multi-request reuse needs the actual explicit owner-drain contract.

Retained c_tokens/c_reqs count only success word0 offers with a successful real B response (c_reqs additionally requires actual non-token terminal kind). A generated snapshot converted to ST_FAULT/EV_ERROR never increments success counters. The committed mirror still linearizes at offer and cannot roll back after B error; these counters diagnose response confirmation and do not authorize context release. Default-off counter equations remain unchanged.

Identity is typed HOST_DESCRIPTOR_COMPONENT: the59-bit owner field zero-extends the accepted descriptor client tag16. It is not native TAG59{epoch16,stage6,token18,position13,segment6}. No source-legal mapping between this fixture domain and accepted native identity has been proved. The80-bit comparison tests the private conditional mechanism only; actual native identity/health binding remains OPEN. Generation/slot/position are independently reconstructed by the bench, not copied from the DUT identity observer.

The actual I_GO issue_fire rechecks ev_n+pending_v<EQD-2 at the launch edge, in addition to the original I_IDLE selection guard. This prevents descriptor-error insertion during the read/issue pipeline from bypassing the reserved-event margin. A canceled unissued I_GO returns idle without an engine pulse or pending reservation. In the selected scalar vehicle pending_v is the exact one-step reserved_pending count.

D_ERR distinguishes temporary pending-step admission stalls from actual bad/poison. Accepted descriptor errors hold until their real dp_ok queue insertion; a simultaneous certified engine event cannot drop them. A healthy valid descriptor holds while its pending cut is outstanding. Actual bad/poison converts an otherwise valid accepted descriptor to a queued fault response instead of installing it. Healthy validation errors retain their original status. A descriptor error carrying a different client tag cannot consume the active owner's one fault report.

This distinguishes owner ep_v engine/failure records from dp_v descriptor errors even when clientTAG16 aliases.
