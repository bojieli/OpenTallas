## What the actual source supports

The existing PPATH=True path already consumes SE writes internally: `dsdv_svc_rs.pb_w` takes the SE full-mask rows, rounds each FP32 element to BF16, writes pbuf, injects P beats into the score exchange, and produces the fold-root PV frame. The old generic statement that all SE writes have no consumer is superseded for this profile. The external555-bit write face remains live, and SO has no installed consumer.

Each P.V quarter supplies160 records:32 headers and128 data columns, each with16 FP32 heads. Four quarters supply512 dimension columns,8192 FP32 values/262144 payload bits; three remote quarters alone require480 records/196608 payload bits, before physical framing and retries. The actual column identity is `d=32*tile+8*(wi-1)+pv_c`. Preserving this identity is mandatory; arrival index alone cannot replace `pv_c` until it is proven against the actual engine stream.

Existing SMJ type9 supports a start/kind/jid, parameter/operand selector, and16-bit per-head operand mask. A conditional serializer can announce SO kind5 once, send five parameter rows, then16 operand frames of32 rows each, mask1<<head. The32 rows contain16 FP32 values apiece in dimension order. This is534 q words:6 parameter words plus16*(header+32). First-to-last span is533 edges at the existing q-pin II1. If the upstream NP4 uniform transport is reused, span is2132 edges/2133 occupied edges, before actual assembler macro reads, routing, phase alignment and downstream SO latency. These are conditional transport bounds, not a token price.

SO retains the previous SE denominator in each divide lane. Do not issue a new SE, reset, change request epoch, or reuse a head while this dependency is live. SO parameter rows1..4 carry this token position's cosine/sine rows; the tail must wait for all needed coefficients. `o_den` alone is not an epoch identity proof.

The actual SO output is32 writes/head, each256 useful BF16 bits in a512-bit row. Address=obase+8*oc+floor(head/2); masks00FF for even heads andFF00 for odd. Complementary halves must survive. This yields8192 BF16 outputs/131072 bits, not2048 z_quant inputs. The intended next consumer is grouped `attn.wo_a`, preserving all output elements and the golden BF16 division/inverse-RoPE rounding. `attn.z_quant` follows the wo_a matvec and must not receive SO directly.

`xs_bf.py` declares K4096 and1024 output rows/group: eight adjacent heads/group, two groups per rank, eight output slices per group. It selects a whole group's normalized O vector for each output slice. ## Completion is a structural dependency

The original PPATH job has seven q frames and synthetic END at local P.V completion. All-quarter SO operands become ready after that local stream can already finish. Appending17 SMJ frames to make24 does not create an SO completion contract: original END can retire/reuse the descriptor too early. A separate SO job also needs an actual matching result/END producer; sending GO unchanged starts attention again. The model therefore leaves completion source, engine join, denominator lifetime, request tag and final WO_A retirement explicit OPEN obligations. No free return-count/drainage claim is taken from the XS fixed RETIRE path.

## Concrete candidate completion and static calendar contract

Candidate C1 keeps one attention descriptor/tag live through SO and gather, changes its booked q-frame count7→24, and replaces the local-P.V synthetic END trigger with an explicit joined final event. This is a proposed structural change, not existing behavior. The original P.V done is only an internal attention milestone. Both W/E entry completions and all four quarter deliveries must join: the selected parent currently lacks an observed W-half jd/hc path, so adding that dependency includes its real landed lane and receiver cost.

Each request carries `(tag,user,epoch)` in controller state. Denominator ownership is established by that request's actual SE den event in all16 heads, remains valid across the SO start, and is cleared on reset, new SE or booked retirement. The SO start cannot substitute its jid for denominator ownership. No later request overwrites head denominator state before C1 completion. Data SRAM need not reset; validity and request state do. All new region resets assert/release through two registered face stages, with equal paid data/control ages.

The compiler first books Q delivery/SE and local attention windows. Define `Aq` as the real last-quarter arrival edge, `Ad` as the last matching SE-den edge, `R` as SRAM read/assembler/landing age, `D` as actual SO input→write age and `G[s]` as each destination group's gather transport age. All remain pinned measured inputs, not zero defaults. At booked `S >= max(Aq,Ad)+R`, broadcast the six SO parameter words. Operand frame h starts at `S+6+33h` at q-pin II1; rows are its following32 edges. SO outputs occupy exactly that head's row window shifted by the measured parser/tap/subtree age D. Pack four consecutive256b rows into one1024b gather beat; eight beats/head, each with the actual group beat index. Route each group only to its eight output slices, with a predetermined source0/1/2 assignment and parity window opened before its first arrival. If reusing NP4 upstream transport, replace word offsets by four-edge offsets and include its assembler stage: q-pin windows must be derived from actual packet completion, not silently kept at II1.

A booked final event `C > max(last SO write, last scheduled destination arrival + destination capture age)` checks all16 head row counts, four-quarter identity/counts, all16 destination gather counts and matching request state. Only then does C1 produce its single original-source END and allow the engine join/tag reuse. Existing `ot_s81_svc_job` observes END and validates q-frame passage; it does not observe destination acceptance, so a new joined completion producer is mandatory. Missed/late/duplicate/foreign data set sticky fault at the booked edge, never stall or reschedule. Fault completion/host-veto propagation must match the existing adapter policy before C1 is legal; the model does not claim that simply suppressing END forever is a complete fault policy. A reset abandons C1 and invalidates every join/den/store state, preventing stale SRAM from satisfying a new descriptor.

A conservative checker-state bill is16 six-bit SO-row counters(96), two seven-bit group beat counters(14),16 head-complete plus16 destination-complete bits(32), four quarter-valid bits(4), and tag8/user10/epoch2(20):166 FF before fault logic, count-distribution copies and reset landing. This is an explicit proposed state allocation, not a proof of complete fault coverage or native fanout. Per-destination arrival duplicates still require the existing XS arrival table, not only a count. No new credits, ready signals or data masking are introduced.

## Capacity and hardware bill

A conservative all-quarter fence can use16 coherent32x512-bit head stores. Each incoming data column performs one32-bit masked write into each head store; serialization later reads a512-bit row from one head. Mapping each coherent head store to eight genuine32x64 single-clock SRAM banks costs128 banks/128 clocks and70708.10112um2 using the historical b65718325 family area. This is a capacity/port lower bound with known family identity, not a new qualified macro: actual contacts, mask semantics, PG, electrical/timing views and placement remain to be proven. It is not an artificial attempt to turn a coherent indexed store into permitted flop arrays. An alternative can stream and reuse quarter capacity, but must prove all per-head/lane write-before-read and no-overlap lifetimes before reducing this bill.

Capturing all16 full write faces costs8880 input FF before control distribution; a distinct exact parity-specialized299-bit interface would reduce that bound to4784 FF, but requires its own source proof and grant. A1024-bit four-row output pack register plus a1033-bit gathered-beat interface is priced separately. More than one independently live head window would multiply pack state unless an SRAM-backed schedule is proven. XS existing BF capacity is80 beats/parity, enough for64 group beats in logical capacity only. Reuse of those existing24 macros/slice needs exact source assignment, parity and next-phase lifetime proof; new VM macro count is NULL.

Mux area, total/reset FF, clock cap, regional roots/landings, relay counts,405um reach, all native fanout<=32, whole band and expanded die area remain NULL. No full hardware bill or placement fit is claimed from these lower bounds. The model is not ready for RTL or a physical gate.
