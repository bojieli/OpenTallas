## Minimum implementable private contract

Keep **two ownership namespaces**. Descriptor owner lives from accepted D_ERR success until its actual final report/drain, with the real client16/slot8 and the existing active-owner/error-owner distinction. Native step owner lives per issued decode step. A descriptor may own many successive native epochs and generations. The functional component can queue event rows, but selected scalar native admission is additionally serialized by POST as described below. Do not replace owner_tag with a mutable current native tag, compare old CQ lineage against the next step, or use clientTAG as a native key.

1. At real scheduler issue_fire, reserve the sole unbound SU step association (separate from a prior native binding still awaiting POST): actual descriptor owner, client16, slot8, raw position18, input token18. Export from functional source, including input token; registered diagnostic step_issue_v alone is insufficient. At true accepted pkgctl start, match the pending tuple and record actual d_gen2. Unready/fault completion without d_start is typed **NO_NATIVE** and still drains/reports; a missing native allocation never becomes a synthetic valid tag.
2. Provide an explicit held owner association across the actual scheduler/package/HC/coordinator seams. Before central allocation acceptance, the accepted HC token/position/gen must match that pending association. Capture the actual central allocation edge and epoch into the same reserved association. A missing, duplicate or mismatched owner is a protocol failure that blocks success and future admission; never infer allocation from delayed request_ready_q, latest grant or trace32. No new free-running timeout, forced reset predicate or observer mask establishes ownership.
3. An implementation can use a distinct `qkd_host_native_owner_join_rc` plus private wrapper family, default disabled, with held join_valid/join_ready and exact acknowledged native terminal TAG59/gen2. Atomically reserve both associations before dispatch. Existing one-request reservation per native rank, four HC command reservations, all8 request credits and real result/return/release accounting stay intact. This is a finite metadata association; it grants no dynamic compute schedule. If source/clock landing adds an edge, price it before any source adoption. It is not presently a zero-latency claim.
4. Bind sampled health/cutoff to the accepted **native per-step key**, its real descriptor owner and actual issue. Match terminal stage37 exactly; never compare incoming stage0 directly to terminal. Preserve input-token vs output-next distinction. Primitive health coverage and per-layer source phase must separately prove which stages contribute before certification. Missing owner or missing health coverage fails certification; no quiet window or synthetic all-healthy vector.
5. At rawdone, retain existing inflight/FIFO cleanup and matching endpoint/DMA drain. Save actual returned values plus immutable bound native key. Certification may gate mutable context/cache success and CQ success, but cannot gate raw cleanup. Prompt steps without CQ need their real cutoff; generated steps copy bound key into the event row at insertion. Descriptor errors have no native key; descriptor failure records may have a bound key or NO_NATIVE. Keep owner_record independent of native_valid so duplicate clientTAG errors cannot consume the active owner's one failure report.
6. At CQ word0 offer, consume the saved **event** key/certificate and descriptor-owner association, not latest allocation. Success committed mirror linearizes once; later fault poisons speculative/cache/future admission while already offered AW/W/data/B/MSI drain stays stable. Later word0 B acknowledges actual DMA; POST still requires its own exact step/CQ/terminal/release/idle/drain facts. Keep join ownership until matching POST and actual report/drain; a release message or credit alone cannot free it.

## Finite metadata and storage sizing

The compact native step key is epoch16+inputtoken18+position13+gen2 = **49 bits**, with stage/segment reconstructed only because this private binding explicitly fixes request0/terminal37 and segment0. A general stage/segment health record needs full TAG59+gen2=61 bits; no arbitrary stage pruning. One native_valid flag yields a **50-bit** lower-bound active binding. Current descriptor fields already exist; a standalone association needs client16+slot8+rawpos18+inputtoken18+gen2+epoch16 = **78 bits**, plus valid/control. These alternatives overlap: do not sum them or call them mapped FF costs. Delivery, dispatch, rawdone, certification, POST and restart lifetime flags must be enumerated in emitted source. Existing authoritative accepted-rank8, result-return8 and release8 sets are three distinct mechanisms; reuse those actual sets or charge replacements, never one shared bitmap.

The least disruptive full-width event proposal reuses existing62 lineage bits as `{terminalTAG59, nativegen2, certified1}`, preserves independent event_owner_record1, and adds native_valid1. Thus `16*(original116+lineage62+owner1+native_valid1)` = **2880 indexed bits**, +16 over component2864. This explicitly typed whole-row storage needs **real SRAM**, preserving access/OLD/read latency and collision behavior. Copy native_valid with cq_saved too (+1 candidate saved bit). Compact alternative uses49 key+cert1+owner1+native_valid1 =52 metadata, totaling **2688 bits**; still SRAM. These are alternative logical row widths, not physical macro/view approvals. Descriptor failure accounting may retain its existing descriptor owner; native key never substitutes for that lifetime. Active binding lower bound50 plus event16 plus saved1 = **67 incremental logical bits** only if existing owner/pending fields remain and existing rank sets are reused; additionally a standalone pending association is client16+slot8+rawpos18+inputtoken18+gen2+valid1 = **63 bits**. One prior native binding awaiting POST and one next unbound step can coexist. Reusing existing source fields could reduce these 63 bits only after emitted lifetime proof. The combined non-overlapping baseline is therefore **130 logical bits**, excluding all other transport holding registers, control flags, copies, resets and physical landing. It is not a complete implementation budget or an increment to the final1609 without emitted census.
