## Concrete private proposal for ROOT selection

Use the same rule for the first prompt input, subsequent prompt inputs and generated inputs: only the real accepted allocation emits one PREP_ROW containing full allocation TAG59 at stage0/segment0 plus generation2. Preserve the accepted raw tuple, no reconstructed epoch. Its valid is one registered ownership event. The scheduler still chooses prompt SRAM versus feedback; no new next-token selector, result source, credit, token admission or runtime row-ready waiter is introduced.

Retain existing allocator/cohort/native reservation ownership. PREP_ROW is an event attached to the existing accepted transaction, not another acceptance or a second queue. A private producer, explicit finite static transport tree, actual KV landing and row owner start the existing controller/join/FILL paths using the allocated input token/epoch. All128 PC destinations, direct join and delayed fan receive the same immutable row identity with separately priced capture edges. Duplicate, conflicting owner, reset crossover or an early reservation faults and stops this candidate's claim; it never waits for readiness to repair a date. Actual serialization, reset/drain and epoch-wrap protection must come from the native owner before this can be implemented.

In this PRIVATE family terminal RESULT remains genuine and unchanged. It updates the real scheduler feedback and CQ/POST under existing ownership; it does not issue a row FILL. The next row is prepared only after the scheduler selects the next real input and its actual allocation is accepted. This is a source-contract change affecting every selected embedding start consumer, not an OR of HC with svc or a synthetic successful RESULT. Preserve public/default source bytes and bindings. No speculative RESULT prefetch is credited.

Use a private paired header encoder/decoder to carry the full row owner. Current header already contains token18 and epoch16; the remaining27 TAG/gen bits fit within its currently zero reserved field. This is a wire-ABI change: existing receiver requires reserved zeros and cannot accept it. Both producer and Qwen expected-E/header/provider source must be privately paired and default off. The548-bit physical payload and65-slot count can remain numerically unchanged, but previously constant header bits become real state/data and must be priced. Exact bit allocation/installed decoder constructor remains a Qwen source dependency, not an authorization to emit it.

Code-word payload512 and existing token/word fields remain bit-exact. Header owner is retained through all64 words and native65 reads/final scale use. Existing token/epoch return checks do not independently carry full position/gen. The one-active-row invariant and epoch/reset/no-stale-return lifetime must establish that all halves/scale belong to that owner; if it cannot, the fallback is full per-return metadata transport with a new separately priced ABI. No alias safety is assumed just because the selected HOST is scalar. Provider full-owner equality against actual allocation must reject a stale header even if its token matches.

## Static edge contract, without invented dates

Let A be the actual allocation-accept edge. For each actual route i, P_i is its complete producer/output, relay, regional phase and receiver capture ledger. Row/FILL and each PC start occur on their separately derived A+P_i edges. These are not assigned the same root start. Header H must satisfy `H > max(C_0..C_63,C_s)` in the rowtx clock domain; equality is too late because residency is pre-edge state. Actual installed PROG/BTAB/CROM/E reservations are absent, so no prologue length is assigned. If actual programme cannot fit, ROOT must select a different protocol/model before compile.
