## One concrete datapath and ordering contract

Replace stream per-row/key apaddress refill with a six-slot, fully elastic, ordered operation pipeline P0..P5. Public ports/widths/clocks remain; their timing changes explicitly. No new opcode or externalcredit/epoch interface. The QKV path remains its existing pipeline, with dispatch/arbitration prevented from overtaking a nonempty stream pipeline. No streamoutput can be bypassed by a newer QKV descriptor or BOOT_END marker.

At dispatchD, snapshot descriptor-owned constants. Two descriptor-preparation edges D+1/D+2 compute32-bit ring-minus-one in low16/high16 pieces (borrow registered), ring-nonzero and small die/namespace masks. These constants are stable for the segment. This is paid for RAW too as one uniform contract; there is no hidden RAW bypass. Existing payloadRAFIFO can accept data as capacity permits during preparation, but no streamoperation issues before constantsvalid. No guessedglobalphase or externalpostreset idle is assumed.

P0: snapshot one eligible stream operation and its payload, row/sector/phase, descriptorconstants, ownership/writequalifier and boundary/tag metadata. Ownership/rowend logic is the original function of CURRENT row; sourcephase/data advance happens on P0 acceptance, not externalwritefire. Snapshot operands cannot change underneath an operation. Accept no operation without sufficient payload/capacity. Nonowned/drop and IKEYphase2 operations are ordered no-write tokens, not maskedwrites; phase2 still updates scaleaccumulator at P0 acceptance so following phase3/4 snapshot the updated group scales. Existing arithmetic/QKV source semantics otherwise remain the reference.

P1: derive group/stack/local and shifted partialproducts from the snapshot, then two balanced CSA reduction layers,10->7->5 operands. Maximum10 operands covers base+3stackpartials+5pitchpartials+sector forROWS, or base+3stackpartials+2superblock shifts+qgroup+qlow+rowlow+phase forIKEYcode. RAW uses base+row pluszero reduction operands. Ring/nonring selection is applied to the operation's actual operands, not to unsnapshotted laterstate; source-original conditional merge/knownness is preserved.

P2: three CSA layers5->4->3->2, storing the two32-bit sum operands. No fullwidth carry propagates in P1/P2. Code/scale/ROWS select is explicit per operation, rather than computing three complete addresses through serial fullword adders before a single register.

P3: add the LOW16 sum chunks, store lowresult+carry and the unadded highchunks. P4: add HIGH16 with registeredcarry and assemble the final32-bit address. All unsigned arithmetic remains modulo2^32. Each carry span is16bits, not the measured32-bit MAJ ripple. Payload/qualifier/tag metadata advances only with the same operation.

P5: boundary holding register for complete address/data/writequalifier; no address arithmetic after it. It holds a pending write stable while w_rdy0, and retires only on w_v&&w_rdy. A no-write token retires without requiring downstreamready. Stagevalid/ready controls propagate elasticity; each stage freezes its entire operation when blocked. Six in-flight operations maximum, with no external credit consumed until actual P5 retirement. Backpressure/ready routing is part of the required nextmodel, not ignored.
