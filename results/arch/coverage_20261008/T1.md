# T1 coverage: Qwen3-8B on the Qwen ROM die (r21b + r21c), TP4, AR only

Stream cov-T1, 2026-10-08 (PT). This pass only looks for gaps; nothing was fixed. The method is `/home/ubuntu/claude-takeover-20261007/coverage/METHOD.md`. The node-by-node ledger is `T1.json` in this directory, with 61 nodes.

**How the graph was built.** It was derived from the model first, not from the hardware lists:
- the model config: `compiler/models/qwen3-8b/config.json`;
- the arithmetic golden: `tools/hdc_golden.py` `Model.decode_token_tp`;
- the ISA program: `tools/hdc_program.py --tp 4`, with the full-shape op trace in `results/rtl/qwen_rom_kv_fullbw_20261004/dspark_verify_P8187/optrace/`.

Only then was each node matched to:
- the r21b die recipe (`results/rtl/qwen_repack_20261008/die_top_lint_r21b.json`, 176 masters);
- the closure loop (`/api/elements` and `~/.local/state/closure_loop/jobs`);
- the token path (`results/arch/token_path_20261008/qwen_rom.json`: 218,472 cycles, 5,492.7 tok/s, a priced candidate).

**r21c does not exist yet.** No recipe is on main `132866cd1`. The embedding-in-HBM RTL is uncommitted in `/home/ubuntu/wt-claude-emb-hbm`, and its end-to-end bench was still running on ot-epyc2 during this audit. MTP is not applicable: the owner chose AR mode, per `dspark_verdict.json`.

## Update 2026-10-09 (stream kv-die): the ROM die + KV die partition

The owner decided at ~04:00 PT on option 1a. Each node it touches has an added `kv_die_20261009` entry in `T1.json`; the r21b/r21c fields stay as the pre-decision record. The evidence is in `results/arch/qwen_kv_die_20261009/`: `CONTRACT.md`, `bench.json`, `reprice.json` and the die records.

**What moves to the KV die:**
- the HBM PHYs, controllers, CDC and landings;
- the KV merge and posted append (C06);
- the near-HBM attention (D10–D13);
- the embedding gateway and strips (D01, F03);
- the host and prefill ingest (H03, H04);
- the PLL and reset sequencer (B04, B05).

**What crosses the UCIe link (C14, new):**
- each layer: q (32 words), the new K/V (8 words) and RES (64 words);
- each token: EMBQ and EMBD (65 words each way), the TOKEN word, and host words (HCTL).

**Exactness.** The attention layer step through the link is bit-exact against `tools/hdc_golden.py` at ctx 1–8,192. HBM returns poisoned rows for t = T-1, so only the merged K/V can give the exact result. The embedding words, host words, token word and KV rows check too. Mutants are caught (F04).

**What the partition settles:**
- **Gap 6 (embedding) is priced:** 287 cycles typical, 614 worst.
- **Gap 12 (KV ECC) has its policy:** SECDED check bits as an ordinary scheduled read (CONTRACT §6). The RTL is still owed.

**What the partition opens:**
- the near-HBM row engines and hub must close; they were dropped 10-04 and are now re-queued under TT sign-off;
- the engine ↔ aggregator re-cut;
- the no-KV ROM tile `qfd_tile_nk`;
- the PLL abstract is still missing.

**Rate.** The typical token re-prices to 221,538 cycles = 5,416.7 tok/s, −1.38 % against the TP4 basis (range 5,398.2–5,418.5).
