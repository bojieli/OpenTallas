# QW-SLICE6 10-19: the hardened one-level slice2 (Q.STA.SLICE.2), build phase

This builds the plan of claude/qw-slice5-1019 @961b2dafd (`results/arch/qw_slice5_1019`). LEAD3-QW decided:
- (a) the slice is a hardened one-level cluster, built once and replicated x12;
- (b) the ~+327 cycles/layer of the plan is accepted.

The slice prefix `qfd_dv_slice2*` is critical: gate packets go to COORD-REVIEW-QUEUE, with no REVIEW.json and no submit. The new leaf masters use the prefix `qfd_dv_s5_*`, which is not critical; they are submitted main + fallback by the sub-lanes.

## RTL

**Leaves** (`rtl/qwen_dv/s5/qfd_dv_s5_leaves.sv`, `qfd_dv_s5_vm.sv`). Each leaf lands `rst_n` in its own two registered stages, which equals qfd_dv_slice2's regional synchroniser, so every register releases on the same edge as before.

| leaf | content |
|---|---|
| fdn / fup | Face strips: pin registers, the outbound-chain merge (ch_dn_o) and the status OR (ag_dn_o) at the dn face, SETID cmd_o at the up face, and the face pass-throughs. Every output is launched in its face region. |
| fn / frs / fs | N / S face entries: rs_n and rs_s split per station region, plus cw_s. |
| ctl | Decode, SETID, configs, VM write merge, XC, ARX / gather, own AR / D2D word, amax_mu, status. |
| suvm | qfd_dv_su8_entries issue control, the kept group relay, stage 1 of the lane relays, and qfd_dv_s5_vm. |
| btab | The station's BTAB copy, beside station region 0. **Deviation from the plan:** the plan landed bt_q across regions, but bt_re / bt_word -> bt_q is a round trip. The closed stnrgc BT_LAT 1 allows only its own pin register, so the copy must sit local to r_st0. 0 edges. |
| red | rd_* + ot_hdc_vreduce. |
| sc | scalar2 + taps. |
| stm | LABELLED STAND-IN for the stream (QW-STREAM2 t2) and tload (QW-TLOAD2 ns3) tiles. |
| tap | xs_tap + x expansion + fault join + column ids. |
| xhead | ot_qfd_xhead + tids + retag. The column is given by the `cid` input, so the leaf needs no strap. |
| lrly x8 | The su8 LTD relay stages + the qfd_dv_su_lane IREG/OREG. |

`HARD` (default 1) adds a register only where the exact cut is combinational. Each of these costs +1 edge and goes to the compiler:
- **ctl:** stn_cfg, sc_cfg, stm_cfg, su_cmd, am_*, w16_*/w1_* VM writes, own_ch, ag_own.
- **stm:** tw_* (static window).
- **suvm:** su_nr (status).
- **fdn:** pc_bad (status).
- **tap:** cid (static value).

The closed stnrgc (PIN_IN 1) adds +1 on cfg relative to rs / nb, because its pin register replaces the slice rs / nb pin registers on the same edge.

**Flat parents.** Both are generated by `tools/qwen_dv/gen_slice5_flat.py`:
- `qfd_dv_s5_flat0`: HARD 0, stnrgc PIN_IN 0. It must equal qfd_dv_slice2 #(SU_TLS 1, SU_LT 1, HD_W130 1, MU_NU 4, PRIVATE_CALR 1) at offset 0, using the regional station source (+define+OT_STATION_REGIONAL).
- `qfd_dv_s5_flat`: the hardened composition.

**Landed parent.** `tools/qwen_dv/gen_slice5_lp_spec.py --gen` builds the landed parents from the lp.py specs `tools/landed_parent/specs/qfd_dv_s5{,b}.json`. It has 21 regions and 183 landings (28,312 bits):

| spec | D / E | landing flops |
|---|---|---:|
| qfd_dv_s5 (main) | 4 / 2 | 111k |
| qfd_dv_s5b (fallback) | 8 / 4 | 193k |

Both audits PASS. The slice has cross-region loops:
- ctl -> SU / station / scalar -> ctl;
- fdn <-> fup.

So every cross-region reader pin is lagged E+1. The lockstep reference is `<spec>_flat_lagref`.

## Benches (`rtl/test/qwen_dv/s5/run_s5.sh`, Verilator 5.050, fleet)

- **eq:** flat0 vs slice2 at offset 0, in four stimulus modes (random / quiet / hronly / legal). The mutants (d10, d12, d9, loff, lrly, red, sc, xh, btab) must FAIL.
- **b2:** dv_bench2 f j k q m n o on FACE 3 (flat0).
- **lp:** the landed parent vs its lagref. lp.py mutants 1 / 2 / 4 must FAIL.
- **audit:** the lp.py audit, plus the unland mutant (must FAIL).

## Price (compiler re-schedule; NOTICE lanes/QW-GEN3.md)

Every cross-region crossing costs +3 edges in the main build (E+1) and +5 in the fallback. The HARD +1 terms come on top.

**Pass chains per slice hop:**
- cmd, hr, ch (both ways), ag, treq: +3.
- **Stream st and scalar sc are THRU in this build: +6 per hop.** Their pass goes through the stand-in stream leaf and the scalar leaf. The plan's FWD version (+3) needs:
  - the stream t2 tile to tap and insert only;
  - the scalar chain's pass / insert split into the face strips.

  This is the follow-up perf item, not a blocker (decision (b)).

**Per-layer bound:**

| item | cycles / layer |
|---|---:|
| pass: 10 hops x (2 st x 6 + 2 ch x 3 + 4 sc x 6) | 420 |
| taps: plan 87 + ~29 HARD +1 terms | ~116 |
| **total** | **~536** |

That is about 19.3k cycles/token, or ~8.3% of 194.5 us. It is above the accepted ~5% (327 cycles). With FWD st / sc it falls back to ~356 cycles/layer (~5.5%).

The 182 slice<->slice face landings (claude/qw-slice4-face-1019 @7811217d7, +3/hop, already priced in that plan) are NOT yet in the parent. They are a follow-up.
