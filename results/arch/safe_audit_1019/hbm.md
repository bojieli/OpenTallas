# SAFE-DESIGN audit: HBM open tiles (SAFE-AUDIT-HBM, 2026-10-19 06:40 PT)

This audit applies the owner's checklist from 10-19 (HANDOFF 0ko, common_brief SAFE-DESIGN CHECKLIST) to every open HBM tile on the release die and to the next-release P=4 tiles.

**Sources:** each kit's `spec.json`, `kit.env`, `floorplan.json` and committed `gate_result.json`, read from the owner's branch head. The extraction script is `/home/ubuntu/scratch/safe-audit-hbm/audit.py`, and its raw rows are in `audit.jsonl`. These were cross-checked against the live lane notes (TW5-HBM-BLK 06:10 collection, HNX-GQ, HBM-BANKLAT-COLL, PL-HBM9, HBM-NEXT-UNITS).

**Items:**
1. pin regs and reset landing
2. reach 405 um
3. fanout <= ~32 in critical cones, kept copies
4. depth <= 600 ps / 20 levels, registered one-hot selects, no in->out path
5. storage over 2 kb goes into SRAM, delay lines of 3 or more become ring buffers
6. floorplan: 43.2 lattice, channel pin density <= 6/um, 40-60 % synth utilisation, aspect <= 2:1, full std-cell band
7. clock: centre-fed or regional roots, spread <= 80 TT+FF, io_hold_margin >= 0.03
8. static schedule, with every added cycle priced

## Rules that cut across many tiles (one fix per tile)

- **R1 (item 1):** the reset_landing rule landed on main on 10-19 (ROOT-RST), and `ref_tile.py gen` now refuses multi-clock kits that do not name `reset_landing.clock`. Kits generated before it have `OT_RST_LAND` off: pslice_c5_lp, pgslice_lg, cx_ijq, VM glue g3 ×3, idx_score qe/qw/leaf, smh_tile_rp4lp, pretree, smh_fc*/xs, smn_fcxr2, hnx_rp4lp4 and hnx_vms_bank. **Fix:** take `tools/ref_tile` from origin/main and re-gen. Multi-clock kits name the data clock.
- **R2 (item 3):** reset trees fan out into thousands of flops. After landing, a single `rst_*__ot_rl1` drives 780 to 7,077 loads (v5r ctl, pvm r4, k9). Reset is not a timing-critical cone, so repair_design's equal-depth tree is acceptable there. This item is PASS on reset nets once the landing exists, and WARN otherwise. Data and select nets above 256 loads are real item-3 failures (listed per tile below).
- **R3 (item 6):** many kits sit at 4-28 % synthesized utilisation (cx_ijq 5 %, idx qw 4 %, idx qe 19 %, fcxr2 6 %, v5r 28 %, pg_stream 3 %). These outlines are pin-bound and fall outside 40-60 %. The safe form is a smaller outline with relays, or pins regrouped onto fewer faces, never a big empty tile. When a closed neighbour fixes the slot, waive the item with that reason.
