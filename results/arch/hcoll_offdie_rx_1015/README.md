# H-COLL off-die RX block boundary (0az candidate)

`ot_hgi_coll_offdie_rx_block` keeps ready/valid only on its external PHY face. An explicit arm configures 1..64 raw 612-bit frames. The link must hold valid and data until handshake. After the last accepted frame, two seal edges commit native captured writes before block-ready. Full/closed staging deasserts ready; asserted valid while not ready does not overwrite a frame.

Each port uses two actual `ot_qkvd_llr_replay_sram_leaf` instances at W306, backed by the exact native 64x512 macro model. No behavioural replacement RAM is used. The stage does not add SRAM ECC; it preserves each native endpoint frame's full identity and CRC for checking by TX6/RX2.

An explicit release enters deterministic drain. The next edge can carry slot0, then slots1..N-1 at the compiler's fixed edges. Invalid/out-of-order/unavailable slots fault and never move to another edge. The raw pin valid/data publish at slot+3; the existing endpoint samples that registered pin at slot+4 and publishes its checked545-bit payload at slot+6. The off-die filling period is variable; the draining period has no on-die ready, credit or retry input. After the final slot there are four flush edges before re-arm. Faults are sticky until reset.

The distinct `ot_hfd_coll_q{2,3}_static_host_v4_elastic_rx` successors instantiate the original whole V4 host and real per-port stages. `rx_required` selects which complete blocks must be ready before a HOST launch is admitted. A missing required block faults and suppresses that launch; the caller must reset/retry explicitly. Arm/release/calendar inputs are compiler/controller commands. Release must follow admitted launch (a released stage is no longer block-ready). Existing V4 wrappers and current v15 bindings are unchanged. Boundary clocks must have the same logical phase as native clocks; this stage is after the SerDes CDC and is not a CDC implementation.

The component proof drives actual TX6 hardware, delays its emitted frames with arbitrary link gaps, drains real SRAM on fixed calendars, compares all612 bits against actual transmitted frames, and compares native RX2 545-bit publication against independently generated payloads. Blocks1/2/17/64/64 reuse the same epoch with full sequence0..147; repeated macro-row reuse crosses64 and128. The last64-frame block drains at one frame per cycle. The other blocks include fixed empty slots. Partial blocks never become ready. A held extra PHY frame at full staging cannot overwrite stored data. The real SRAM data mutant and premature block-ready mutant fail independent assertions. Invalid0/65 sizes, release without a block and unavailable fixed slots produce explicit checked faults. Reset is real and initial SRAM contents remain unreadable.

Physical area/pins/clock/timing, whole-q3 runtime, full FEC/finite-CDC composition, actual multi-die calendar and G96 throughput repricing remain OPEN. This finite single-block candidate does not establish a multi-die throughput result. It cannot receive the next block while the current block drains; repeated-block latency must include this serialization. The model counts the two physical SRAM macros per port and the full1224 data tracks for input/output. No routing or clock grant is implied.

A separate exploratory whole HOST reduction run on this current source failed in native reduction, with all boundary/program faults zero: native pipe_v reaches80 but wb_tag remains X, pending0001 never clears, and publication reports unavailable cause04. The exact state trace and bench snapshot are retained as `parent_reduce_state.FAIL.log` / `inherited_reduce_diagnostic.sv.txt`. It is not used as positive evidence for this boundary. The native RX component proof does not instantiate that arithmetic reducer.
