# Native SU ROM registry and host bridge

This additive bridge connects the source-pinned 42-slot N256/M64 native690 ROM to the actual pre-norm graph. It resolves 253 of 871 graph operations: RMSNorm, QKnorm, RoPE, Q BF16 rounding, SwiGLU and softmax. The 22 remaining kernel families, including ME launch entries, row scales, attention, KV, collectives and embedding, remain unresolved. Full decode is not executable.

`tools/qwen_r25_decode_program.py` accepts `--native-rom`, `--native-dispatcher` and `--native-provider` together. It installs actual native descriptors into the graph registry. `tools/qwen_r25_native_bridge.py` independently accepts an existing `--program` JSON, enabling the previously pinned graph without importing arithmetic tooling. `registry.json` is the compact actual graph output; `install.json` contains ROM/provider/dispatcher pins and finite VM addresses. Paths in these measured records identify the immutable EPYC4 run; regenerate the contract at the deployment location rather than reusing remote paths.

The provider uses actual elaboration `$readmemh` parameters Q0/Q1/Q2/Q3/META, ENABLE=1. Default production consumers remain disabled. Metadata is 42 bits: valid, quarter mask, window, row0 and row count. Production dispatcher parameters are OWNER_W=74, CAPACITY=8224. No new ROM ISA or CP opcode is introduced.

Actual graph ranges are RMS0/count4, QK4/count6, RoPE10/count6, Q rounding16/count1, SwiGLU17/count2 and softmax19/count23. Splitting the compiled RoPE stage at its existing final Q rounding word preserves the distinct graph edge and all immutable payloads. Native ROM PCs are never emitted as SM/kernel PCs: the old command linker rejects native registry entries until an actual CP-to-SU adapter exists.

The actual launch pins carry PC12/count13/position20/queries3/checked2=3 and owner74 `{position20,token18,generation4,job32}`. `NativeSUHost` holds these pins until ready, waits for actual dispatcher finished/fault, and never manufactures results. A finite VM provider must return an identity-matching installation receipt after write ACK and same-sector visibility, with exclusive dispatcher ownership. For four sequential queries, it must gate ROM request acceptance during operand and RoPE constant replacement. This provider hook is an explicit integration requirement; the dispatcher has no per-query operand-install handshake. There is no complete CP/host integration claim.

The four quarter tags use high two QID bits and low fourteen transaction bits. They do not offset VM addresses. The shared VM has 262144 FP32 words, read-only zero at262143, and sequential query reuse of eight heads with8224 rows. Score base0, FP32 exp65792, BF16 publication131584; each quarter owns two heads at stride8224. Denominator base210144 has two words per quarter. Full RMS reduction is still duplicated four times: 12288 extra square elements and four rsqrts, with no cycle/area/performance credit.

EPYC4 had383GiB available and2.9TiB disk at admission. System Python ran this small standard-library metadata/protocol gate through `admit.sh 1`; there was no new local compute. `gate.json` reports19 passing cases including held launches, owner74 token boundaries131071/131072/151935, query tail bounds, registry resolution, refusal to treat ROM PC as kernel PC, ROM corruption, stale completion, stale owner, missing visibility and missing query gate. The one-GiB reservation conservatively covers source/JSON/temporary bank inventory (tens of MiB), with the host admission guard's additional cushion.

These are metadata and host protocol checks, not actual arithmetic RTL, SS/FF closure, physical mapping or whole-decode evidence. The parent and stage owners are separately qualifying the actual quarter/finite-provider arithmetic. Compiler evidence remains unchanged under `results/rtl/qwen_native690_20261009`.
