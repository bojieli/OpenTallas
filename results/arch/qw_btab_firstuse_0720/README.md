# BTAB S4 first-defined-read and startup contract

The old `tb_btab_s4` receipt remains unchanged: it fills128 rows and compares only after cycle136, so it proves initialized steady traffic rather than independent cold first use. This packet closes that specific component-level evidence gap using the **unchanged** source3f0f4b600 implementation and the exact physical SRAM functional model, rather than the old simplified model. It does not claim a global parent boot-install proof.

The component has no reset port. Its value contract is explicit: a read sampled on rising edge R has a defined value if the selected logical row was completely written before R. That value appears after R+1 (a downstream FF can sample it on R+2). An unwritten-row read is undefined; a first simultaneous write/read of such a row does not magically initialize its old read value. The macro's actual functional model is read-before-write for a same-row simultaneous read/write. Its Liberty read arc is rising-edge with input setup/hold; Liberty alone does not specify collision data values.

`tb_btab_firstuse.sv` disables the actual model's zero initialization (`OT_MEM_NO_INIT`) and independently initializes both instances' physical arrays, held macro read registers, and old/new FF state with separate random draws. It asserts that raw startup outputs and an untouched SRAM row differ, so common default zeros cannot silently satisfy the test. The first row37 is written while the other127 rows remain unrelated. **The first defined read is sampled on cycle3 and checked on output cycle4, with only one row initialized.** No `c>136`, reset warmup, or global full-table preload predicate exists. Checks are enabled only by a real prior read command to an initialized row; every such defined output is checked, including first uses and all256 payload bits.

Exact Verilator5.050 runs passed seeds1,17,999. Each checked921 outputs, including all512 row/bank first uses and507 outputs before all rows had ever been initialized. These runs also exercised162/164 simultaneous read/write samples, including both undefined first-write reads and defined read-before-write cases. All three causal negatives failed at the first defined output (cycle4, row37, bank0): actual select-polarity corruption in the source, an extra register on the observed actual DUT output, and suppressing the candidate's actual first write. `RESULT.json` and raw per-seed/build/witness logs preserve exact source hashes, options and fleet units. Simulations are finite evidence, not a universal random-state formal proof.

`source_contract.py` supplies a separate source-equation certificate: all16 one-hot selection bits are unconditionally captured from the read bank; the selected SRAM read register is overwritten on R; and on R+1 both the old bank-select/capture form and the new one-hot form select that word.16,384 bank/bit Boolean cofactors verify the selection identity for arbitrary other-bank read values. The relevant prior FF state is overwritten before the first defined output. This is a source-equation certificate, not full mapped-netlist formal equivalence. The source and physical model hashes bind its assumptions to the actual files.

The no-reset inventory is also explicit: no declared functional reset port, source FF events only `posedge ck`, actual native standard FF `clear`/`preset` fields absent, and physical SRAM event only `posedge clk`. No raw reset contact is waived, and no canonical framework reset-proof receipt is manufactured. Row/column repair pins are constant zero configuration inputs, rather than reset pins. The existing final native/geometry/clock/timing audit remains applicable to the unchanged DUT source.

Physical arrays including spare rows/columns are4x130x258 =134160 cells =16.376953KiB, ratio1.02355957. Parent obligations remain: every consumed read must target a previously installed row and honor the fixed response age; actual compiler/table-install provenance, replica count, nominal clock compensation and neighbor composition still need their own receipts. This proof deliberately supports per-row first use, so it does not rely on claiming that a parent globally prefills all512 words. There was no implementation change, new gate, route, or shared-helper edit.
