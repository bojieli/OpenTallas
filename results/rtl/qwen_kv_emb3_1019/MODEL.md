# Allocation-owned embedding admission repair

The d963 context tap diagnoses an early new owner but still changes start, token, epoch and retained owner. It also accepts later contexts after sticky fault. The repair qualifies the existing single admission predicate with no prior fault and gap==0; only that predicate changes owner/token/epoch/start. Invalid current context or occupied-gap context may set sticky fault and decrement the existing counter, but cannot publish a new owner. No added state, die boundary width, SRAM, edge, clock, arithmetic or static-calendar change. One new local row_open wire and ctx input exposes existing row_tx.armed as an admission veto. ctx_start input count +1; row_tx diagnostic output +1, wrapper external ports unchanged. The 207-flop source price and two-edge face-to-start age remain. Boolean fanout adds admission gating to existing local flops; native mapped census and physical timing remain unmeasured.

MIN_GAP=66 is only an early-context consistency floor, not proof that the actual 64-word+scale fill and 65-record drain have completed. Existing row_tx and join independently diagnose overlap. Production source dates must establish the next context arrives after final row slot and join last; no ready/wait/credit is introduced. The full-component bench will derive rows from real accepted allocator grants and canonical TX/RX source rather than inventing expected owners.

The existing armed state remains high through the pre-edge observation of the 65th send; it clears only after that edge. A context consumed on the same edge is conservatively rejected, because the old row is still open in pre-edge state. The next edge can accept a context if no prior sticky fault. This is a static fail-stop overlap check, not admission backpressure; it never retains/retries the conflicting owner. No claim is made about the independent compute consumer final-scale lifetime.

The armed export lives in opt-in qkd_embedding_row_tx_ctx, an exact copy of the released row body plus diagnostic assign. The public qkd_embedding_row_tx source and its closed native view stay byte-identical. The context wrapper selects the successor; it requires its own mapped/native qualification.
