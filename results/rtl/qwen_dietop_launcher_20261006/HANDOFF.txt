Qwen DIE-TOP launcher correction — isolated implementation, no remote deployment

The old source tools/qwen_rom_fulldie_run_case.sh wrote markers into its input
case directory even if docker run failed. Its final date command masked the
failure exit. A caller could therefore mark the case done and attempt dependent
PDN while the original same-name container remained live.

The shell entry point now delegates to tools/qwen_dietop_launch.py and deliberately
rejects the old positional interface. Copy BOTH source files when installing the
new runner; existing remote scripts were not replaced and the live r21 job was
not stopped or restarted. Future callers must use this runner for the complete
placement -> PDN dependency, not append an unconditional PDN call. It never
launches GRT or DRT.

Invocation template (run on the admitted compute host with a clean pinned source
checkout and generated inputs; RUN_DIRECTORY must not exist, parent must exist):

  bash tools/qwen_rom_fulldie_run_case.sh \
    --source-root /path/to/clean/pinned/checkout \
    --source FULL_SOURCE_COMMIT_SHA \
    --inputs /path/to/generated/a_pdn_inputs \
    --run /srv/opentallas-scratch/qwen-die/NEW_UNIQUE_RUN_DIRECTORY \
    --threads 16 --peak-gib MEASURED_PEAK_GIB \
    --admit /srv/opentallas-scratch/admit.sh

The peak is a measured scheduling estimate, never a Docker memory limit. The
runner invokes the shared admission guard before each container starts, then
checks current MemAvailable against peak + max(10% HOST TOTAL memory, 32 GiB).
The guard remains responsible for concurrent/ramping reservations and current
fleet CPU policy. No shared guard was changed by this patch. The added capacity
check fails closed if headroom changed after admission; there is no automatic
retry. This patch does not supply an unmeasured r21/DRT peak.

Ownership and dependency behavior:
- Atomically claim the fresh run directory before any Docker action. Existing
  paths are rejected without altering files. No outputs go to the input directory.
- Copy the nine generated a_pdn input files; reject symlinks and changes during
  copying, hash the snapshot, make it read-only, and mount every input read-only
  inside /work. Prior outputs, case.done and .exit markers are never copied.
- Pin the image to its resolved sha256 ID; create a uniquely named container with
  run/phase identity labels. A create conflict records only an attempt failure in
  the new owned directory; it cannot inspect/start a foreign container or publish
  a phase completion. All later Docker operations address the returned full ID.
- Inspect matching ID/image/labels and fresh created state before starting.
  After attach returns, require the exact container to be exited with exit 0,
  not running/OOM-killed, and a real finish timestamp. An attach or admission
  failure never promotes a potentially still-live container to completion.
- Require physical log markers and nonempty ODB outputs; caught Tcl errors,
  absent legality/pin-access/PDN markers, and physical FAIL markers block PDN
  or final completion even when the process returns zero.
- Preserve created containers and all failure evidence. No rm/stop/kill, timeout,
  cgroup cap, or restart. In-flight interruption leaves no success receipt.
- Only complete.json means placement AND PDN completed, with per-phase container,
  artifact and log hashes. It explicitly does not claim GRT/DRT or SS/FF closure.

Source HEAD/cleanliness and input hashes are recorded separately: this launcher
protects a generated snapshot but does not prove that a manually supplied set
was generated by that commit or that its abstracts match hardened hardware.
Actual relay netlist, pin-plan measurement and full-die physical gates still apply.
Owner's 21:30 exception permits re-routing affected blocks' pin plans with the
same RTL despite the element freeze, as corrected in the takeover HANDOFF.

Validation uses fake Docker subprocesses plus real temporary git checkouts.
The first test attempt exposed Python 3.10's lack of hashlib.file_digest; fixed
with streaming SHA-256. Initial failure retained separately. Final targeted
results are in pytest_final.txt. No synthesis, route, or remote job was launched.
