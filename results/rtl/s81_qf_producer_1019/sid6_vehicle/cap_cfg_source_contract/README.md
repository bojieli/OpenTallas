# CAP source configuration and ownership: read-only preparation

The existing ABI supplies a real configuration producer without a new datapath: a scheduled XR CTL packet addressed to slice6, target3, leafmask0 carries160 bits of configured state. The actual XR output registers drive the shared CAP cfg pins directly. CAP registers the pins, then installs active fields. The existing slice also connects CW through actual DL4 routes into VP pin registers and the SRAM write ports. Source hashes and exact bit expressions are in contract.json.

For the existing sparse head6 storage map the body has obase/ops/np0, fmt2, rbase=(tau_e<<14)|0x1800, rcnt828. tau_e is the actual backend tag, not an epoch counter or a configured SENT bit. The logical row map occupies offsets through827 with holes; the range is not a512-consecutive-row remap. Actual all-row coverage, rounding and stored data remain unproved for this full-six vehicle.

If c samples the XR input packet, source register algebra gives XR cfg launch after c+2, CAP pin sample c+3, active config after c+4; a D2 consuming that new config can first do so at c+5. These are structural edges, not measured dates. The running first trace retains reset config and F9 failures, and is unchanged by this preparation. Its output is needed to select a later fixed SOURCE-owned programme; no tag sequence or actual CFG edge is supplied here.

The source hardware F11 guard only observes cfgv_q && any_open. It does not prove decoder/CW/VP drain. A safe owner transition must also account for old complete words already beyond pairing, upstream returns still in flight, every D1/D2/D3/CW/leaf relay/pin/write edge, pending reads and destination live ranges. Config must remain valid for each actual D2 consumer. All actual owner identities, port occupancy, fault/reset/reinstall behavior and original deadlines need a fixed, falsifiable calendar before numerical use.

The current frozen source CTL contains387 commands:320 row writes,20 QB commands and47 streamer commands; target3 count is0. Adding one target3 per15 epochs would consume up to15 additional real CTL slots (402 total) and existing160-bit configured-state transport. No slots or bandwidth are assumed free, no dates are chosen and no command is installed. No new FF/gate/SRAM is proposed, no production/MU capacity or healthy CW stream is credited. Exact original source/weights/gold and frontend02 inputs remain untouched.

The width rcnt828 is only the decoder interval. It includes316 unused offsets around512 real configured rows across all15 epochs, and is not an epoch output quota or physical capacity/lifetime proof. Frozen original plan metadata expects36 real rows in each epoch0..13 and8 in epoch14; all actual produced counts remain NULL until the coupled trace. contract.json pins the90-plan metadata hash and lists each original semantic row per frame/epoch. This inventory does not rerun numerical planning or grant actual row coverage.
