## Concrete correction to predecessor

Pinned source has **`src/CMakeLists.txt`, `src/OpenRoad.cc`, `src/OpenRoad.i`, `src/OpenRoad.tcl`, `include/ord/OpenRoad.hh`**, not the predecessor's nonexistent `src/ord/*` paths. End-of-create alone is insufficient: an earlier dbInst/ITerm callback may invoke analysis before end. `proposal/native-boundaries.patch` adds native begin-create before ALL existing inst/ITerm callbacks, end-create AFTER their callbacks and before return, and pre-DNT false-to-true before assignment. This leaves original callback order intact. Begin's pending stack makes reentrant estimate/protection refuse; end preflights EVERY PG term before any connect, binds only newborn null terms and reads back. Nested births are LIFO. There is no global-connect scan inside callbacks. A thrown exception poisons the guard and MUST terminate the run; partially constructed DB must never resume or publish. Existing consumers receive normal ITerm-create before connect notifications. A consumer caching PG at inst-create is still a proof gap; it sees null until end, so those consumers must be inventoried/tested or strict begin guards must reject their PG use.

The first concrete C++ owner is proposed in **odb** (`NativePgBirthGuard.hh/.cc`), so OpenDB/EST do not depend upward on ord. ord owns activation/lifetime and capability receipt. The draft uses actual native public `dbGlobalConnect` regex strings, exact region identity and real net/MTerm signal types; it matches `std::regex_match` semantics from native dbGlobalConnect. It does not infer VDD from pin names and does not call native whole-library `getMTermMapping` per birth. Duplicate matching rules to SAME net are allowed; multiple distinct target nets, role mismatch, missing rule/ITerm, wrong existing net, protected unbound instance/target refuse. Masters with no PG roles require no invented PG. Physical-only/open-output instances are included. To keep caching safe, rule/domain/master mutations are frozen while active. There is no master-role cache; role lookup uses current master.

Draft source ~200 lines plus callback patch. **No compile claim**: callback patch has not been applied to a full upstream checkout, no EST/ord registry bridge exists yet, no SWIG wrappers were generated, actual exception propagation and logger/error IDs are not qualified. The draft's std::runtime_error is a proposed fail-stop transport, not a demonstrated whole-command failure protocol.

## Mutation surface and scaling

The C++ draft observes ITerm connect/disconnect and instance moves for generation invalidation. Native pre-DNT audits exact instance. Master swap is conservatively refused by existing **before** callback, avoiding a callback reentrancy hole; its after callback is only a read-back assertion. No transparent master-swap support is claimed. Add native pre-mutation refuses at dbGlobalConnect::create/destroy (and duplicate-rule path), dbRegion::addInst/removeInst/destroy, instance rename, supply-net destroy/merge/role/DNT changes and PG-master/MTerm mutation/destruction. No metadata-only type change may escape because no placement estimate followed it. Master mutations require cross-block database/library guard lookup, not an instance-only callback. Supplied region during initial dbInst construction must be allowed as part of its native birth before Begin, while later addInst assignment is unsupported; this requires an explicit native construction token rather than a name check. All those source points are listed as missing, so stale cached rule pointers can NEVER be activated by this draft.

Birth cost is O(PG_terms×rules), with regexes compiled once on activation, no full-library/per-block scan per birth. Full entry/estimate/qualified-write audits O(instances×PG_terms×rules), limited to transaction boundaries. Per-net ensure guards O(1) once complete native invalidation exists, never one full census per net. RAM O(rules + nested births), plus one owner per live block; no 98k-instance mapping rebuilt for each new cell. Hardware area/state/cycles zero. Native CPU/memory cost unmeasured. Ordered native receipt (capability/source/image/block identity, rule fingerprint, event sequence, epoch, birth/bind/preprotect/estimate start/end) still needs a bounded implementation; no receipt writer exists in this draft. A receipt without these integrations is inadmissible.
