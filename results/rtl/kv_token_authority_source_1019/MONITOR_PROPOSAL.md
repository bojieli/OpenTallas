# Implementable monitor proposal, pending causal validation

Generate a verification-only manifest from the selected compiled cut with source hash, clock, effective source reset, reset-cleared qualifier register, and ordered relay instances. Fail generation on unknown primitive, combinational valid transform, missing driver, multiple driver, wrong bit mapping, unsupported clock or mismatched source hash. The included walker is a bounded evidence extractor for the selected G7 paths, not a production HDL elaborator. A future implementation must additionally assert source/output aliases and each hop's one-edge behavior.

For every path create a source-known tag initially0 and an initially0 verification tag per actual downstream FF. At a real effective source-reset assertion, or at a target posedge with that reset known0, verify after NBA that the actual source valid is exactly0 and mark source-known1. Propagate each tag by the same clock edge as its corresponding actual FF, using old tag values just as the RTL samples old D. Sample the monitor after NBA (the current negedge consumer is adequate for these positive-edge paths). Never infer that an unreset Q was0: its tag stays0 until an initialized sample has physically reached it. An asynchronous reset that occurs before the first target edge can initialize the source before that edge; a reset first sampled at an edge cannot retroactively initialize the D that a downstream FF already sampled. This ordering must be exercised by the control harness.

An initialized FF remains known across a later reset. **Do not clear knowledge tags on a repeated reset and create a new blind window.** Keep the protocol monitor armed after its first known frontier, through idle, active traffic, reset assertion and flush. Separately track actual reset episodes, assert reset-cleared source behavior, and check qualifier-zero propagation through the actual downstream captures. The request lifecycle can be cancelled only by its actual source reset under the explicit reset contract; retain raw record and error history, and diagnose in-flight records around reset. A repeat reset must never clear errs or hide a malformed first post-reset record. If a different implementation re-arms after reset, it must preserve checking of already-known downstream state and must demonstrate no blind interval.

Before the first known frontier, record raw observations and source-reset checks but do not enqueue K/V responses, allocate sequence ordinals, or count face retirement from arbitrary initial Q. A request at the first authoritative edge, even before trace_on/A0, is processed and checked. After authority, unknown valid is an error, not silently false. The source-side producer fault monitor needs its own reset/inventory walk; do not inherit trace_on as its authority. Assert that programme admission does not occur while any required monitor is unknown. This prevents the fixture from suppressing an uninitialized transaction that actual consumers could use; source startup safety itself still needs separate closure.

Track admitted/active requests from actual source command acceptance (`u_attn.ctl.guard.accepted` with the accepted identity) and actual successful run (`run && run_ok` at its sampling edge), rather than from preloaded expected arrays or scheduled A0 alone. Bind the accepted {epoch,layer,position/token} to the unique programme entry and source request. Keep source-owned issued/active/completed states and an ordered RESULT beat bitmap per identity. A STATUS must match an active source request's epoch/layer and valid payload; duplicates, unknown identity, malformed word and STATUS before required source completion/RESULTs are errors and cannot advance completed count. Never fall back from an unknown STATUS identity to kva_nst or index0. Valid error STATUS can terminate an owned failed request but cannot count as successful retirement. Keep raw STATUS count separate. Preserve unchanged case dates and deadlines; add explicit PROGRAMME_EXECUTED checks so a poisoned completion count cannot skip programme execution.

The seq-request detector must set its previous-value state from the first authoritative valid sample, not consume unknown startup rising edges. A first-authoritative asserted request is a real request and must not be discarded by that initialization. K/V pending response queues must remain empty before their own frontier; after that, every real sampled request is queued at the original measured LG with unchanged payload identity and row checks. Do not reset queue counters at A0. A real reset needs an explicit source-owned cancellation rule and no accidental response replay; retain any violations.

Required minimum controls before fixture adoption:

1. Actual arbitrary initial relay state plus original kind14/STATUS startup replay: no transaction mutation before knowledge arrives; raw evidence retained. Removing knowledge guard must reproduce poisoned count/PROGRAMME_EXECUTED failure.
2. The same malformed STATUS on the **first known output edge**, idle and before trace_on/A0: require error and no retirement. A mutant that gates until trace_on/A0 must miss it and fail this control.
3. Real owned acceptance/run with valid and wrong/duplicate STATUS identities; only exactly one valid matching completion advances successful count. A mutant restoring fallback-to-next-index must fail.
4. Reset assertion between clocks, reset first sampled on a clock, repeated reset during pending responses, and all actual variable path depths: prove old-D/NBA tag order, no post-initialization blind interval, no phantom queue response or hidden malformed record.
5. Runner verdict parser: rc0+preserved SMOKE_FAIL rejected; exactly one SMOKE_PASS accepted; missing, repeated or conflicting terminal verdict rejected. Exit status remains an independent prerequisite.

These controls are proposed, not executed. Keep original failure logs immutable and use a separate default-off fixture/harness revision. No RTL repair, changed schedule, timing mask or new full vehicle run is included here.
