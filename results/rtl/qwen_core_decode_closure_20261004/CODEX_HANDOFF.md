## If the route misses on the issue loop (d_chase_n -> chased -> issue -> LOAD -> la_rd / fq_n / run_*)
Try these zero-latency options in order:
1. Duplicate `issue` per consumer group (pointers / control registers / unit go). One kept copy already feeds the
   lm_head argmax update.
2. Register the per-unit selection of the chase source at LOAD (one-hot), so the comparator output feeds an AND-OR
   instead of a mux.
3. Only then consider a one-cycle issue pipeline. It adds 1 cycle per issued op: report the cycles added and recompose
   the 8K AR/DSpark rates (results/rtl/qwen_dspark_system_20261004/ctx8k/step_composed_ctx8k.json).
