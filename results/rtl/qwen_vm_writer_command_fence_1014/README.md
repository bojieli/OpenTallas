# Distinct command admission fence and actual writer composition

The new default-off command helper retains the actual474-bit SU command bundle in one entry. A lease request blocks NEW command offers. Previously accepted commands still launch and drain; a waiting lease cannot strand its own old command queue. Lease guard requires no pending command, no same-edge writer go, the producer's future-strobe certificate, and no actual memory commit pending/current event. Lease active blocks new writer commands until matching global release input. The helper never carries or masks posted writes. Logical state for CMD_W474 is478 bits (descriptor474, pending1, launch_busy1, lease_active1, fault1).

The launch_busy flag prevents a posted/OS-delayed ready from launching another queued command until the actual future-strobe certificate returns. The helper unit proves held descriptor versus changing incoming offer, old queue drain, future writer certificate, current/pending commit, and lease release. Four mutants (ignore drain, use offered descriptor, admit new offers while acquisition waits, use stale posted ready for a second launch) fail. This is a functional candidate; ready/go/guard are combinational faces and have no registered physical/CDC/gating adoption.
