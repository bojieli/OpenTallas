# Table lifetime correction model

Source vehicle: exact gate2 d9ef2759827ab649e467ad5cb7e171f3e97c696f FANOUT_SAFE table block; no full arithmetic or latency change. Four logical rows `{set,which}`, three config transfers per row, twelve physical 32x64 banks. All four rows are programmed explicitly with nonzero words before qualified comparisons; `OT_MEM_NO_INIT` disables the macro's otherwise artificial power-up zeros. Reset clears guard state, not SRAM data. Cold launch before complete config has no RTL validity protection and remains a compiler admission prerequisite, not a proved hardware property.

Original hazard guard stores only one 3-bit timer, armed by a write matching the delayed selected row at the write edge. It cannot see a same-edge write when old hit=0 and loses writes to a future selected row while the selector pipelines. Therefore it does not implement its documented four-edge lifetime condition.

Bounded opt-in correction: one 3-bit countdown per logical row (12 FF vs3, +9 FF), arm on every base write independently of selector, guard launch with `(row_history[selected]!=0) || (same_edge_write && write_row==selected)`. Three-bit counter 4→0, no wrap. Gap0 through4 illegal, gap5 legal. Existing reset region3 has11 asynchronous-clear loads: replacement adds9, total20, below24. Selector fanout adds only four small mux inputs; write predicate drives four row decodes and same-edge comparator. Every functional write remains unchanged. No extra payload storage, ports, cycles or clock domains, and no arithmetic/reduction change. Added area/clock/logic must be remeasured before physical use; existing full-table gate is unchanged and preserved.
