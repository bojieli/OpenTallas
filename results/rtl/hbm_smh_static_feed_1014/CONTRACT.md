The opt-in `ot_hbm_accel_smh_static` successor preserves the original SM tile and backend arithmetic instances. Historical `ot_hbm_accel_smh.sv` stays byte-identical. The replacement front removes descriptor/request credits, bulk-copy ring, runtime issue sequencer, retirement-gated launch and arrival-gated advancement. Its compiler-issued S1 slots include row/tag/x-store controls, padding and format launch; packet availability and identity faults never alter issue timing.

The production shape is SUB4/LBS2/LSB16/NC8/IL8/RMAX4096/LEV4/XD128/TCK1/PIO2/RPT2. Define `OT_SMH_FC_HIER` and `OT_SMH_PINREG` consistently with the original physical hierarchy. `OT_SMH_CG` may expose the original tile wake port. The standalone command feed has no defines and accepts one 83-bit command and one 1099-bit packet per edge; two capture edges later it drives the original S1/hop-H 1082/570-bit boundaries without ready signals. Format launch has one capture edge and the compiler must schedule its native downstream format propagation before the first affected issue.

Packet bits are `{valid,tag10,scale64,weights1024}`. These are actual checkpoint scale and weight bits; metadata is not synthesized by the scheduler. Compiler command bits 82:40 are `{expected_request_valid,address32,tag10}` (observational stream), 39:30 expected packet tag, 29 expected packet valid, 28:26 `{format_launch,format2}`, 25:0 `{issue_valid,first,last,row12,group_last,slot3,xaddr7}`. xaddr already includes the compiler's activation base. The separately scheduled xwrite interface preserves the existing 2048-bit data, address7 and group7 path.

`ot_smh_calendar_static` is a real 1024x256 SRAM programme reader, defaults W83, magic c7a1, PC identity at233:224, payload82:0 and reserved bits zero. Its launched [base,limit) range loops gaplessly; first programme output is start+4 edges. It is a source implementation derived from the VM static calendar, qualified separately by the calendar component verdict. Do not confuse its configured programme contents with a completed SM compiler schedule.

Qualification remains incomplete: the committed component gate covers only production-width S1 packet/control transport (4096 consecutive lines, II1, two capture edges) and a rejected data-bit mutant plus missing-arrival fault without stalling. It does not prove numerical SM arithmetic, whole32SM operation throughput, die closure, per-token cost or compiler schedule completeness. The existing immutable SM production prices are unchanged. INT8 format3 conversion requires a native fixed-schedule converter and is currently rejected through ENABLE_INT8; Qwen qualification is outstanding. Front physical partitioning and signed timing closure are outstanding; do not replace accepted masters or claim a closed die using these new fronts.

The `ot_hbm_accel_smh_programmed` wrapper joins the actual SRAM source to the actual SM successor. Its first calendar is start+4 and first original S1/hop-H bundle is start+6; xwrite and packet producers must already be scheduled at their declared ports. `tools/hbm_smh_static_program.py` encodes proven calendar cycles into real programme words; it is an ABI encoder, not a replacement for the required operation/memory scheduler. The full arithmetic top elaborated with exit0 before unused parameter cleanup; the retained lint log contains inherited arithmetic select-range/width/UNOPTFLAT warnings and is not a clean child-lint or closure verdict.
