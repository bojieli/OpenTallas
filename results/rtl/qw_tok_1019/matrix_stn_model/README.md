## Why kc=1 is the honest minimal port

`dv_bench.l6_parts` computes only the completed cluster sum after all K terms. `dv_lower_mat_bench.drive` injects that one final eight-word block per pair. Therefore its input stream has **one** block per reduction, even though the underlying matrix has K/split=8 (QKV) or 32 (GU). Setting kc=8/32 without also expanding the input produces no selected results. Setting kc=1 exactly describes this final-cluster boundary. The proposal supplies kc=1 at both lowering calls and both calibration calls. The unchanged default-off external packet must label this scope before replay; no production compiler should infer native kc=1 from matrix shape.

The completed vector packet did not stage `stn_ages.json`; it is an additional exact dependency from overlay `416cd1a11`. Its historical values are l8_ar=26, ar_hop=2, xc_cc=2, amax_ami=3, arx_after_amv=3. Restore its exact blob in a fresh isolated snapshot and retain its historical provenance. Do not relabel it dh2 calibration. On replay, compare every actual output edge and fault against that unchanged contract; a mismatch is evidence to preserve, not permission to edit ages.

The final-cluster programme keeps its existing command-chain arrival 2s, STN lead six edges before first far word, near lead fourteen, and last-round drain window. QKV/GU each have one full-shape round. At their current t0=400, far words are edges 400..407; STNs land at 394 and enter at 394-2s. Earliest entry is 372, so the command-to-last-input span is 35 elapsed edges (36 inclusive). These are compiler-contract edges, not measured completion latency or physical phase. Readback SU copies and prelude tables are bench observation/setup and must be reported separately from operation latency. Keep their exact events; no invented zero-cost programme deployment.

## Golden arithmetic and source identity

Recorded input identity is TP8 die 0, layers L0/L1, P8191. Four QKV/GU NPZ hashes are inherited from `28ebdeac7/fixtures.json`. Inspection on ep7 found QKV w=(768,4096), GU w=(3072,4096), signed int8; x FP32[4096], BF16-valued row scales, FP32 ISA gold_y and a split field. No OD NPZ exists in this staged directory. OD must wait for its independently pinned TP8 raw partial fixture; TP4 partials cannot substitute.

Arithmetic is exact binary32 RNE with gradual underflow and canonical +0, with separate multiply and add rounding. First round x to BF16 RNE (`b+0x7fff+tiebit`, low16 zero). Split K into contiguous chunks. For each chunk start at +0 and sequentially add rounded w*x products in increasing K order. Reduce 64 chunk accumulators by the canonical pairwise tree to each cluster. L7 adds cluster pairs, L8 adds those pairs, L9 adds the two station halves. Multiply the finished sum by its BF16 row scale with a separate FP32 rounding. GU emits gate then up; QKV retains Q/K/V fixture row order. Never commute the K accumulation, fold row scales into weights, use FMA, or manufacture gold from DUT output. Every final cluster expectation must independently match the recorded gold_y before RTL execution.

Native running-stream expansion, if pursued, must retain the **same full K/split accumulator** at each k step, then reduce those current accumulators by the same 64-way tree. Recalling `l6_parts(w[:,:short],...)` is wrong: it changes contiguous chunk ownership. K indices, row order and eight-word interleave must come from actual tile source and fixed issue waveform. Reusing the final value as earlier blocks would make last-k controls hollow.

## Finite run proposal and causal controls

After ROOT review, four recorded positives (L0/L1 QKV/GU) on each existing binary give eight positives, comparing all 768/3072 ISA output words per cut. Require actual RTL execution, nonempty event/log files, no fault, station idle after drain, every word bit-exact, output address/edge checks and complete NU1/NU4 trace comparisons. Reuse the hash-pinned binaries exclusively and reject automatic build fallback.

For final-cluster cuts, existing sbase1 must cause wrong-scale words; an intentionally wrong kc=2 must cause absent results or busy/word-count failure (this verifies configuration dependency, not native last-k). Shift one near block by an edge to require pairing fault; configure the next STN before prior drain to require a specific address/count/data failure. A row-scale-before-tree or sequential-instead-of-pairwise mutant must first be shown to differ from the actual recorded operand/gold bits before acceptance as a rounding control; if it does not differ, record it as noncausal rather than claiming a witness. Keep early-bit mismatches and failing logs. No control that exits during lowering/import counts as a numerical failure.

Native last-k acceptance additionally requires actual earlier accumulator blocks and explicit kc-1/zero-field faults selecting the wrong block or producing too many words. MUT14/MUT15 are not present in the fixed MUT0 binaries: do not claim those RTL mutations were run through them. Command mutants can use the existing binary; RTL mutants require separately reviewed builds. Nonzero user plus independent kc is a field check unless downstream context observations prove more.
