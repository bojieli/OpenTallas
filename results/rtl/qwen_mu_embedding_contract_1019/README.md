# Default-off recurring embedding identity and lifetime mechanism

The isolated `qfd_mu_embedding_ledger` captures the validated accepted tuple per user, snapshots that tuple at a compiler fetch slot, and holds the snapshot for every expected-word slot until release. Consume must carry the same user/token/epoch. A later accepted tuple may update the user's next-token bank without changing the resident snapshot. Fetch/consume/release are static inputs: faults never delay or suppress them. No production instance or enabled ABI is changed.

The local microarchitecture model in contract.json has 179 state bits (136 bank bits, 4 valid, 36 resident identity, 2 reservation, 1 fault); no new payload memory, MAC, transport queue or runtime arbitration. Four-way identity selection and 36-bit equality comparisons need physical implementation before timing/area adoption. Logical mechanism adds zero edges; an eventual registered boundary costs its actual landing edges, still unpriced. This is a mechanism model, not a unified production admission or token-rate claim.

Native proof instantiates the actual qfd_native59_dv_service, qfd_embedding_word_provider, preload face, and actual 64x512 SRAM functional model. Released checkpoint rows are existing token0/65536/151935 vectors; no invented payload or early-row production fixture. Each independent row runs user0,1,2,3 then reloads all four with epoch+4. The user0 next-token bank changes after consume while the original row remains readable. Synthetic round offsets in contract.json are explicitly a minimum mechanism bench; they are not the production OVL/FACE/INIT schedule.
