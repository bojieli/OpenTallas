# Layer-parallel exact full-token check, Qwen3-8B ROM TP4 (2026-10-03)

The tool is `tools/qwen_rom_layer_parallel_sim.py`. It cuts the RTL exactness turnaround for a full
Qwen3-8B ROM token from a serial chained run to about one layer of wall time.

- **Serial reference:** 36 layers plus the head, 171,090 cycles. The retained TP4 run took 131,331 s
  (36.5 h). Estimates from the observer rate are about 23 h.
- **Layer-parallel:** each stage runs as its own job, entered from the golden checkpoint. The
  per-stage proofs are then chained.

## Proof structure

Job k preloads `x = golden exit(k-1)` into vector-memory words 4096..8191 on every die. L0 instead
gets the golden embedding preload. The job runs stage k alone from reset and checks two things:

- `RTL exit(k) == golden exit(k)` bit-exactly on all four dies.
- For the head, it checks the token id and logit bits instead.

Since `golden exit(k-1)` is the input of golden stage k, the stage proofs compose into the full
token. This holds only if a stage's result depends on nothing that the job does not reproduce. The
chained run carries three kinds of state between stages, and each is checked as follows.

- **Vector memory and KV (memories).** The job's host is an *audited copy* of the pinned host.
  - The pinned `rtl/test/qwen_rom_runtime/qwen_rom_rt_w12.cpp` is unchanged. The copy is generated by
    `emit_host` at build time and gated by `RT_DEP_AUDIT=1`.
  - For every stage and die, the copy records every VM or KV word read *before the stage wrote it*,
    and every word the stage wrote. It writes the full sets to `<stage>_die<d>_dep.txt`.
  - `--verify` rebuilds the chained entry state: the preload, plus the write sets of all earlier
    stages, plus the KV zeroing at each `kv_reset` stage.
  - It then requires that no pre-stage read outside the x window, and no pre-stage KV read, touches a
    word an earlier stage wrote. Every such read therefore sees the same value (zero) in the isolated
    job as in the chained run.
- **Writes landing after `done`.** After the last stage's PASS line, the audited host clocks 512 more
  cycles and counts VM/x/KV writes (`DRAIN`). A write into x after the dump would reach a chained
  successor but not the golden exit, so `x_writes` must be 0.
- **RTL registers.** Every stage starts via the sequencer's `start`/`h_start` from `S_IDLE`. The
  sequencer reloads token, position, segment and descriptor state there (`rtl/rom/ot_qwen_tp_seq_w12.sv`).
  - Each stage's cycle count must equal the chained reference.
  - An isolated stage counts one cycle more than an `h_start` entry. The wrapper's start pulse is
    counted from cycle 7 but sampled at cycle 8, so `isolated = chained + 1` for k ≥ 1.
  - Two supplementary *pair* jobs (`L18+pair` = L17→L18, `head+pair` = L35→head) chain two stages
    from a golden entry. The second stage of each pair is entered exactly as in the full chain.

The composed total is `7 + sum(chained stage cycles) + (stages - 1)`, with one host cycle per image
switch. `--verify` checks it against the reference's 171,090.

## Records here

- `lp_build.json`: build record from the large VM.
  - Pinned source commit `103d3ec89` (clean worktree).
  - Driver arguments, Verilator models and both host binaries' sha256.
  - `link_reconstruction_byte_identical`: re-linking the pinned host with the tool's reconstructed
    link line gives the driver's binary byte for byte.
- `smoke/`: the default-identity smoke and the head smoke.
  - Identity: L1, 600 cycles. The pinned binary and the audited binary give identical stdout (timing
    fields stripped), both with the audit off and with it on.
  - Thread scaling: 1/2/4/8 threads.
  - Head smoke: a full head from the golden L35 exit, giving token 50994 / `419c72b5`.
- `plan.json`: 37 single jobs and 2 pair jobs.
  - Entry and expected-exit sha256 for each job, fleet, host assignment, and amendment.
  - The PVE1 build was too slow on that shared host, so its 13 jobs moved to the large VM before
    they launched.
- `verdict.json`: the per-stage results.
  - Exactness, faults, cycles against the reference, audit summary and DRAIN.
  - Image sha256 hashed on the host against the retained record's 740 pins.
  - Chain links, entry-state composition, composed cycles and wall times.
- `jobs/<stage>/`: each job's `token.log`, `launch.json`, `exit.json`, `time.txt`, `image_sha256.txt`,
  `stages.txt` and `*_dep.txt`. The exit vectors are not copied; their sha256 is in `verdict.json`.

## Replay / reuse on another design (e.g. a branch's full-token gate)

```bash
# 1. build once per host, from a pinned clean worktree of the branch (models via the unchanged driver)
python3 tools/qwen_rom_layer_parallel_sim.py --build --workdir BUILD --source-root WT -- \
  --tp 4 --groups 6144 --count-width 18 --su-width 64 --lv 7 --smin 7 --smax 11 --tcut 7 --bd 41 \
  --xvm 1 --nws 5 --tws 38 --ord 7 --mem-extra 1 --scale-local 0 --code-banks 5 --coll-lat 339 \
  --coll-depth 1024 --jobs 24          # plus the branch's own opt-in flags, e.g. --enable-ar256
# 2. plan: stage list (same format as the token driver), ISA oracle dir, L0 preload, fleet JSON
python3 tools/qwen_rom_layer_parallel_sim.py --plan --plan-dir PLAN --stages stages.txt \
  --oracle ORACLE --preload preload.hex --fleet fleet.json \
  --reference results/rtl/qwen_rom_TP4_terminal_20261002/original_terminal.json --pairs L18,head
# 3. launch (detached, one thread per job), watch, collect, verify
python3 tools/qwen_rom_layer_parallel_sim.py --launch  --plan-dir PLAN [--host NAME] [--only L3,L4]
python3 tools/qwen_rom_layer_parallel_sim.py --status  --plan-dir PLAN
python3 tools/qwen_rom_layer_parallel_sim.py --collect --plan-dir PLAN
python3 tools/qwen_rom_layer_parallel_sim.py --verify  --plan-dir PLAN   # exit 0 iff composed token exact
```

The fleet JSON lists hosts with `name`, `ssh` (null for local), `binary`, `workroot`, `path_map`
(stage-image prefix rewrite), `slots`, `threads` and `env`. `--reassign FROM=TO --reason ...` moves
jobs that have not launched yet and records the move in the plan.

The reference record is optional. Pass it to cross-check cycles and image pins. Omit it when the
design under test is meant to change cycles, and compare the new per-stage cycles yourself.

For this run, the stage images, oracle and preload are the retained ones on PVE1:
`/home/ubuntu/w12/st_tp4_sw64/{stages.txt,sw/}`, `/home/ubuntu/w12/oracle_tp4/` (oracle sha256
`7babf695…`) and `qrom-observer-L0-review-f5-20261003-r1/preload.hex` (sha256 `11f5ae1f…`).
They were copied to the large VM under `/home/ubuntu/lpsim-20261003/data/`. All 740 image pins and
all 144 expected vectors were re-hashed equal to `results/rtl/qwen_rom_TP4_terminal_20261002`.

## Limits

- The single-preload host enters with the same x on every die. This is true for the residual after
  every all-reduce here. A design whose stage entry differs per die needs a per-die preload.
- The method checks position 0 with a per-layer zero KV window. A position > 0 check also needs the
  KV contents preloaded, which the host does not take yet.

## Results of this run (frozen source 103d3ec89, large VM, one thread per job)

- **All 37 single-stage jobs are bit-exact.**
  - L0–L35: exit x matches on all four dies.
  - Head: token 50994, logit bits 419c72b5.
  - No faults.
  - 740 stage-image pins equal the retained record.
- **Cycle counts.**
  - Every layer runs 4,669 cycles isolated, which equals the retained 4,668 chained (L0 4,669).
  - The head runs 2,999, against 2,998 chained.
  - Composed total: **171,090 = retained**.
- **Pair jobs pass.** `L18+pair` gives L18 4,668 chained and exact. `head+pair` gives head 2,998 and token 50994.
- **Entry-state composition.**
  - The only pre-stage read of a word an earlier stage wrote is VM word 0. It is read on the stream
    unit's B port at cycle 19 by instruction 0 (RMS sum of squares, `ma`/`ad`/`md` bypass, so B is unused).
  - `poison/` covers this. All 37 stages were rerun with every non-x VM word preloaded with NaN
    `7fbadbad`: all exact, token 50994.
  - The final `verdict.json` was verified with `--poison-verdict` and gives `composed_full_token_exact: true`.
  - The poison verdict's own `chain_covers…` is false only because its L0 entry is the poisoned
    image, not the plain preload.
- **Wall time.** Each job took 3,471–4,363 s, about one layer at one thread under contention. The
  run took 6,948 s from first start to last end; the 13 jobs moved off PVE1 started 42 min late. The
  serial chain took 131,331 s, so this is about 19× faster.
- **Aborts.**
  - Two poison waves were stopped early for memory: 13 jobs at 04:50 and 23 jobs at 05:26. They are
    recorded in `poison/aborted.json`; their directories were kept on the VM and the jobs relaunched.
  - After the abort, `--launch` was changed to schedule against measured `MemAvailable` and load
    (`--fill`).
