# ROWX2 transport compiler component

`tools/s81_dv/layer_prog/rowx_transport.py` implements the payload transform specified by `dsdv_svc_att.sv` and `tb_dsdv_svc_rowx.sv` at feaec58ef0. It accepts complete, actual per-owner/per-tile 513-bit export words, validates fixed rank slots, P.V head flags, tile/rank identity, reserved fields and unique ownership, excludes the receiver, and preserves every 256-bit half while pairing adjacent tiles into a ROWS PK2 frame. For 512 ranks the output is 2,048 payload words plus one header per half. Owner numbering is die + 4*stack, from selected GID bits [5:4]/[7:6]. No backpressure, dynamic issue or changed arithmetic is introduced.

CLI: `python3 tools/s81_dv/layer_prog/rowx_transport.py input.json rows.hex`. Input has `gids`, `receiver`, `half`, `tag`, `pos`, `user`, and `exports[owner][tile]` containing hex export words in pass/word order; all sixteen owners and all eight tiles in the half are required, including empty slots. Default ROWX plan NXW40/NP7/XP320 covers all 512 ranks in 2,240 entry word slots. The zero traffic is kept in booked slots.

Validation: 17 focused pytest cases PASS. Independent concatenation/decoding reconstructs every 144-bit row payload across both halves, excludes all local rows, and checks a deliberately concentrated 300-row owner distribution. Eight malformed/mutant streams are rejected: rank swap, tile change, duplicate holder, dropped slot, missing held rank, P.V stamp-field pollution, head flag change, and nonzero invalid half. Invalid coverage and resource bookings are rejected. These are compiler tests; no new RTL simulation or physical gate is claimed.

A concrete runtime blocker is exposed by `landing_reads`: existing `dsfd_dvland_pvrd` wraps its address calendar at nw=160. The 2,240-word half export reuses the same leaf rows fourteen times. Source leaf = (ordinal mod160) mod5; row-pair = rb+4*floor((ordinal mod160)/5)+2*half_index. Each incoming row pair must be read before the next write to that address, exactly 160 entry cycles later at XP320. A bulk store-all-exports approach loses data. The compiler's remaining work is to book actual XR read/send/receive instructions and all link ages against these deadlines, or to report measured required buffering/bandwidth to the plan owner. This component does NOT implement that die link schedule, does not run the ROWX data through bound leps, and does not promote attn.rows_allgather or a token to LOWERED/PASS.
