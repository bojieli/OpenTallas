# Modern native59 MCTX RoPE source successor

Source-only recovery of the actual service4 lineage at `75b9fe42b368ed74bacdd22fc451ffe15d86cc9d`, with the RoPE producer behavior from `24554dd8db42a8357010f5e809622ed151009b36` + `ff184fe2fd6b5fae8adf21da88d7dd56dac71635`. No gate, simulation, audit campaign, source adoption, or replacement of an admitted view is claimed. Existing MCTX functional evidence 4b72/4d7f and service R3k receipts predate these changes and do not qualify this changed successor.

The recovered `qfd_native59_svc` retains two real operation slots with MCTX=1: `nf` allocates, `fs` selects the front TX/Q operation, and `bs` selects the oldest back RX/completion operation. Every slot retains its actual captured `s_optag`, static service, record endpoint, and DR landing fence. The recovered qbank/flat parent and LOCAL32 publication copies are preserved; no extra context bank or global latest-context substitution is introduced.

ROPE=0 and USER_BIND=0 are the new default-off switches. Existing recovered MCTX/EMB_RELAY defaults are unchanged. ROPE=1 emits 64 EMB code reads plus one scale read at indices 0..64, then twelve invalid/read-disabled positions 65..76, then eight code reads at 77..84. The final addresses are `9723904 + emb_tok*8 + beat`, beats 0..7. Scale read is confined to index64. `ea_c` still drives its original LOCAL32 low/high address halves; all e1/e2/e3/e3b and EMB_RELAY e4/e4c validity/data/select stages remain in place. Both direct k3 and relay k4b return beat encodings normalize RoPE to 0..7. EMB_RELAY=1 retains its extra return edge; RECV_INPUTS and pin-register ages remain as in service4. The compiler/RP1 arm schedule must preserve these existing extra ages around the twelve blank output positions. New source has no closure receipt.

## Actual metadata interface

Add 2-bit `tx_user` and `rx_user` input ports to `qfd_native59_split_flat` (forwarded to `u_svc`) or directly to `qfd_native59_svc`. Enable USER_BIND=1 for the successor. Connect SF7 TX/RX scheduled metadata beside the corresponding `tx_slot` / `native_rx_v` + `native_rx_payload` / `rx_slot` bundle. Metadata passes through exactly the same optional RECV_INPUTS boundary edge and existing p_* edge as those events, with no new data stage.

At the record endpoint TX expectation is bound to FRONT `s_optag[fs][44:43]` (TAG59 epoch low two bits), not current c_user. At RX acceptance, metadata must match BACK `s_optag[bs][44:43]` and incoming record payload[520:519] (encoded epoch low two bits). Wrong TX metadata removes its expected event; wrong RX metadata removes its accepted event, allowing the existing codec timing fault to reject rather than consume a mismatched bundle. Wrong scheduled metadata also sets the existing boundary sticky fault. A later front context cannot relabel a back response. Original fs/bs static retirement order is unchanged; metadata does not permit arbitrary out-of-order retirement. USER_BIND=0 ignores these ports.
