# Provisional wrapper rendered from the recorded existing RoPE image

Kdie requested a real source for its missing include so GEN can measure geometry and relay ages while the corrected final programme is being composed. The existing compiler now exposes its own wrapper renderer, which is also still used by the final generation path. The recovery mode reads the actual08d6b6778 release metadata and admission image, verifies their recorded SHA256, and emits this wrapper with FIRST1176, ADM72/1100, BASE16 and the exact committed ROM directory. The normal renderer output is byte-identical to the previous inline implementation. A changed image is refused before output creation; existing TT-source and STATUS refusal checks pass.

The header explicitly says PATHFINDING ONLY. This older real73-record image lacks the recurring HEAD_PREP slot. The wrapper permits source/GEN work with actual implemented control logic; it does not qualify a final programme or bypass the required current source and GEN transport ages.

Reproduce with tools/qwen_tokfunc/compile_rope_pair.py --render-existing-wrapper --release-metadata SOURCE_JSON --admission-image ACTUAL_ADMISSION_SVH --out FRESH_DIR --rom-dir rtl/qwen_sys/d2d_static_20261015/ovl_release_rope. Inputs are exactly the corresponding committed08d6b6778 files named in existing_source.json.
