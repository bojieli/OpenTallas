# Actual final-layer producer binding

The production seam is **final down/combine rows -> current VP POST -> current VN G8 -> existing XFIN NX snake -> VN scale -> existing VQ XB -> existing rstop gather port -> native head input replay -> ROM head**. G64 is an older minimum arithmetic vehicle and is not the current p4l producer. No complete layer/token or physical binding is supplied here.

The exact missing operations, in execution order, are:

1. Bind each final FFN down return to its actual owning leaf-store rows. The distributed TP4 combine must perform the golden owner fold `((p0+p1)+(p2+p3))` with real VS operations and actual RS ownership. `lower_vpx.GAP_FOLD` has neither encoder nor row ownership. `GAP_POST` therefore has no legal `a1` yet. Do not substitute an arbitrary scratch row. For each of 16 slices x five beat leaves, retain the 16 FP32 y rows for its 64 elements until POST finishes.
2. Retain the real final FFN GUNIT six-row result in each participating leaf. Actual L5 sends CTL target5, word mask15: row1008=pre[0..3], row1009=post[0..3], rows1010..1013=comb[j][k], row-major. Existing VP reads five coefficient rows and 16 y half-beats, consumes real residuals through VN hr/hq, and writes four-copy h in place through hw. The measured old beat contract POST command->last hw is63 edges; current interface/landing changes must be revalidated. Do not use this diagnostic number as a newly qualified calendar.
3. Preserve the *same token's* final FFN pre row1008 through final head normalization. The final head consumes the final FFN pre_out. The next layer's entry previous-pre transfer is a separate missing operation: preceding layer FFN row1008 must reach the new layer's stores before attn NORMR and remain live until consumption. Final-head work does not solve that whole-layer gap. Attn row1000 is the wrong operand for the final head.
