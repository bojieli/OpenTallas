POSTED START repair and bounded functional evidence

`dsfd_wfc_vmx_w` previously emitted a permanently zero START bit with POSTED=1. The selected CL die wrapper uses that mode, while the static VM ignores reserved row 7fff. The repair captures the actual outgoing link doorbell and its full `{user10,token21,pos21}` payload, then emits the 53-bit sequencer input after the constant START_DELAY_S=1 serial register. The production `u_vw` instance binds that value explicitly. Missing outgoing VM availability sets a sticky fault; it does not move the pulse. Nonposted START and HEP metadata retain their interfaces.

`receipt.json` covers the real producer, a functional copy of the generator's posedge `dsfd_hstnh_53` semantics repeated 40 times, and the real `dsfd_stage_seq_static_c8`/fixed mailbox/fixed issuer. The initial die plan has 40 registered stations and 41 bus records, not 41 registered stations. The bench loads eight actual PW36 words: BEGIN, three pages for engine0(arg102938,issue0,done3), three pages for END(issue7), and SEAL. Its phase table is fixed before execution. Ideal related 3:4 clocks and a declared reset epoch provide this functional boundary.

Forty cases pass: eight source phases, eight missing-availability fault cases with the same command/KIT cadence, and eight cases each for dead START, corrupt token, and one-edge-early START mutants. Each mutant fails the observed consumer behavior. The early START mutant causes an actual calendar phase fault; this is distinct from a write-commit ordering negative. The wrong-token mutant reaches the real command and KIT pins with the wrong token. The benches compare those pins with the literal source metadata.

The mapped composition gate in `tools/s81_vm/wfc_start_vm_gate.py` additionally connects this producer to one VM-owner immutable WFC/A2F package with 128 real SRAM instances. A legitimate write and START can arrive on the producer's separate f_vw and f_cs inputs on the same fast edge; the actual FIFO enqueues the write before the doorbell. The real c8 engine0 command drives an explicitly declared bench read-pin adapter into the real VM. This adapter is a test boundary, not an actual native engine. Its result is a fresh literal SRAM payload, with no internal expected-value forwarding or golden compute.

The separate `wfc_guard_gate.py` measures actual final-write/direct-read visibility and rejects a one-serial-edge-early read by observing stale SRAM data. Its total reply latency already includes the added WFC request capture edge; the +4core/+3serial delta must never be recounted as +5core. Parameter profile is READ_PIPE4/HOP1=1 (RPE2), WFC RLAT15/RESPONSE_PAD2. Source hashes identify every consumed RTL file.

These are bounded functional proofs. Native physical images are absent. Final die clock delivery, later WFC→VM physical relays, physical mailbox capture windows, the real native engine after the c8 command, and the historical ready-driven producer/FIFO/link schedule remain outside this qualification. Any later package or final GEN that changes a normal path age needs its own exact source binding and joined proof.

One fixed-programme check (PW start_phase1) accepts source offsets0 and4 and rejects the other six with the actual issuer phase fault5. Thus the eight individually calibrated successes do not establish production admission across arbitrary phases. A physical clock/reset epoch and compiler-reserved absolute launch slot are missing. No constant extra write guard has been proven to solve this phase-binding gap. The direct-read conservative guard and its stale-data negative remain separate component facts. See fixed_programme/receipt.json.

The direct-read five-edge rule is specifically serial edge W sampling dsfd_vm_static_wfc.f_wfc[0] (final data write) to serial edge R sampling f_wfc[528] (dependent read), with R >= W+5. It does not start at producer f_vw or VM core wf_v, and includes no incoming final-die relay. Reply age21 is R to t_wfc[514] valid/data observed after NBA at serial R+21. Joined source-phase offsets and direct-read source-phase offsets are separate local bench counters; their numeric indices are not interchangeable.

Final617 bounded mapped diagnostics are terminal: the rebuilt model passed eight normal cases and rejected eight actual wrong-write cases (one source payload bit changed before the real producer). Each wrong-write failure occurs when the actual mapped SRAM reply reaches the explicit command/read-pin test adapter. The native programme emitter already refuses dispatch without evidence-backed physical_phase_qualified and phase_modulus_stream4; the diagnostic encode/PW loads used here do not bypass that production restriction.
