# Native SU VM calendar recovery (2026-10-19)

The original saved sw5e replay had no hostCP configuration or launch for VM calendar target96. Reset selectors therefore dropped every SU VM request. `native_su_calendar.py` derives the actual 187-bit selector and owner programme from the native2422-bit PGP command image, using the fixed4-edge drain, 3:4 bridge slots,2-edge LG request path and10-edge host-leaf/target/calendar publication. It loads real programme rows with the existing `cal_word`/`prog_row` ABI, completes the descriptor range scan, then launches without waiting on data. The source-defined replay patch preserves every original drive and numerical check inside the observation window and all1377 preloads, and omits only later events to fit the existing6309-event binary.

A minimal vehicle contains the saved actual CKgen,7111-edge PGP column producer, host configuration leaf, target96 + calendar SRAM,8 native VM face banks,8 LG taps and8 multirate bridges. Original44 programme commands are unchanged. A separate fixture appends16 idle commands and2 readback commands through the same real PGP. It writes16 nonzero256-bit patterns and reads all16 back exactly through the native banks/bridges, in addition to the original16 reads. No DUT force, synthetic completion or dynamic scheduling is used.

- Saved10/7 profile: **FAIL**. All8 taps fault: first read_due3579 precedes native rr_v3580; write_due3637 precedes native done_d3638. The saved native face input pin register costs one additional edge. Valid counts alone (16 reads/16 writes) would conceal this error; the fault checks remain mandatory. `native.log` preserves this failure.
- Source-priced diagnostic11/8: **PASS**,44 exact PGP commands,16 reads/16 writes and zero target/calendar/release/tap/bridge faults (`native11.log`).
- Nonzero readback fixture11/8: **PASS**,62 exact PGP commands,32 reads/16 writes, all256 bits checked, zero faults (`readback.log`).
- Missing read selectors, wrong read owner and one-edge-late calendar each **FAIL** with committed witnesses (`readback_mutant1..3.log`).

The first44 words in `readback_expected.mem` are the producer-repaired first programme from3a8b0a830; the extra18 fixture words are not an accelerator schedule change. `config.mem` uses the real four-index-bank dictionary ABI. `exact_sources` preserves the compiled saved master definitions, including actual SRAM models; `manifest.json` pins every file. Reproduce through `run.sh` on fleet Verilator5.050.

This is a component proof and an old saved-profile diagnostic, not a token, layer, die, CDC timing or release qualification. Release PGSTREAM remains18/15. No release profile is changed or automatically rebound by this work. The old saved CKgen has a139ps relative rising-edge offset after timeprecision rounding, so a physical phase proof remains required; its exact digital clocks were used here. A full successor must regenerate the actual SU compiler/calendar at its real bound18/15 profile, price all fill/return ages and loading/quiescence, then replay all original numerical checks. The old10/7 binary numerical first-record run with the additive calendar is separately pending and retains its timing defect.
