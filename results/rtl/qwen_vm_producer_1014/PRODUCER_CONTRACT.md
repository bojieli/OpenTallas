# VM producer operation lease candidate

This is isolated candidate RTL, disabled by default. It does not change the existing 149-child region ABI, adopt a physical master, or implement the complete 32-column delivery fabric.

`ot_qfd_vm_producer_lease` binds the global lifetime controller at source `ad6904156`, `rtl/physical/ot_qwen_xdelivery_lifetime.sv`. `acquire_v/acquire_ready` captures the immutable IB379, mode1, context16 and current actual commit version32. IB is opaque. A decoded native bank/address is a separate provider input; no incoming IB reinterpretation or dictionary lookup is performed here.

Acquisition reserves the descriptor/version only and issues no provider read. Every read, including the first, requires an explicit actual `query_v/query_ready` handshake after native dispatch/acceptance. Query handshakes under the same lease issue reads with new phase4/address96/root5/recipient16 metadata and opaque query_seq16. Every query must match the held context16/version32 before readiness and retains the original descriptor/context/version. A single private512 result is per-query retention, not a snapshot of the entire VM. Consequently **all native writes remain reserved from pending acquisition through matching global release**, including between queries and after output consumption. An offered loader write must use `native_write_allowed` in its acceptance handshake. Outstanding accepted writes continue draining; never stop their commit pipeline.

`commit_v` is an actual native commit event; `commit_pending` covers accepted writes not yet committed. Version increments once per actual commit edge, not per offered write or ENGINE/load step. Both must include every native write producer (ordinary banks and SU banks) before full VM composition. The supplied ROW binding observes a qualified `accepted_write` through the native three-edge commit pipeline. Its caller must exclude writes ignored during reset warmup, invalid addresses and zero masks. The native bench uses nonzero masks and legal addresses after reset warmup. This proves that ROW component, not the missing SU/X provider bindings.

Acquisition blocks new write acceptance immediately and waits for both commit_pending and commit_v to clear. Provider read request and response each use held valid/ready. Output q_v/q_ready consumes the result exactly once; core pause and load_step are not implicit gates. Metadata and private data remain stable through stalls. Matching release requires context16/version32 and real recipient quiescence; current version is not substituted for the acquired version. Global `release_v` must only be asserted after the actual recipient ledger has sealed and retired all queries. Response capture is not retirement.

`source_output_drained` indicates no pending source request/response/output; it is insufficient by itself to prove no future query remains. The lifetime controller's complete bank ledger and source schedule provide that proof. Acquisition and queries stop during explicit transport flush. Flush acknowledgement requires IDLE, no pending commits, and recipient quiescence. Reset clears local payload/state and disarms acquisition; the global transport flush fence must complete before a context can reopen.

The native ROW binding drives the existing `re/ra/rq/rqb` ports and receives actual `ro`. It does not gate the native ENGINE or modify ME timing. Registered request acceptance precedes the actual region request by one CLOCK; the region ROW result updates eight CLOCK edges after that request, and private capture occurs on the following edge to avoid the old NBA value. Its response is therefore ten CLOCK edges after binding request acceptance. The producer's separate response capture and output handshake add further edges, measured by the integrated bench. These cycles and the write reservation must be priced in the native accepted-operation cost; no cost acceptance is claimed.

Component validation covers 32 operations with two query addresses, both opaque modes, all phase bits, 512-bit held data, drain, output stalls, recipient fence and exactly-once output. Six mutants reject early acquire, live descriptor substitution, duplicate output, premature recipient release, and unsolicited retained-data overwrite, and reusing the previous query seq on a subsequent response. Seq is carried from the current accepted request, never from a resident fill. It adds 16 retained metadata bits and source seams; physical placement/clock accounting remains pending. Native ROW validation instantiates the complete functional region with eight banks (DEPTH174/LAW8), actual 512-bit writes to two addresses, and 64 ROW reads. The early native capture mutant rejects stale output. The integrated lease/native ROW bench binds these same real paths to 32 operations with two queries each.

Still required for complete adoption: actual X/SU exporters, global descriptor/provider schedule, all native write acceptance/commit bindings, complete recipient ACK composition, coherent ENGINE pause/latency equalization, exact native cost, all ABI ports and clock roots, assigned pins and physical timing. No physical fit or SS wire closure follows from these behavioral gates.
