# Opt-in coherent STATUS age guard

Final coherent73 STATUS generation must invoke `compile_rope_pair.py --status-observers`. This requires explicit nonnegative integer `kv_descriptor_to_kvn_expected_edges` and `status225_transport`, plus actual nonempty GEN paths `kv_descriptor_to_kvn_expected_path` and `status225_transport_path`. These names match the K source ledger (clarification1e1a5851e, source-only). Null, missing, negative, and unknown inputs refuse before output creation. Fourteen pure CLI checks pass, including controls that preserve legacy mode and the independent core GEN gate; existing three TT status refusals still pass.

These are separate evidence paths. `host_stages` retains the existing D2D boot/HOST O61 ingress meaning. STATUS transport is225 bits (v1, epoch16, payload208), while the local atomic HOST reader snapshot is293 bits. Snapshot width is not a transport age; operation owner/epoch is independent of STATUS receipt epoch.

The guard does not infer a KVN deadline, add a calendar frame, or price an extra normal data edge. The existing descriptor-to-header deadline remains unchanged. The actual input ages/paths and fixed schema are retained in generation metadata for subsequent playback qualification. Without the opt-in flag, generated metadata explicitly marks STATUS disabled and legacy/intermediate source generation behavior remains available.

All four new age/path fields remain null in the actual K ledger. Qualified final TT/source/GEN ages are also absent. No final73 image or replay was generated by this change, and historical595/health113/localbank4 values are not substituted.
