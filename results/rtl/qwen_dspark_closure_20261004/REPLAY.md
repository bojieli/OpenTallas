# Qwen3-8B ROM DSpark new hardware: SS/FF closure at 1.2 GHz (0.833 ns)

Scope: the hardware the adopted DSpark step (results/rtl/qwen_dspark_system_20261004, 1.516x per user at 8K)
added to the AR design. Sign-off policy: SS setup >= 0 with 60 ps uncertainty, FF hold >= 0 with 25 ps,
ORFS at WC (hold WC,BC) with ADDER_MAP_FILE off, then tools/w18/corner_sta.py on the routed odb/spef.

## Sequencer fix (zero-latency; no cycle added)
Screen (tools/risk_clock_loops_screen.py, repaired phase, ~150 ps pessimistic against routes):
ARP=0 -162 ps, ARP=1 -326 ps (kind -> rx_total -> last-beat compare -> 8-slot record demux).
LA=1 (default-off parameter; the VPRM die's SEQ_LA, driver --seq-la):
- registered last-beat / read-gate / collective-kind flags (look-ahead from the counters);
- one-hot record slot;
- argmax: the running best's order key in a register and log-depth kept-tree comparators, duplicated (best / record);
- kept prefix adders for core_next_token + row0 and the receive counter;
- vm_raddr as a running address register and c_data as a first-word-fall-through head register (the first route
  closed reg-to-reg at +51 ps but missed the 20 % output budget on these buses: -129 / -55 ps, `routes/seqvp_la1_0833`, kept).
Screens: LA1 -272, LA2 -146, LA3 -64 ps; route: closed (above).

Equivalence: rtl/test/qwen_dspark_closure/tb_seq_vp_la_equiv.sv runs LA=0 and LA=1 side by side on one random
environment (wide/AR256/short all-reduces, ARGMAX_NEXT up to and past 8 records, ARGMAX, END, back-pressure,
gaps, signed/equal logits, injected faults): 20,000 steps, 27.4 M cycles, 0 mismatches on every output (c_data/c_last
qualified by c_valid, vm_raddr by vm_re). Mutation of the head register or the key register is caught.

## Composition
No cycle added anywhere (sequencer LA is cycle-identical; accept unchanged). The 8K speculative rate is unchanged:
3,447 accepted tok/s per user vs AR 2,274 = 1.516x (results/rtl/qwen_dspark_system_20261004/ctx8k/step_composed_ctx8k.json).

## Open (unvalidated physical terms of the adopted DSpark step)
- VPOS core: the AR core's own decode path fails 1.2 GHz by 1,257 ps at SS (repaired screen); the restructure is
  results/rtl/qwen_core_decode_closure_20261004 (DEC_LA). Zero-latency VPOS fixes available once it is: register pos_r+o (8 values)
  at S_DYN so me_tiles takes a mux instead of the 18-bit adder, and pre-select the DYNS value when the instruction
  enters ir. The dynp table write (-310 ps, S_DYN only) can take a second S_DYN cycle per segment start if needed.
- KV (owner decision 2026-10-04): the REAL_MEM simulation-model service (ot_qwen_rt_kv_mp_service) is NOT
  APPLICABLE to closure. The physical multi-position KV for DSpark is the STREAM4 successor service (tagged reads +
  multi-position commit/rollback), built, screened and routed by the full-bandwidth stream. Near-HBM is not counted.
