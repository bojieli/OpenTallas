# Paired ROM publication candidate

Default-off source repair, priced before RTL in `tools/uarch_model.py::rom_spine_publication_price` and `results/uarch/rom_spine_publication_20261005/model.json`. No P&R admission, clock closure, measured power or token claim.

Two alternatives are implemented; they are not silently composed:

- E1 `ot_v41_rom_stage_q_pg_cdc_w10 PUBLICATION_CAPTURE=1` captures the complete `pv/pval/prow/pseg/pnseg/perr/ppos/busy/fault` tuple on ungated root `clk`. K1/NB2 is 128 cold-reset FF, 48.52224 um2 cell body, 97.04448 um2 placement floor at 50%, 55.549696 fF clock pin capacitance. All nine outputs move together one edge. PG scheduler outputs and the internal ownership/restore controller are unchanged. This component's actual enclosing field-return consumer is not yet selected/enrolled.
- Existing S81 capture-parent generator `S81_PUBLICATION=1` forwards top→die→tile→core→spine `CAPTURE_PUBLICATION=1`; it enrolls the new publication leaf automatically. Each selected root tuple is `{valid,row16,pos3,fp32,bf16,error}`; global field fault is captured on the same edge. R128 costs 8,833 cold-reset FF, 3,348.41364 um2 body, 6,696.82728 um2 placement floor, 3,833.363006 fF clock pins. Original root-return and metadata feed the existing finite capture via the paired outputs. The existing phase/capture controller retains BUSY ownership through actual commit/drain; it is not replaced by pipe-empty or delayed-idle credit. This is the original capture path, not the separately owned indexed/stream proposal.

Each alternative charges one edge (0.833333 ns at 1.2 GHz) per field receipt/phase, II1. Enabling both would require two edges and a new exact enclosing test. Clock tree, loaded fault fanout, wiring, slot/track fit and cell steering costs remain unknown positive additions. The selected clock relationship must come from Maxwell before route; the new register is not assumed to fix existing skew for free.

Arch's concrete source contract is `tools/dsrom_s81_capture_parent.py` plus `rtl/dsrom_sys/rd64_capture/ot_dsrom_rd64_vm_capture.sv`: actual last-write-wins `capture_vm_accept` is the only VM receipt; `rows_left` debits accepted writes; terminal requires `capture_drained`; capture fault propagates through existing C8 write quarantine/fault and visibility gates. Aligned global field fault or valid root error drives the existing capture warm-quarantine request. That request inhibits all VM valid ports, latches sticky capture fault and preserves held phase identity, expected/received/committed counts and stored debt. No reset, fabricated ACK, cancellation receipt, rollback or ledger is added. Prior committed VM words remain; the faulty phase must not be consumed or retired. Cold reset still requires the original authoritative all-copy fence.
