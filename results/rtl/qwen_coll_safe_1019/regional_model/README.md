## Core cmd_free boundary ownership

The direct six-logic-level output is separately real: `ot_qfd_io_collective_static.sv` maps `cmd_free` to `u_coll.cmd_free_next`, not to registered `cmd_free`. The collective owns `{rem,cnt,s_mode}` and the pin-captured command fields. Its current combinational next-state predicate predicts availability one edge ahead because the command boundary already captures commands one edge before their internal use. `ot_coll_cmd_issue.sv` forwards this status as `available` and `end_ok` to `ot_qwen_fixed_issue.sv`; `qfd_seq_su_collective_calendar.sv` wraps that same issuer. Fixed issue is selected solely by the compiled cycle/head. Missing availability sets sticky fault; it never stalls or reschedules the issue.

**Blindly adding an output capture is incorrect.** It adds one edge of status age and can fault a legal command on the transition to free. For example, a reduce with rem2/cnt0 becomes rem1/cnt0 on the next edge, so current next-free is true while a one-edge-old registered value from rem3 was false. This is a status-contract change even though no payload latency changes.

A concrete structural choice must accompany A or B:

- A source-owned registered predictor can compute two deterministic state transitions before one output register, including both the current pin-captured command and the current external command that will enter the core next edge. The registered value then has the same acceptance meaning for the existing consumer as today's combinational one-edge predictor. It adds exactly one boundary capture flop and moves the comparison cone before that flop; it adds zero command/payload cycles **only after equivalence and actual source/consumer clock-age proof**. Full mapped area is unmeasured. It must not duplicate an asynchronously inferred state or omit the new-command overwrite, zero-word/busy-command refusal, gather count, reset or end conditions.
- Alternatively, register the existing status and explicitly delay the issuer's availability/end diagnostic by one edge, matching the issued command identity to the captured status. Issue timing stays fixed, but the fault observation and end/done audit acquire one edge. Both the generic issuer and the sequencer adapter, plus the completion/drain guard, must be composed and witnessed. Changing the shared fixed-issue core is a separate coordinated source change, not an incidental wrapper edit.

For either choice, show exact first and adjacent legal commands, 1/2/4-word reduce and gather, idle-to-busy and last-word-to-free transitions, zero-word and busy-overlap refusal, both reset orders and stage end. Check issuer-specific fault edge and identity, rather than accepting a later aggregate collective fault as equivalent. Include an uncompensated-status-register mutant. The actual physical source/consumer root phases remain part of the contract. No source has been retimed, and no status capture edge is silently included in the current live gates or in the LU/LS compiler rows.

The native core census10,190-flop/large-outline warning remains advisory. Actual propagated TT/FF pin-flop spread and linked references decide clock acceptance; the separate cmd_free boundary-registration obligation remains open regardless of that result.

The core's second non-flop-driven output is `fault = |fault_code`; `fault_code[4:0]` already comes directly from the five sticky `{f_cf,f_ln,f_pr,f_md,f_ar}` registers. This shallow reduction is separate from the six-level cmd_free path. It does not alone require another data pipeline stage. If actual reach or the selected physical boundary requires a registered aggregate, capture **the complete six-bit `{fault,fault_code}` status bundle** together: one additional diagnostic edge, six boundary flops, no normal command/payload cycle. Registering only the aggregate would change its same-cycle relationship with the cause bits. The completion/end/drain proof must wait for the last possible fault observation, including any new regional fault-return crossing; current live source and timing are unchanged. Likewise every TX/RX regional abort/cause/PHY-up fault bundle needs an explicit source and destination age in the selected implementation; those diagnostic ages cannot be silently called zero or used to gate a different issue calendar.
