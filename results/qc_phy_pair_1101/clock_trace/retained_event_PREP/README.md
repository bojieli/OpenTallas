# Disabled retained-event CDC alternative

Source/model proposal only. The native SAFE0/SAFE1 witnesses and all actual833/1000 failures stay intact. No RTL selection, public-port change, calendar emission, clock alias, full compile, physical gate or adoption is performed.

Existing actual primitives are `rtl/lib/ot_cdc_mailbox.sv` (one-outstanding four-phase request/response with stable payload and src_ready) and `rtl/lib/ot_async_fifo.sv` (power-of-two Gray-pointer FIFO, minimum depth4, two-stage pointer publication and online/reset rendezvous). `ot_reset_sync.sv` is their native reset conditioner. `ot_rom_link_cdc.sv` supplies a different open-loop idle-rate contract; its default ppm-scale idle rate cannot fix a20% core/FDI frequency difference and is not selected here.

The smallest throughput-capable proposal uses the existing async FIFO to carry the **actual native slot descriptor `{version,addr[5:0]}`**, seven bits, rather than sampling a pulse or advancing unrelated counters. On a source event, descriptor acceptance must also control the real source data write. The destination consumes one accepted descriptor per FDI edge when ready, and its read address/version come from that descriptor. Existing same-domain codec tails can remain explicit fixed tails; the clock crossing becomes queue/phase dependent and must be repriced. This is an additive disabled candidate with a new explicit handshake/overflow contract, not a replacement hidden behind the current port signature.

Two integration choices require a coherent source event:

1. Retain each request/data until `src_ready` and advance the compiler/controller only on acceptance; return ready or completion through the actual controller interface. This changes the source interface/calendar contract and must price the feedback paths.
2. Keep the current public one-cycle compiled slot ports and prove every offered event arrives when the queue is ready under all permitted phases/resets/bursts. Add a real sticky overflow/fault path for `raw_slot && !ready`; never silently acknowledge or overwrite it. Current token owner explicitly confirms **no qualified15FDI/95FT spacing/burst bound exists**, and old59P/global dates cannot supply one. This option is therefore HOLD.

The primitive's `wr_overflow` is reset-only in this ready/valid implementation: holding valid while not ready is legal. It cannot diagnose loss of a non-retained one-cycle compiled event. The proposed adapter must add its own sticky raw-offer-not-ready detection and route it into a real fault/abort path. A disconnected debug flag supplies no correctness credit.

Rate condition at core833ps→FDI1000ps: accepted average source events/corecycle must be ≤833/1000 even with a destination accepting every edge. Thus at least167 of every1000 source cycles must be idle asymptotically; this is necessary, not sufficient. A finite four-entry FIFO cannot absorb sustained1/corecycle. Finite bursts, pointer-publication delay and reset readiness must satisfy the actual ready signal; no four-event burst guarantee is inferred solely from DEPTH4.

With both domains already online, no queued predecessor and destination continuously ready, the default FIFO publishes a newly accepted source descriptor through two destination pointer synchronizers, then registered nonempty; the downstream consumption is the fourth destination edge after the write. Ideal RTL latency is `(3*Tdst,4*Tdst]`: at1000ps, `(3000,4000]ps`, or `(3000/833,4000/833]` core periods. Queueing adds whole destination service edges, and stalls add unbounded delay unless bounded by contract. Coincident edges and physical setup/metastability aperture remain unqualified. This latency replaces the old KC crossing, not an added constant borrowed into the old LS436. Preserve/priceseparately TX same-domain tails r_slot→wr_v4FDI and wr_v→rd_vKW; peer RX prediction must use actual accepted TX timing/identity or a new proven schedule bound. A lossless event queue alone does not qualify fixed peer RX arrival calendars.

Reset proposal: use EXT_RST0 and the same asynchronous source on both FIFO reset inputs. Either-side cancellation flushes queued descriptors with independently conditioned releases and online rendezvous before admission. Reset also flushes the associated real data ring/controller epoch. No request replay after cancellation is claimed. Mailbox has a distinct destination-reset replay contract and requires a matching destination reset/idempotence rule; that is why it is an alternative, not an interchangeable implementation.

Raw declared state for one DEPTH4/W7 FIFO:28 payload +12 local binary/Gray pointers +12 synchronized pointers +6 online/rendezvous +2 full/empty +2 reset-only flags +4 internal reset-conditioner =66 bits. A separate raw-offer sticky bit with its own conditioned reset adds3, total69 declared bits. The old token landing declares11 bits, giving a preliminary +58 declaration comparison per crossing. Reset-only flags and memories may optimize; mapped FF/area, any replaced counter savings, physical synchronizer placement, MTBF, source parent/root reach and all15/95 instance totals are unqualified. No source gate or actual area credit is claimed from this count.

Reviewable next finite gate, after interface choice: exact existing FIFO/reset source + additive descriptor adapter, arbitrary phase sweep833/1000, all accepted sequence/address/version ordering, deliberate downstream stalls, repeated levels as consecutive events, reset cancellation/no ghost, and explicit offered-when-not-ready fault. Mutant removes ready retention or changes descriptor bit to prove the witness is live. No whole QC build. Qualified compiler arrival/START/fault/interface pricing and both real PHY/provider clocks remain required before adoption.
