## EOS and measured decode behavior

An exact replay of the retained 32-token chat, including layer-hash capture,
reproduced result
`3162857610517ebeef7b79028d0a720f8b0ed0e5c5d5f0675226ed5904cfeb32`
and took 48.47 wall-clock seconds on the local RTX PRO 6000 Blackwell. That
measurement includes model loading, the 11-token prefill, and 32 greedy output
selections; it is not a steady-state throughput claim.

The EOS campaign sets 800 generated tokens as a warning threshold and 8,000 as
the requested hard maximum. Each prompt is additionally bounded so prompt plus
committed decode context never exceeds the deployment's 8,000-token product
limit. The six retained results were:

| Prompt | Generated tokens | Wall time | Official EOS |
|---|---:|---:|---:|
| arithmetic | 4 | 5.511 s | yes |
| geography | 8 | 10.126 s | yes |
| science | 46 | 54.779 s | yes |
| computer science | 81 | 95.658 s | yes |
| practical advice | 182 | 213.743 s | yes |
| reasoning, thinking enabled | 1,052 | 1,245.575 s | yes |

The reasoning case crossed the 800-token warning threshold, but reached token
151645 (`<|im_end|>`) at 1,088 committed context tokens. All other cases reached
the same official EOS within the warning threshold. Campaign ID:
`783d61ef54052728a514c88c94f1b2c45d9961696c2eae65af7e49692ae9e020`.

## Bash-only TerminalBench agent

`tools/run_qwen3_terminalbench.py` renders the hash-pinned tokenizer's official
Qwen3 tool template, advertises exactly one strict `bash(command: string)`
function, parses `<tool_call>` JSON fail-closed, and returns command results as
tool-role messages rendered into `<tool_response>` blocks. It re-renders the
complete transcript for every turn because the compiled greedy service owns a
fresh KV session per generation call.

The retained campaign pins TerminalBench commit
`d28711d0da2675d0bb1d56de45ae5df6082438a3` and passes:

| Task | Model turns | Bash actions | Generated tokens | Wall time | Withheld official tests |
|---|---:|---:|---:|---:|---:|
| `hello-world` | 2 | 1 | 64 | 77.299 s | 2 passed |
| `fix-permissions` | 3 | 2 | 92 | 111.720 s | 1 passed |

Each task runs in a fresh container with no network, host bind mounts, elevated
privileges, or retained Linux capabilities; it also uses `no-new-privileges`
and bounded PIDs, memory, and CPU. Test and solution files are not present in
the agent-visible build context. The harness copies only the pinned official
test module into the container after the model terminates, runs it separately,
retains the complete model/tool transcript, and removes the container in all
exit paths. Campaign ID:
`853bced4fdbc0ed88519678e8b92d22c7059fb9a8c10226525e182d81e22c17b`.

The agent campaign deliberately uses Qwen3's official non-thinking template
mode. Tool calling is supported in both modes, while the pinned Qwen3 model card
warns against greedy decoding in thinking mode because it can repeat. This
compiled runtime is greedy by construction; the separate EOS stress campaign
still exercises thinking mode and records its longer 1,052-token completion.

## What “end to end” means here

The executed path begins with validated token IDs, performs an embedding lookup,
all 36 attention/MLP decoder blocks, atomic per-layer KV commits, final RMSNorm,
and the untied vocabulary projection. Greedy host selection feeds the selected
token into the next one-token decode span. Context overflow is rejected before
any KV state changes.

This is not a two-matmul proxy: each span executes 253 matrix projections, 145
RMSNorm operations, 36 RoPE applications, 36 grouped-query causal attentions,
36 KV commits, 36 gated SiLU MLPs, 72 residual additions, the embedding lookup,
and final-token selection.

Before state commit, the service independently reconciles static graph counts
and dynamic context-dependent work. At the 8,000-token boundary the certified
expectation is 111,133,523,443,712 matrix multiply/add operations,
18,876,727,296,000 attention multiply/add operations, 11,239,424,000 vector
elements, and 1,179,648,000 logical KV bytes written and read. A counter
difference aborts the span and clears its prepared KV ranges.

The functional result does not close the recovery plan's RTL/co-simulation,
target-node PPA, schedule timing, power, thermal, or manufacturability gates.
No throughput or product-silicon claim should be inferred from it.
