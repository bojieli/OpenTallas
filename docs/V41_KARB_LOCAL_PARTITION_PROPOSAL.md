# Local HBM K arbitration proposal

Status: root approved an opt-in functional prototype and slice characterization on 2026-09-29; not an adopted production timing change. Base revision: `86b85fc480db8171ddd4a4057d04c8b4ca220424`. No RTL changes or physical jobs accompany this document. Machine-readable dimensions and source hashes: `results/physical_abi3/asap7/chip/v41x_hbm_karb/local_partition_proposal.json`.

## Failure and actual scope

The old standalone NPC32 square exposed 40,332 signal pins to 5,008 positions. Its 52,812 cells occupied 4,847.56 um², whereas satisfying the reported 3,871.87 um perimeter with a square would require approximately 0.94 mm². The 12,000 x 30.24 um strip passed pin placement but was stopped on PVE2 at 2026-09-29 06:06:56 UTC after 75,425 seconds, >219,000 placement iterations and overflow approximately 0.88 versus initial 0.77. It consumed 48.4 GiB RSS. This establishes failed placement convergence under that setup; it does not establish that all strip layouts are impossible. Evidence directory: `/home/ubuntu/v41-route-recovery-20260929/karb-strip-20260929T060623Z` on PVE2. Last usable checkpoint remains `3_2_place_iop.odb` in the original work directory.

The actual arbiter is `rtl/chip/ot_chip_v41x_hbm_karb.sv`. Each PC has independent round-robin arbitration between B (pooled index) and K (KV), a requester tag bit, and two 8-bit write-outstanding counters. B responses are local pass-through. K requests broadcast 337 payload bits at AW28, and K responses select 276 payload bits from 32 PCs. Its global lowest-PC priority mux and ready path cross the whole strip. `rtl/chip/ot_chip_v41x_die.sv` instantiates four such arbiters. `ot_chip_v41x_hbm3e_phy.sv` remains a behavioural controller/stack model; the K and W traffic groups have separate model timing and do not prove shared physical bandwidth.

## Proposed hierarchy

Use 32 identical arbitration slices per stack, arranged in eight adjacent groups of four. Each slice owns one global PC_ID from 0 to 31 and keeps its B and H buses inside that PC's 375 um PHY window. Keep `GLOBAL_NPC=32`: `pc_of(addr)=((addr>>2)^(addr>>7)^(addr>>12)) & 31`. Region is PC_ID[4:2], local index PC_ID[1:0]. Never instantiate the existing NPC4 arbiter as a functional substitute: that changes the address hash.

At the K ingress, decode once and send a unicast request to one of eight regional endpoints, then one of four local slices. Propose one registered request stage at the stack ingress and one at the selected regional endpoint. Each stage needs two entries, with explicitly verified registered backpressure; full payload, write strobes, tag, length and target PC must be retained. Preserve per-PC acceptance order across reads and writes. Request queues create a new acceptance boundary: k_rdy means buffered ownership, while local arbitration and its counters update only at actual h_v && h_rdy. Request forwarding must not bypass an older request to the same PC. For the prototype, add an explicit per-PC K read fence: no K read reaches h_v while an earlier accepted K write on that PC is still queued or lacks PHY wr_done. Track queued writes separately from issued write-owner counters, so ingress acceptance cannot erase the dependency. Fence clearance requires the actual completion event, not an enqueue/pop. This is an additional proposed service constraint requiring root approval; preserve B protocol and its own existing completion discipline. Global K FIFO ordering prevents a later read overtaking a prior write en route to any region.

On K response, each regional endpoint selects one of its four local PCs into a two-entry registered response queue. A registered stack egress selects among eight regional queues, also with two entries. Keep B responses directly local. Response payload is 276 bits (TAGW16 + BEATW4 + DW256); retained PC identity adds five bits where diagnostics/order checking need it. Once selected into a queue, data/tag/beat remain stable under stalls. Consume a PHY response only when its queue reserves capacity. No combinational ready chain may cross all eight regions.

Arbitration proposal: retain lowest-PC priority within each regional capture and lowest-region priority among ready queues. Buffer capture can change cross-PC response order compared with the old instantaneous 32-way priority mux. This requires root approval of transaction equivalence rather than cycle/merged-order equivalence. Preserve order within each PC. Existing KV consumer addresses staging by tag, entry and beat, and sets s_rdy=all ones; verify interleaving and generation handling with that actual consumer. Global priority starvation is not repaired implicitly: finite completion guarantees still require a bounded arrival contract, or a separately approved fair-arbitration change.

K write completion needs a registered event path, preserving pulse/count semantics. Current k_wr_done is an OR of all PC completions and can already merge simultaneous events; die wiring produces pk_wd but KV prefetch has no completion input. Do not silently turn it into an exactly-once counted completion interface. Keep per-PC write-owner counters local and decrement at actual PHY completion, never at request enqueue or response dequeue. Overflow bounds for those 8-bit counters must be proved against controller queue capacity.

Status totals require registered aggregation outside the data-critical path. Preserve eventual counts and document changed observation latency; do not retain a 32-PC combinational popcount across the edge. A small serial status interface is a proposed integration view, not a substitute for the existing 96-bit status outputs in an equivalence wrapper.

## Exact service implications to approve

At empty queues and no stalls, a K request accepted on edge n can first handshake at the local PHY on edge n+2. A K response captured from PHY on edge m can first handshake at the K consumer on edge m+2. Thus uncontended K round-trip service adds four cycles, and last-response slot readiness can move four cycles if the complete otherwise-identical path is exposed. At the inherited 920 ps characterization clock this is 3.68 ns; achieved frequency is unknown. B request/response adds zero intentional pipeline cycles. Its arbitration schedule can still change because K arrives later. Preserve the local rr update only when both eligible requesters contend and h_rdy grants a request; an ineligible fenced K read does not consume a turn. With both eligible continuously and PHY accepting, each obtains at least every second accepted slot. Write-ownership blocking and controller stalls are outside that fairness bound. B response ready/valid remains independent of K regional congestion unless the actual controller itself introduces shared queue head-of-line blocking.

The intended sustained capacity remains at most one K request and one K response per stack per cycle, with up to 32 B PC handshakes per stack per cycle and independent 1/cycle local H port limits. A pair of two-entry stages does not itself prove throughput: verify credit-return latency and simultaneous enqueue/dequeue maintain initiation interval 1 in the implemented circuit. Eight regional response queues plus the stack queue hold at most 18 K response beats; eight regional request queues plus ingress hold at most 18 K request records. Arbitration/backpressure and the explicit write-completion fence can add variable delay, so four cycles is a minimum added traversal latency, never a universal completion bound. For a read behind a prior same-PC write, earliest PHY read acceptance is max(request pipeline readiness, completion-fence clearance); a synchronous registered clearance normally makes the read eligible on the cycle after wr_done. End-to-end completion must charge that residual write service plus queue/arbitration delays. An unbounded behavioural controller stall means there is no finite universal service bound.

Actual `ot_chip_v41x_kv_prefetch.sv` issues reads only after all its write queues have been accepted. It counts outstanding halves on f_go (request acceptance), not at PHY issue. The proposed queues must therefore preserve write-before-read order on the same PC, propagate reset/flush ownership coherently, and ensure accepted requests eventually return or fault. Buffered responses must remain included in outstanding generation accounting until delivered; otherwise srst can recycle a generation while its data remains in the network. The index writer's wr_done ownership must also survive these boundaries.

## Ports and physical allocation

At AW28, a B or K channel has 337 request payload bits + valid/ready + write-done + 276 response payload bits + valid/ready = 618 signal bits. H adds one owner bit in each request/response tag: 620. The old top is 32*(618+620)+618+96 status+2 clock/reset = 40,332. At AW30 these become 620/622/620 and 40,462 respectively.

| Boundary | AW28 pins | AW30 pins | Notes |
|---|---:|---:|---|
| Single PC, B+H+local K+clock/reset | 1,858 | 1,864 | Internal hierarchical signals, not chip pads; excludes status/test |
| Four-PC region, local B/H exposed, one K trunk, clock/reset | 5,572 | 5,590 | Excludes status/test; hierarchy should keep B/H internal at stack assembly |
| Same four-PC region plus legacy 96-bit status | 5,668 | 5,686 | Diagnostic wrapper only |

Use full AW30 for new physical feasibility; AW28 is only historical replay. Begin with a 375 x 64 um local characterization envelope, not a claim that the die budget fits. At AW30, 622 H bits across a 375 um facing edge are 1.659 pins/um; 620 B bits on its opposite edge are 1.653 pins/um. If all 620 K bits occupy two 64 um side edges they require 4.844 pins/um before spacing/blockage/clock allowances; actual layer track capacity must be checked. Prefer regional K register banks abutting slices and internal over-cell channels, so K does not become another artificial external perimeter constraint. Overall raw perimeter density is 1,864/878 = 2.123 pins/um, but per-edge density and legal pin access are the gates.

Thirty-two 375 x 64 um envelopes allocate 0.768 mm² per stack before regional buffers/trunks. The current 12,000 x 17.2 um KV/key/staging band allocates only 0.2064 mm². This proposal therefore requires an explicit root floorplan rebudget, not an assertion that segmentation alone solves area. Region nominal spans are 1.5 mm; stack root-to-region routes can still span millimetres. Two request/two response stages are a proposed contract requiring extracted wire proof. If that proof fails, return the measured violation to root; do not silently add stages.

Physical views needed: synthesizable local slice and regional wrapper; exact port manifest with PC_ID and global hash; floorplan/pin constraints bound to the actual AW30 PHY LEF; routed slice LEF/Liberty including setup/hold and extracted parasitics at declared corners; regional queue/selector views; register coordinates and route corridors for every K trunk; controller service contract and timing views for the real shared K/W controller. Existing `physical/asap7_memory_macros/ot_hbm3e_phy_v41x_aw30/` supplies a matching assumed abstract, not a measured controller. The quarter-scale s4 PHY cannot validate full-size wire delay.

## Approval and bounded execution gates

Root must approve the four-cycle minimum K traversal change, explicit same-PC K write-completion fence, queued cross-PC ordering, status latency, 375 x 64 um study envelope, and shared-controller assumption before RTL implementation or launch. No existing selector, VM or ME physical runs are part of this proposal.

After approval: (1) check the global hash exhaustively over its 17 influencing address bits and all PCs, and prove ownership, masked writes, stable stalls, per-PC ordering and finite queues; (2) run actual KV generation/restart and pooled-index writer consumers with simultaneous reads/writes, reset, and backpressure; (3) synthesize one AW30 slice, verify legal pins against the actual PHY window, then place/route only that slice; (4) build one four-PC regional selector and prove throughput with finite credits before routing; (5) route the longest root-to-region boundary at full-size distance with neighbouring obstructions; (6) feed measured cycles, latency bounds, area and power into the shared HBM ledger before replicating four stacks. Require congestion convergence and routed setup/hold/DRC evidence at each step. Stop and return to root on a failed physical gate; no automatic giant-strip retry.

## Root prototype decision

Implement globally hashed PC slices, two request and two response stages, explicit same-PC write-completion fences, and bounded queues. Use round-robin eligible K capture at regional and stack levels to avoid starvation; cross-PC response order may change while tagged identity and per-PC order remain intact. B service stays direct. The proposed per-slice envelope is authorized for characterization only; its full-stack area and four-cycle minimum traversal must be priced before adoption. Functional ordering/credit tests precede route.
