# Public visual assets

This directory contains the public-facing OpenTallas visual set. Every asset is
generated by [`tools/render_public_assets.py`](../../tools/render_public_assets.py);
none is a photograph or an artist's rendering of fabricated OpenTallas silicon.

The figures use three evidence classes on purpose:

1. **Conceptual architecture** explains the intended organization. It is not
   physical implementation evidence.
2. **Checked simulation result** plots values from repository JSON or CSV
   artifacts. It is not measured hardware performance.
3. **Archived physical geometry** renders actual `.mag` or `.def` geometry from
   a completed local tool run. Its technology and scope are printed on the image.

## Regeneration

From the repository root:

```bash
python3 tools/render_public_assets.py
```

The renderer needs Python and Matplotlib. It parses the archived Magic and DEF
text geometry directly, so regenerating these views does not require a PDK, Magic,
KLayout, or OpenROAD installation. To inspect output without replacing the tracked
gallery, provide another directory:

```bash
python3 tools/render_public_assets.py --output-dir /tmp/opentallas-public-assets
```

Generated assets should not be edited by hand. Change the renderer or its checked
source evidence and regenerate the full set.

## Interpretation rules

- Never describe a conceptual SVG as a die shot, tapeout, placed-and-routed chip,
  or fabricated wafer.
- Never describe analytical throughput as a benchmark or measured product result.
- Never turn deterministic low/central/high scenarios into statistical confidence.
- Never scale either open-PDK slice into N7/N4 density, timing, power, yield, or
  whole-array performance.
- Never treat the ASAP7 routed block as a full stage, full chip, ROM macro, target
  numerical implementation, or foundry-qualified result.
- No asset in this directory establishes manufacturability, model accuracy,
  production economics, or silicon yield.
