# Fusion audit: dataflow levels 1-5 across the four designs

Stream FA, 2026-10-01. Record: `results/uarch/fusion_audit.json`, regenerated by `tools/fusion_audit.py` (test: `tests/test_fusion_audit.py`). Every figure below is a MODEL ESTIMATE from that record. None is measured in RTL. The product rows stay W16b's (`tools/uarch_model.py`); this audit supplies candidates for W16b to price behind the 1% gate.

## Method

- **V4.1 ROM.** The product's per-token DAG at S = 41, 1.2 GHz SS, BF16 columns, with the 0.9 GHz serial domain, W11's measured serial build and W18b's shrunk die. The graph is rebuilt exactly as `cons_v41_rom` builds it; the rebuild reproduces the main-branch product, 2,736.7 tok/s on the square C_rotate.
  - The SU network is W11's C_rotate on W18b's compact hub, in slow cycles a leg: broadcast 7, operand read 18, element write 17, result 7. An unfused op pays 42 and a reduction 32, as W16b prices them.
  - Each candidate is a counterfactual: legs are removed or dependencies rewired, and the full longest path is solved again. Overlap is honoured; nothing is added by hand. AR and the 6-position MTP verify pass are both solved again.
- **Real-program census.** `hdc_replay_v41.ShapeBuilder` at the shipped shape: embed, 40 layers and the head on one die (2,650 SU ops), plus the exact TP-4 layer-0 program with its 12 collectives. The census records which unit wrote every SU operand, which matvec-to-vector patterns dominate, and whether each reduction is local or cross-die.
- **V4.1 HBM.** W19's executed TP-96 program (`results/rtl/w19_hbm_tp96_program_oreduce.json`), priced with W19's own W15b P=48 NVLS formula and W19's node prices.
- **Qwen3-8B ROM.** The calibrated sequencer replay at the product SS point. A folded op is replaced in place by a one-element op that keeps its waits and barriers. The range's low end adds the epilogue's pipeline depth back.
- **Qwen3-8B HBM.** The reference dependency chain, measured against the HBM token's cycles.
- **Exactness classes.**
  - A: the same operations in the same order.
  - B: a different schedule that the golden mirrors exactly. Example: the golden's chunk-8 / RMS_SPLIT tree rebuilt on a stream with a log-depth stack of partials.
  - C: changes rounding, so it needs a contract change and a quality check. **C items are user decisions; levels 6-7 are excluded (AGENTS.md a4f314fb).**

**Level 4 is not a gain over the model.** It is the condition for realising the model. The DAG overlaps independent chains freely. The same token on an in-order stream unit, in the graph's emission order, costs:

| SU issue model | AR µs | AR tok/s | vs. the DAG |
|---|---|---|---|
| the DAG (free overlap) | 352.4 | 2,838 | — |
| pipelined (an op issues once the previous op has issued) | 389.4 | 2,568 | −9.5% |
| blocking (an op waits for the previous op to finish) | 439.4 | 2,276 | −19.8% |

So the compiler must interleave the independent chains (level 4), or every row above is optimistic. The off-path SU work is 92 µs against 147 µs on the path (ratio 0.63), which is the room interleaving has. W11 reports that the sequencer (`hdc_program_v41.schedule`) drains the SU on every SU-to-SU dependence. That makes level 4 W11's first item, ahead of the buffer.

## The staging buffer (the DaVinci FixPipe analogue)

**What the real program needs.** 1,364 of the 2,650 SU ops take an operand straight from a matvec unit. In order of count:

| Op | Count |
|---|---|
| SiLU·up(·w) | 280 |
| expert-sum adds | 240 |
| KV writes | 160 |
| mHC sigmoid mixes | 160 |
| sums of squares | 132 |
| max | 120 |
| scale | 80 |
| RoPE | 48 |
| divide | 40 |
| softplus_sqrt | 40 |

The 240 expert-sum adds (`moe_sum`) are not in the priced graph at all. The model is right only if the w2 epilogue accumulates the experts in id order, which is class B.

**Reach on the per-token DAG.**

| | Programmable | Fixed-function |
|---|---|---|
| SU ops reached (of 1,702) | 974 (565 on the path) | 707 |
| chain starts removed from the SU network (of 706) | 500 (70.8%) | 368 |
| reductions removed (of 336) | 212 (63.1%) | 168 |

The long tail a fixed function misses is 267 ops (27% of the buffer's reach): the attention exp, den, sink and normalize, softplus_sqrt, the mHC pre/post sigmoid, and the indexer q. **Prefer programmable epilogue lanes.** W11's 4-bit `xkr_epi` can name the 15 functions the reach needs (sumsq, max and sum taps; rsqrt; scale; RoPE; FP8 and FP4 qdq; SiLU·up·w; residual / mHC post mix; bias; softplus_sqrt; exp(x−max); normalise with sink; sigmoid mix). That exactly fills it, with no room. Use it to select a short micro-program in the buffer lanes rather than a fixed unit.

**The root's pitfalls, one by one.**

1. **Tree order.** The golden sums with chunk-8 runs and a padded pairwise tree (`csum`), or with RMS_SPLIT = 8 segments of P = 8 interleaved partials. A tap that receives the stream in index order rebuilds exactly that tree with one sequential accumulator per chunk and a log-depth stack of partials, so it is class B. A streaming sequential accumulator would be class C and is not proposed.
2. **TP placement.** Of the 212 reductions the buffer reaches, 131 are local (matvec or attention output) and 81 are cross-die, after an all-gather: q_norm and kv_norm on every layer, and the compressor norm. In the exact TP-4 layer-0 program these are `L0.attn` sumsq x2 (after COLL) and `hc_post` sumsq (after the wo_b all-reduce). For cross-die reductions the buffer sits after the collective engine. Alternatively the partials ride the gather: at TP-4 each die owns exactly 2 of the 8 RMS_SPLIT segments, so one scalar a die is a subtree of the golden's tree (class B).
3. **Wire.** Only the removed VM read leg (18), the per-op broadcast (7) and the separate reduction pass are counted. Delivery into the lanes still pays the element write (17), or the broadcast (7) for a scalar.
4. **Inherent wait.** The normalised output needs the scalar first. The scale therefore runs as a second pass over the buffer and keeps its issue time; only the first pass rides the producer stream.
5. **Clock crossing.** The buffer can be the 1.2 → 0.9 GHz ratio FIFO. That removes the separate crossing on 281 on-path producer→buffer edges, an upper bound of 1.25 µs AR, not re-solved.
6. **Sizing and area.** The largest vector that has to wait for its scalar is the 4 × 5,120 FP32 mHC residual (80 KB). With double buffering that is 160 KB, five 32 KB SRAM macros (0.06 mm²).
   - Epilogue lanes: 128 light lanes plus 32 SFU lanes is about 1.6 mm². That is +4% of the 38.6 mm² C_rotate hub block, and 4/3 the producer element rate for the clock ratio.
   - Placement: it sits at the VM strip edge where the field trunk and the collective DMA land. No new long wire is needed; delivery reuses the existing write network across the 10.7 mm hub.
   - This is a modest change, not a large architecture change.
7. **Scalar broadcast H-tree.** The existing 7-cycle broadcast is already at wire reach from the centre (4,890 µm Manhattan, centre to corner, 748 µm a stage). An H-tree rooted at the hub-edge buffer would reach the far corner in 10 stages. No gain. Its routing would be about 32 bits × 156 mm of track, under 2% of the lane array's M5 capacity.

## V4.1 HBM comparator (TP-96, GPU-real techniques only)

W19 baseline: AR 495.2 µs and MTP verify pass 994.4 µs. Collectives take 283.7 µs of the AR (586.4 µs of the pass). There are 265 on the path, 6 a layer, and the NVLS fixed latency is 0.78 µs of each gather.

| ID | Candidate | Class | Instances | AR µs saved | MTP µs saved | Precedent |
|---|---|---|---|---|---|---|
| H1 | gather + hc_post + hc_pre + norm sum-of-squares partial (fused AR + residual + RMSNorm) | B* | 80 | 12.4 | 23.9 | TRT-LLM, NVLS |
| H3 | router gather overlapped with the shared expert | A | 40 | 7.2 | 7.2 | CUDA streams |
| H5 | TMEM-style accumulator + register epilogue (SwiGLU·w, z_quant, q RoPE, softplus_sqrt) | A | 164 | 6.1 | 11.8 | Blackwell TMEM, CUTLASS |
| H4 | EP + smaller TP, or TP-48, at equal cost | — | 0 | 0 | 0 | — |
| H2 | merge the expert-intermediate and ffn-out gathers into one K-split all-reduce | **C** | 40 | 29.5 | 8.0 | Megatron row-parallel |

- **H1 is B\* rather than B.** 5,120 / 96 is not an integer. Rank slices must be cut on tree-aligned runs, or each rank sends several subtree partials; otherwise H1 becomes class C.
- **H4 changes nothing.** The 6 collectives a layer are re-sharding points, so a different split does not lower the count.
- **H2 is class C.** The golden accumulates the FP4 w2 blocks sequentially, and a K-split re-associates them.

Together, H1 + H3 + H5 give 25.7 µs AR (+5.5%), owned by W13b and W15b.

## Qwen3-8B

**ROM.** Product SS replay: 8,474 tok/s. Ranges run from the epilogue's pipeline depth added back to the op folded outright:

| Fold | Range |
|---|---|
| Q2: qkv epilogue (per-head q/k-norm tap, rsqrt, scale, RoPE) | +1.3% to +3.8% |
| Q5: scores exp + sum | +0.6% to +3.1% |
| Q1: gate/up rstd scale + SiLU·up | +0.1% to +2.9% |
| Q3: p.v reciprocal + normalise | about 0 |
| Q4: residual + sum of squares in the all-reduce delivery | about 0 |
| all folds together | +0.4% to +11.0% |

The Qwen die's SU ops carry no hub-network legs in this model. The per-op cost that dominates is the ME's 166 + 112 cycles, together with the 72 all-reduces at 442 cycles. W12b should measure Q2 and Q5 before anything else is adopted.

**HBM.** The token is HBM-bandwidth bound at 1.25 M cycles. Every epilogue and AR + norm fusion together removes at most 2.3% of it. These are class A/B with TRT-LLM and CUTLASS precedents.

## Related work

- **Huawei Ascend / DaVinci.** Liao et al., "Ascend: a Scalable and Unified Architecture for Ubiquitous Deep Neural Network Computing", HPCA 2021; and Liao et al., "DaVinci: A Scalable Architecture for Neural Network Computing", Hot Chips 31 (2019).
  - The Cube writes L0C. On the 910B, FixPipe applies quantise, bias, activation and element-wise work on the way to the Unified Buffer.
  - This is the model for level 2-3's staging buffer. Its fixed function covers 73% of our reach here.
- **Google TPU.** The MXU result FIFO drains into vector registers (Jouppi et al., ISCA 2017 and later generations), which is the analogue of delivery into lane registers.
- **NVIDIA Blackwell.** Tensor memory (TMEM) is an accumulator store between the tensor core and the CUDA cores, with register epilogues. It is the HBM comparator's H5.
- **Groq TSP.** MXM → VXM streams with no memory stop (Abts et al., ISCA 2020). This is the limit case of cut-through and interleaving, statically scheduled: level 4.
- **Tenstorrent.** Circular buffers between the Tensix compute and data-movement cores. They are the producer/consumer staging with credits that W11's KR chase implements.
