# Native HWIN event ledger

The actual production boot decoder already checked all eight CSR0x16 rows, but its bound MU record dropped them. The pipeline compiler could therefore check KIT/slot timing without retaining or matching the real tag/replay output calendar. This change retains those exact decoded rows, emits the source-derived event ledger per actual KS descriptor and requires its explicit physical-resource/consumer booking before reporting READY_FOR_RTL. It does not create event allocations or select a production epoch.

The smallest current-source vehicle instantiates the full47-slot/eight-row HWIN ABI at833ps/1fs. Across94 starts/two wraps it checks376 complete TX tag words and188 enabled replay words, errors0/fault00. Actual MUT3 copy-drop and MUT4 replay-enable-ignore variants each produce188 oracle mismatches. A wrong returned position raises the real RX-membership fault01. RX sampled one edge after KS through RL−1 is accepted; same-edge and RL controls fault. No source RTL or pin cycles changed.

For KS INPUT SAMPLING edge N, native output pins become visible after N+D+1 for configured delay D. This is not the older driving-NBA event convention: a driver changing f_ks after edge N is sampled at N+1, then outputs at N+D+2. The compiler guard accepts only the measured HWIN SHA and selected direct HOSTB0/STATIC_KS0 wrapper. Current source aliases those KS/outputs directly; HBE/RF variants require their own actual input/transport join.

`layer_prog/native_hwin_calendar.py` consumes actual bound MU bytes, source identity, slot calendar and real user/position descriptors. The resulting event includes exact row, kind, endpoint name, slot, copy/replay flags, payload and output edge. A `native_hwin_consumer_book` on each pipeline job must use schema `opentallas.s81.native_hwin_consumer_booking.v1`, the same clock/reset identity and resource `[stage,copy,rank]`, plus one matching row per enabled output. Each row retains every predicted source field and supplies actual `consumer_source`, positive `transport_edges` and `consumer_sampling_edge=pin_visible_after_edge+transport_edges`. Omitted books, off-by-one dates, wrong copy/identity and unbound transports remain concrete production gaps.

`check_ledger.py` exercises all94 starts and564 enabled events against that API, with wrong-date/copy/unbooked and RX controls. Its FIXTURE resource/clock and64-edge gaps/RL300 are explicit component premises. They are not production resource allocations, reset/KS bookings, window retirement or the46-user AR model's physical schedule. Hardware capacity47 must not be promoted to a47-user production target.
