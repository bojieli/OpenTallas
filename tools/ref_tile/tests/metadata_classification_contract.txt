Only hcoll_issuer_r256v8_grid and hcoll_issuer_r256v8_gridb may use this new type.

  schema: opentallas.ref_tile.metadata_classification.v1,
  parent: {
    binding: {path: committed original_binding.json, sha256: exact bytes},
    gate: {path: committed original_gate_result.json, sha256: exact bytes},
    log: {path: committed original.execution.log, sha256: exact bytes},
    spec: {path: committed original_spec.json, sha256: exact bytes}
  },
  archive: {path: committed NEW classification_inputs.tar.gz, sha256: exact bytes},
  classifier: {
    published_commit: full commit reachable from refs/remotes/origin/main,
    executed_modules: {all23 canonical imported project module paths: sha256},
    proof: {path: committed execution proof JSON, sha256: exact bytes}
  }
}

The parent quartet is part of the NEW archive's actually consumed inputs,
committed at source_binding.commit == start_commit. Its whole binding digest
and archive/manifest/start commit must agree with physical_parent. Original
physical gate must be CTS/remote-archive verified and FAIL solely for fill.
Its raw log must contain the exact original GATE_SOURCE_ARCHIVE_SHA256 marker.
The original spec bytes must match the original physical archive's spec row.
All328 original non-tools consumed inputs must remain present and identical;
the sole exception is adding exactly spec.fill_reason.pin_bound (nonempty).
The original consumed record schema/digest/count/unique sorted paths and full
path-to-SHA agreement with its old manifest are verified before coverage is used.
Clock, trial route, reset, port latency, measured band fill and every original
non-fill measured item must remain unchanged. The new verdict is WARN/PASS
with pin-bound fill WARN and no FAIL items.

The NEW tar is a committed output artifact at the admitted route source. It
is NOT input to itself. Existing SB.snapshot over its actual bytes must exactly
reproduce the new manifest/files and committed input identity. A missing tar,
wrong archive hash or changed manifest fails. No physical remote verification
is asserted by this replay. The output execution proof is likewise committed
at admitted route source, containing:
 execution_kind, classification_source_commit, classification_manifest_sha256,
 classification_archive_sha256, executed_modules, published_commit.
The23 actual module hashes must match the input archive, pinned published
main history AND admitted route source. Missing/other helper sets fail.

Original physical FAIL/history and earlier unqualified packets remain intact.
Publication/replay of issuer packets against this support must follow owner
review and normal submit_exact; this patch itself rewrites no issuer packet.

The23-module census includes forwarded_clock_outputs.py from the H9 publication
frame. Recreated issuer inputs must use that exact published frame; no old22
module downgrade or unpublished domain-API helper is supported.
