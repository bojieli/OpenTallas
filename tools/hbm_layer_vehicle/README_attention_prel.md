# Attention relative-SVG prototype (2026-10-19)

`attention_prel_svg.py` compiles independent eight-row DeepSeek QK/PV subruns through the existing relative SVG programme ABI. Each subrun is one golden csum8 subtree and one cache block: 32 lines for KV8, 17 for KV4. The packet-valid command and its cache read occupy the same programme word; the existing PREL R/C stages align the returned packet with its command. The probability-store read (`pread`, consume minus three) and observational request (`req_lead`, eight) retain their original meanings and positions.

The emitter preserves the complete SM-element calendar, including configure, consume, probability-store read, BE clear/publication and mode-only tail words. It retires the cache after the complete tail. Descriptors use loops=1 and row_off/tag_base/lstep/fl/mrel=0; cache bank and epoch still relocate. Runtime layer/expert-stride composition is not claimed by this prototype. Original compiler defaults and released RTL masters remain unchanged.

An actual full-service trial exposed a pre-existing dense-consumer assumption: the internal unused `ot_smh_static_feed` requires dense valid bit25 to coincide with packet arrival. Attention uses bit25 for a converter consume, independently of KV line arrival. The opt-in `ATTENTION` parameter on the new SRAM composition masks that bit only at the unused dense decoder, retaining its packet-valid/tag checks. The actual SM command is unchanged. The first failed trial is preserved in `results/rtl/hbm_ds_layer_tput_1018/attention_prel_1019/dense_monitor_fail.*`.

The model was committed before compiler changes (`c4b902887`), and its dense-consumer distinction before RTL (`fc07455e7`). For L02 SM0 (64 rows), the initial compiler inventory is 16 descriptors, two distinct programmes totaling 635 resident words, 512 HBM lines, 69,632 padded HBM bytes and 1,302 installation ingress edges. This fits the existing 1,019-word attention reservation. The conservative initial schedule prices 9,432 stream edges from issuer run origin through the final tail; this is correctness pathfinding and has no throughput adoption credit.

The runtime reuses the production testbench `tb_hbm_svg_rel_sm`: ingress collars, relative issuer, programme SRAMs, four-PC HBM producer/controllers and DRAM model, landing/cache SRAMs, extension calendar and actual die SM arithmetic. It checks every QK score and every PV node bit against the fixture, all fixed GO slots, and composes actual RTL PV subrun nodes in the golden tree order against the complete SM-owned subtree. That last composition is Python; on-die cross-SM SU/COLL merge remains a separate gate. `--mut wrong_row` changes the actual cache row while preserving its expected tag, so arithmetic must detect corrupted data. `--mut read_early` advances only the cache read one edge and must fail the retained packet-valid/tag check.

No new hard tile is introduced. A mixed dense/attention schedule still needs an explicit per-go attention semantic bit; the fixed opt-in instance is only the prototype. Physical closure, native landing/return latency adoption, token-wide descriptor composition, result-writer subrun mapping and production throughput qualification remain open. The prototype uses the storage-only SRAM response FIFO path; it does not claim that the native registered landing/return hierarchy is adopted.
