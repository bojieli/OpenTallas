# Native TP8 PV256 ordered product merge candidate

This default-off module has no instantiation in the accepted stack or hub. It is a
correctness component, not a native attention, physical, or throughput qualification.
Its input products are generated by the canonical scalar model, not by this RTL.

`hdc_golden.attn_splits(128,3072)` returns score128/PV256. The actual legacy stack
request function in `ot_qwen_nearhbm_attn_stack_h.sv` is
`tpos(k,r)={1'b0,k,SB,r}`, hence `t=512k+128SB+r`. Canonical residue
`c=t mod256=128(SB mod2)+r`. Stacks 0/2 therefore share one chain, and stacks 1/3
share another. Chain c must consume products at `c,c+256,c+512,...`, alternating
the two physical owners. Summing two completed PV512 accumulators changes rounding.
Native host source `tools/qwen_host/native_fixture.py` computes
`stack=(t>>7)&3`, `sec=(L<<11)|(v<<10)|(g<<9)|(((t>>6)&1)<<8)|((t>>9)<<3)|((t>>3)&7)`.
`qkd_host_ingest_map.sv` extracts `stack=addr[6:5]`, preserving that ownership;
its audited SHA256 is `36a310d43df175fab68c93e69a598055f7b130459019ebb2a89fd364cef5f6e9`
on `codex/qwen-host-integrate-1013`. The native mapper branch remains an explicit
integration dependency; this component does not qualify physical HBM operation.

The component captures a tagged vector before using the existing FP32 RNE adder,
starting each residue from canonical +0. It checks position, epoch, query head and
dimension block, and refuses a new invocation while busy. Faults are sticky until
reset; result data and ownership tags remain stable under backpressure. The
qualified consumer must reject faults and provide ascending addressed products.
The denominator is outside this component: canonical sequential chunks of eight,
then pairwise tree, independent of PV256. Neither a sequential sum of128 nor the
legacy PV512 partition denominator substitutes for that order.

The full-context gate uses position8191/context8192, four query heads, one FP8 KV
head, HD128. It checks all131072 residue leaf words from RTL against canonical
products, then reconstructs the pairwise256 tree and normalization, checking all512
attention output words. Stalls occur on input and output. Intentional position,
epoch, head and product-data faults must be observed. Product multiplication, QK,
softmax, score/exp memories, HBM integration and routed transport remain outside
this gate. No immutable price or accepted-cost ledger is changed.

For this case: 262144 vectors of16 FP32 products are consumed. Half originate in
the other physical stack of the pair: 131072 x512 bits =67108864 bits (8MiB) per
KV head. Transporting FP8 V rows before multiplication could instead move .5MiB
V plus32KiB of four BF16 exp values. That alternative requires actual row ownership,
backpressure, mapped address and compute integration; this module does not claim it.

All canonical accumulation state totals256 residues x4Q x128 FP32 dimensions =
512KiB, before tree/storage/control overhead. A production implementation must
retain the original parallel engine structure or measure any degradation. This
single16-lane reference serialized all8192 invocations and measured1471835 cycles
with stalls. It is deliberately not submitted as a priced production replacement.
Placement, per-clock-root sinks, port dimensions, actual pair reach and wire/cut
budgets are pending. Replication alone is not proof of physical or throughput fit.

## Raw V-row candidate

`ot_qwen_tp8_vrow_merge` implements the lower-traffic alternative as a new,
uninstantiated transport module. One native owner pair has eight finite request
slots. Every request records its source-owned position/epoch; the physical memory
adapter echoes the slot, position and epoch with the actual FP8 V128B row and four
BF16 exp values8B. Responses may arrive out of order, but downstream emission
follows issue order. The per-residue scoreboard refuses anything other than
ascending `c+256n`. Request and returned data are stored before presentation.
Output backpressure holds data/tags stable; duplicate, unsolicited, wrong-position
and stale-epoch returns fault. A new epoch begins only after all rows drain. A stale response coincident
with the new start faults rather than being discarded.

The positive row gate feeds actual FP8 V and BF16 e to the real
`ot_qwen_nearhbm_prod` RTL, four query heads x128 dimensions per row. Pair0 passes
4096rows/2097152 product words in8034cycles, with2760 out-of-order responses.
Pair1 passes the same count in8105cycles, with2757 out-of-order responses. Both
data mutants produce four incorrect actual RTL product words. Position ordering,
return tag and epoch mutations each fault. Stale-return-at-restart mutants fault
after the full positive run on both pairs (8035/8106cycles). These cycles measure this component's
finite synthetic memory responder, not the real HBM controller or a priced layer.
All8192 rows and4194304 products are covered; QK and exp are still scalar inputs.

Full-context partial-state map is `state[head][c][dimension]`, with c0..255.
One owner pair stores c0..127 or128..255. Within a pair, the eight canonical residue
contexts of one group (`c=128PAIR+8gam+j`, j0..7) may interleave through the original
eight-cycle arithmetic recurrence while physical t[8] alternates each256 positions.
There are sixteen groups per pair. The row harness uses this actual group/round/j
order. It does not implement or qualify the existing head engine's accumulation
state, hard SRAM banks, reduction tree, interleaving or production schedule.
